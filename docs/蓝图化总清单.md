### 需求 1:变量显示 / 精确定位变量 / 实现与应用

用户原话:"有变量显示,可精确定位变量实现与应用等"

### 需求 4:动画系统 / 分类动画

用户原话:"分类动画(分为静止,运作等),blender 一个动画会包含其他模型的
动画(或者说没有专门的动画播放器)"

**这是最关键的一条,而且是 Blender 数据模型的问题。**

| 问题 | 说明 |
|---|---|
| **Blender 没有"动画播放器"** | Blender 的动画是**动作(Action)**,挂在**物体**或**骨架**上,而且**一次只能激活一个**。没有"列出这个角色所有动画"的概念。 |
| **一个 .blend 里多个角色的动作混在一起** | `bpy.data.actions` 是**全局**的,不区分属于谁。用户的胡桃模型有 `骨骼动作`/`形态键动作`,如果再来一个角色,动作会混在一个列表里。 |
| **动作归属** | 靠 `action.id_root`(是 OBJECT 还是 ARMATURE)+ 谁在用(`action.users` / NLA)来推断,不可靠。 |

**要做的**:
* [x] **动作归属识别**:扫描场景,把每个 Action 关联到实际使用它的骨架/物体
      —— `nodes.actions_on_object()` / `action_belongs_to()` /
      `check_action_target()`(选错会给出明确告警)
* [x] **动画名下拉**:选完物体后,只列出**属于它**的动作(治用户踩过的坑:
      动画名填成默认 `idle`,而模型里叫 `骨骼动作`)
      —— 「动画_播放」用原生 `PointerProperty(type=Action)` 选动作,
      外加『选…』按归属排序(★ 排前);默认值改成空,留空 = 随便播一个
* [x] **动画分类**:让用户给动作打标签(静止/移动/攻击/受击/死亡/其他),
      存成 Action 的自定义属性(`action["gk_anim_category"]`)。
      入口:侧栏『动作分类』面板(游戏逻辑 / 游戏动画两处都能看到)
* [x] 导出时按分类生成 Godot 侧的结构
      —— 生成 `const GK_ANIM_BY_CATEGORY := {"攻击": ["砍", ...], ...}`,
      Godot 侧可 `GK_ANIM_BY_CATEGORY["攻击"].pick_random()`

**这条路走通的关键**:Godot 那边 `AnimationPlayer` 是**每个模型一个**,
里面装多个动画 —— 和 Blender 的模型不一样,要在导出时做映射。

### 需求 5:粒子/特效系统

用户原话:"粒子(特效)系统(怎么实现?使用 blender?还是 godot 的?)"

**答案:必须用 Godot 的。** 理由:

* Blender 的粒子系统**完全无法导出**到 glTF —— glTF 规范里没有粒子
* 就算能导,Godot 也不认
* Godot 的 `GPUParticles3D` / `CPUParticles3D` 是运行时系统,GPU 加速

**所以设计应该是**:
* **Blender 侧**:只做**标记**(这个物体是个粒子发射器 + 参数)
* **导出时**:生成 Godot 的 `GPUParticles3D` 节点 + 材质
* **参数**:数量/生命周期/初速/方向/重力/颜色渐变/大小曲线

- [ ] 设计 Blender 侧的粒子参数面板(照抄 GPUParticles3D 的参数)
- [ ] 导出时生成 `GPUParticles3D` 节点
- [ ] `播放特效` / `停止特效` 节点
- [ ] 贴图走现有的材质/贴图导出链路

**这是个独立的中等工程**,建议排在节点系统之后。

### 条件动画 + 时间轴 / 相机(2026-10-03 第二轮)

用户第二轮要的:"设置上一个已经播放完成、设置布尔变量,判断输入/在地面且移动/
变量真假,然后播放**一个或多个**动画";以及"**时间轴** —— 摄像机视野变化、
不同摄像机**丝滑切换**、场景动画、不同动画的**整体联动**"。

| 要的 | 节点 / 改法 |
|---|---|
| 上一个播放完成 | 新节点 **『动画_播放完成』**(两张树可用):可与『逻辑_布尔运算』拼复合条件;标志**粘住**到下一段动画开播,所以"播完了**并且**在地面"等得到 |
| 设置布尔变量 | 状态节点新增 **『进入时』『离开时』** 执行流(照 UE5 的 State Entry/Exit)→ 『动画_设变量』真的被执行;接在『转到』上会被告警纠正 |
| 播放一个或多个动画 | 状态节点新增 **『同时播 2 / 3』**:一个状态同时播多段(Godot `play()` 一次只播一段,自动开"层播放器");切走时自动停 |
| 摄像机视野变化 | **『定时_缓动属性』** 缓动相机的 `fov`(默认 0 秒 = 立刻变,老图生成结果不变) |
| 丝滑切换摄像机 | **『相机_切换』+『过渡(秒)』**:动的是**新**相机(先站到旧机位再插值回自己),两台都不用被挪走;每帧推进挂 `_physics_process` |
| 场景动画 / 整体联动 | 『定时_缓动属性』能缓动**任意节点的任意属性**(`position:y` / `modulate:a` / `light_energy`…);Godot 的 Tween 是**异步**的,几条串起来天生同时跑 —— 不必另造一个时间轴编辑器 |

这一轮同样挖出两个"语法对、跑起来才炸"的坑(已钉进 README 踩坑清单):

- **`new_section()` 不还原写入目标** → 状态钩子一生成,`_ready` 里
  "起始状态播一下"整行跑进了 `_gk_anim_enter_状态()` 的函数体,
  进游戏什么动画都不播(现在统一走 `ctx.capture()`)
- **跨函数用局部变量** → 相机过渡的"目标相机"先是 `Identifier ... not declared`,
  声明成成员变量后又被语句里的 `var` **遮蔽**,过渡静默失效

验证从 5 层加到 **6 层**:多了一步**真 Godot 跑 1.5 秒**
(`_dist/anim_probe` 最小工程),断言"t=0.5 动画在播 + t=1.5 当前相机已是特写机位"。

### 动画状态机重做 —— 图状状态机(2026-10-03)

用户反馈:"①『动画_状态机』未能正常工作 ②游戏动画里之前添加的节点使用不了"。
在**他的真实工程**上导出复现,查出四个根因,全部修掉:

| 根因(实测) | 修法 |
|---|---|
| 转场的『上游』空着,状态的『转到』直接连到了下一个状态的『进入』→ 导出后 `_physics_process` 只有一句 `pass` | **状态直连 = 播完就切**(Godot 的 auto-advance 语义) |
| 一个状态只能有一条出线(走链只取第一条,其余静默丢弃) | **图状**:任意多条转场,按画布上下位置 if/elif,一帧只走一步(UE5 语义) |
| 起始状态的动画从来没播过(只赋值,没有 `play()`) | 统一走 `_gk_anim_enter()`,起始状态也播 |
| 告警只躺在导出报告里,用户看不见 | 节点上 + 侧栏 + 导出报告三处同步 |

蓝图层面对齐虚幻 5 的部分:

- 转场三件套(上游 / 条件 / 转到)+ **从 / 到 状态下拉兜底**(连线优先)
- 条件来源:`自己写(接引脚)` / `上游动画播完` / `选输入:按住|刚按下|松开`
- **取值类节点整类开放给动画树**:常量(数值/文本/布尔/向量)、数学、
  向量、比较、布尔运算、类型转换、输入(按住/按下/轴/方向)、手柄读取、
  动画_是否在播、动画_时长、取值_是否在地面
  —— 转场条件可以像蓝图一样就地拼,不用回玩法图
- 诊断:缺线 / 条件为空 / 状态重名 / 状态无名字 / 状态孤立 / 重复转移,
  逐条成人话,并**原样**进导出告警

顺手修掉两个"看不见的"老问题:

- **`id()` 不能当节点身份**:真 Blender 里 `tree.nodes[i]` 和 `link.to_node`
  给的是同一个节点的两个包装对象(`is` 都不成立)→ 入口状态被算成终点,
  一进游戏就播错动画。改用 `as_pointer()`(`nodes.node_key`)。
  **离线桩测不出来**,所以新增真 Blender 测试 `tests/blender_anim_tree.py`
- **菜单过滤与"能不能加进这棵树"合并成一份判断**
  (`properties.node_fits_tree`):`gk_tree_type` 是元组时,老代码五处
  `!= kind` 全为真 —— 这就是用户在动画树里加『常量_数值』报
  `RuntimeError` 的原因

验证:`scripts/verify_anim_system.ps1`(离线 258 项 → 真 Blender 24 项 →
示例工程 13 项自查 → 两个生成脚本都过真 Godot 解析 → 反例必须被拒绝)。
连线图与排错表写进了 [节点怎么连](节点怎么连.md) 第五节,
可直接照抄的样板在 `examples/demo_anim_tree/`。

**第二轮(用户回:"那个切换条件现在没有自定义,然后后面的形态键动画无法播放")**
—— 把生成结果丢进**真实 Godot 工程跑起来**之后,又挖出五个只有真跑才看得见的 bug:

| # | 现象(实测) | 根因 | 修法 |
|---|---|---|---|
