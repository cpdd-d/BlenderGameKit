### 需求 4:动画系统 / 分类动画

用户原话:"分类动画(分为静止,运作等),blender 一个动画会包含其他模型的
动画(或者说没有专门的动画播放器)"

**这是最关键的一条,而且是 Blender 数据模型的问题。**

| 问题 | 说明 |
|---|---|
| **Blender 没有"动画播放器"** | Blender 的动画是**动作(Action)**,挂在**物体**或**骨架**上,而且**一次只能激活一个**。没有"列出这个角色所有动画"的概念。 |
| **一个 .blend 里多个角色的动作混在一起** | `bpy.data.actions` 是**全局**的,不区分属于谁。用户的胡桃模型有 `骨骼动作`/`形态键动作`,如果再来一个角色,动作会混在一个列表里。 |
| **动作归属** | 靠 `action.id_root`(是 OBJECT 还是 ARMATURE)+ 谁在用(`action.users` / NLA)来推断,不可靠。 |

**要做的**:
* [x] **动作归属识别**:扫描场景,把每个 Action 关联到实际使用它的骨架/物体
      —— `nodes.actions_on_object()` / `action_belongs_to()` /
      `check_action_target()`(选错会给出明确告警)
* [x] **动画名下拉**:选完物体后,只列出**属于它**的动作(治用户踩过的坑:
      动画名填成默认 `idle`,而模型里叫 `骨骼动作`)
      —— 「动画_播放」用原生 `PointerProperty(type=Action)` 选动作,
      外加『选…』按归属排序(★ 排前);默认值改成空,留空 = 随便播一个
* [x] **动画分类**:让用户给动作打标签(静止/移动/攻击/受击/死亡/其他),
      存成 Action 的自定义属性(`action["gk_anim_category"]`)。
      入口:侧栏『动作分类』面板(游戏逻辑 / 游戏动画两处都能看到)
* [x] 导出时按分类生成 Godot 侧的结构
      —— 生成 `const GK_ANIM_BY_CATEGORY := {"攻击": ["砍", ...], ...}`,
      Godot 侧可 `GK_ANIM_BY_CATEGORY["攻击"].pick_random()`

**这条路走通的关键**:Godot 那边 `AnimationPlayer` 是**每个模型一个**,
里面装多个动画 —— 和 Blender 的模型不一样,要在导出时做映射。

### 需求 5:粒子/特效系统

用户原话:"粒子(特效)系统(怎么实现?使用 blender?还是 godot 的?)"

**答案:必须用 Godot 的。** 理由:

* Blender 的粒子系统**完全无法导出**到 glTF —— glTF 规范里没有粒子
* 就算能导,Godot 也不认
* Godot 的 `GPUParticles3D` / `CPUParticles3D` 是运行时系统,GPU 加速

**所以设计应该是**:
* **Blender 侧**:只做**标记**(这个物体是个粒子发射器 + 参数)
* **导出时**:生成 Godot 的 `GPUParticles3D` 节点 + 材质
* **参数**:数量/生命周期/初速/方向/重力/颜色渐变/大小曲线

- [x] 设计 Blender 侧的粒子参数面板(照抄 GPUParticles3D 的参数)
      —— 2026-10-05 第二十一轮:『游戏物理』面板新增『粒子特效』框(数量 /
      生命周期 / 一次性 / 爆发度 / 初速 / 方向 / 扩散角 / 重力 / 发射半径 /
      起终颜色 / 起终大小 / 预发射 / 随机度 / 局部坐标 / 叠加发光),
      方向按物体自己的旋转算;物体是网格还是**空物体**都行
- [x] 导出时生成 `GPUParticles3D` 节点
      —— 面板上可切 **GPU / CPU**(GPUParticles3D / CPUParticles3D,
      2D 项目对应 …2D 两版);材质 / 渐变 / 大小曲线全在,
      有物理体的发射器挂在 `Colliders/<名字>` 下(跟着物体动)
- [x] `播放特效` / `停止特效` 节点
      —— 『特效_播放』『特效_停止』,外加 **『特效_爆发』**(重新喷一轮,
      一次性发射器=再放一轮)。生成的引用带**具体粒子类型**,
      忘了勾『作为粒子发射器』时明确告警 + 跳过
- [x] 贴图走现有的材质/贴图导出链路
      —— 物体材质的基础色贴图直接用(同一个 `export_textures` 链路、
      同一套文件名算法);没有就导出时现写一张内置圆形柔光
      (`art/fx_soft.png`,纯 Python 生成)

**这是个独立的中等工程**,建议排在节点系统之后。→ ✅ 已完成(第二十一轮)。

### 动画状态机重做 —— 图状状态机(2026-10-03)

用户反馈:"①『动画_状态机』未能正常工作 ②游戏动画里之前添加的节点使用不了"。
