## 一、用户 6 条需求逐条拆解

### 需求 1:变量显示 / 精确定位变量 / 实现与应用

用户原话:"有变量显示,可精确定位变量实现与应用等"

| 项 | 现状 | 要做的 |
|---|---|---|
| 变量列表 | 有 `变量_设置` / `变量_取` 之类的节点,但**没有集中管理** | **变量面板**:一处定义(名字+类型+初值),节点里下拉选 |
| 精确定位变量 | 无 | 点击变量 -> 高亮所有用到它的节点(UE5 的 Find References) |
| 变量的"实现" | 无 | 变量可以绑定一个**函数**(UE5 的 getter/setter 自定义) |

**UE5 对应物**:My Blueprint 面板的 Variables 区。

**建议做法**:
* 在**节点树**上挂一个 `CollectionProperty` 存变量定义
* 再加一个 `变量_取` / `变量_设置` 节点,名字走 `EnumProperty`(由变量表动态生成)
* 点击变量时遍历所有节点找引用

### 需求 2:查看函数 / 自定义函数 / 折叠函数

用户原话:"可查看函数,自定义函数,折叠函数等"

| 项 | 现状 | 要做的 |
|---|---|---|
| 查看函数 | 无 | 函数列表面板 |
| 自定义函数 | **无**(节点图只能生成 `_ready` / `_physics_process` 等固定函数) | **函数节点**:一个子树编译成一个 GDScript `func` |
| 折叠函数 | 无 | 选中一批节点 -> 折叠成一个"折叠节点" |
| 调用函数 | 无 | `调用函数` 节点 |

**UE5 对应物**:My Blueprint 的 Functions 区 + Collapse to Function。

**这是目前最大的结构性缺口** —— 现在整张图只能生成一个 `_ready`。
想复用逻辑只能复制节点。

**建议做法**:
* 新增一种节点树类型(或节点上的一个"函数入口"标记)
* 每个函数入口 -> 生成 `func 名字(参数) -> 返回类型:`
* `调用函数` 节点 -> 生成 `名字(参数)`

### 需求 3:属性显示 / 砖块结构

用户原话:"基本属性显示,按照虚幻5的布局或者设计砖块结构

| 节点搜索 | ✅ 有 | 保持 |

**这条基本已经符合**,主要是**打磨**。

### 需求 4:动画系统 / 分类动画

用户原话:"分类动画(分为静止,运作等),blender 一个动画会包含其他模型的
动画(或者说没有专门的动画播放器)"

**这是最关键的一条,而且是 Blender 数据模型的问题。**

| 问题 | 说明 |
|---|---|
| **Blender 没有"动画播放器"** | Blender 的动画是**动作(Action)**,挂在**物体**或**骨架**上,而且**一次只能激活一个**。没有"列出这个角色所有动画"的概念。 |
| **一个 .blend 里多个角色的动作混在一起** | `bpy.data.actions` 是**全局**的,不区分属于谁。用户的胡桃模型有 `骨骼动作`/`形态键动作`,如果再来一个角色,动作会混在一个列表里。 |
| **动作归属** | 靠 `action.id_root`(是 OBJECT 还是 ARMATURE)+ 谁在用(`action.users` / NLA)来推断,不可靠。 |

**要做的**:
* [ ] **动作归属识别**:扫描场景,把每个 Action 关联到实际使用它的骨架/物体
* [ ] **动画名下拉**:选完物体后,只列出**属于它**的动作(治用户踩过的坑:
      动画名填成默认 `idle`,而模型里叫 `骨骼动作`)
* [ ] **动画分类**:让用户给动作打标签(静止/移动/攻击/受击…),
      存成 Action 的自定义属性
* [ ] 导出时按分类生成 Godot 侧的结构

**这条路走通的关键**:Godot 那边 `AnimationPlayer` 是**每个模型一个**,
里面装多个动画 —— 和 Blender 的模型不一样,要在导出时做映射。

### 需求 5:粒子/特效系统

用户原话:"粒子(特效)系统(怎么实现?使用 blender?还是 godot 的?)"

**答案:必须用 Godot 的。** 理由:

* Blender 的粒子系统**完全无法导出**到 glTF —— glTF 规范里没有粒子
* 就算能导,Godot 也不认
* Godot 的 `GPUParticles3D` / `CPUParticles3D` 是运行时系统,GPU 加速

**所以设计应该是**:
* **Blender 侧**:只做**标记**(这个物体是个粒子发射器 + 参数)
* **导出时**:生成 Godot 的 `GPUParticles3D` 节点 + 材质
* **参数**:数量/生命周期/初速/方向/重力/颜色渐变/大小曲线

- [ ] 设计 Blender 侧的粒子参数面板(照抄 GPUParticles3D 的参数)
- [ ] 导出时生成 `GPUParticles3D` 节点
- [ ] `播放特效` / `停止特效` 节点
- [ ] 贴图走现有的材质/贴图导出链路

**这是个独立的中等工程**,建议排在节点系统之后。

### 需求 6:场景资产的使用与启用

用户原话:"场景资产的使用与启用(不可能最后场景一大堆模型在那,
有时要定位到一个模型,拉过去的话,视图上会有拉不动,显示到头了等)"

| 问题 | 说明 |
|---|---|
| 场景里模型太多 | 需要"预制体/资产"概念 |
| 定位不到模型 | 需要一个**资产列表**能点选定位 |
| "拉过去视图上拉不动" | 可能是 Blender 视图裁剪(clip end)或被其它物体遮挡 |

**要做的**:
- [ ] **场景资产面板**:列出当前项目用到的模型,点击 -> 视图定位到它
- [ ] **实例化引用**:一个模型只导一次,场景里多处引用(现在是每个物体都导)
- [ ] `创建实例` / `销毁实例` / `启用` / `禁用` 节点
- [ ] 视图裁剪问题单独查(clip_start/clip_end)

## 二、建议的落地顺序

按"用户疼不疼 + 依赖关系"排:

| 顺序 | 任务 | 为什么这个位置 |
|---|---|---|
| 1 | **动画名下拉 + 动作归属识别** | 用户实际踩过坑;做完动画系统才好继续 |
| 2 | **动画事件输出**(Started/Running/On Finish) | UPBGE 最值钱的地方;接上就能做连招/循环逻辑 |
| 3 | **变量面板 + 定位引用** | 蓝图化的地基,后面函数系统也依赖它 |
| 4 | **自定义函数 / 折叠** | 结构性最大缺口,但依赖 3 |
| 5 | **动画状态机** | 依赖 1+2 |
| 6 | **场景资产面板 + 实例化** | 独立,可并行 |
| 7 | **粒子系统** | 独立的中等工程 |
