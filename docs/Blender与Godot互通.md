# Blender 与 Godot 怎么互通

这一页回答四个具体问题:

1. **一个 `.blend` 怎么对应出一个 Godot 项目**?(文件都放哪)
2. Blender 里建好场景后,**贴图和模型怎么进 Godot**?
3. **模型的脚本怎么搭载**?
4. 怎么在 Godot 里**用 C++ 写脚本**?

---

## 一、一个 `.blend` 对应一个 Godot 项目

### 核心规则

**导出路径跟着 `.blend` 文件走,不是插件的全局设置。**

```
D:\我的游戏\角色.blend
    ↓ 自动推导
D:\我的游戏\角色_godot\        ← Godot 项目根目录
```

这么做解决的是三个实际问题:

| 问题 | 以前的麻烦 | 现在 |
|---|---|---|
| 每开一个新工程都要填路径 | 插件设置里填一次,换文件就失效 | 打开哪个 `.blend` 就知道该写哪 |
| 一个仓库里放多个 `.blend` | 全都导到同一个目录,互相覆盖 | 各导各的,互不干扰 |
| 交付时要说明"文件在哪" | Blender 工程和 Godot 工程分开给 | 一个文件夹拷走就完整 |

### 怎么用

1. **先保存 `.blend`**(Ctrl+S)—— 没有路径就推不出项目位置,插件会明确提示
2. 切到**游戏逻辑节点编辑器**,顶部会出现 **创建 Godot 项目**
3. 点它 → 弹出确认框(可以改位置)→ 建好后问你要不要**用 Godot 打开**
4. 之后所有导出(脚本 / 模型 / 材质)都自动落进这个项目

> **没保存 `.blend` 时不会静默写到家目录。** 早期版本会兜底写到
> `~/BlenderGameKit_Export`,结果是用户根本不知道文件去哪了。
> 现在推不出目录就报错,让你先保存 —— 明确失败比静默乱放好。

### ⚠️ "打开 Godot"按钮不出现?

**这是有意的 —— 项目还没建出来时没东西可打开。** 面板会显示:

```
Godot 项目
  对应文件: 3dtest.blend
  <项目路径>
  状态: 尚未创建

  ┌ 项目还没建出来          ← 这里会告诉你下一步
  │ 建好之后这里才会出现『打开 Godot』
  └ [ 创建 Godot 项目 ]
```

先点**创建 Godot 项目**,建好之后同一个位置就变成 **[打开 Godot 测试]**。

（早期版本在这种情况下只放一个没有任何说明的 `+` 按钮,确实让人找不到东西。
现在把"下一步是什么"直接写在面板上。）

### 两种情况:项目建在哪

| 你的情况 | 插件怎么做 | 面板显示 |
|---|---|---|
| `.blend` 放在普通文件夹里 | 在它旁边建 `<文件名>_godot/` | 规则: **跟着 .blend** |
| **`.blend` 已经放在某个 Godot 项目里** | **直接用那个项目**,不再套一层 | 规则: **Blender 文件在项目里** |
| 手动指定过位置 | 用你指定的 | 规则: **手动指定** |

第二种是实测补上的:很多人会把 `.blend` 直接放进 Godot 项目目录
(甚至就放在项目根)。这时如果还建一个 `xxx_godot` 子目录,就变成了
**项目套项目** —— 又别扭又容易搞混。所以插件会**往上找**,遇到第一个
含 `project.godot` 的目录就认它(最多找 4 层,所以放在子目录里也能找到)。

> 如果你把 `.blend` 放在别人的 Godot 项目里,而那个项目没有
> `art/scripts/scenes/materials/shaders` 这几个目录,插件会**自动补齐**。
> 这个操作是纯增量的 —— 只建缺的目录、只写不存在的文件,不会覆盖任何东西。

### 项目结构

```
角色_godot/
├── project.godot        主场景已自动设好,按 F5 就能跑
├── README.md            说明哪些文件是生成的、哪些可以自己改
├── scripts/             GDScript 逻辑     ← 节点图生成(不要手改)
├── scenes/              .tscn 场景装配     ← 模型 + 脚本 + 碰撞体
├── art/                 .glb 模型 + .png 贴图
├── materials/           卡通材质 .tres
└── shaders/             NPR 着色器(随插件复制)
```

**为什么不用 `.blend` 所在目录当项目根?**
那样 `.godot/` 导入缓存会和 `.blend1` 备份文件混在一起,
Godot 还会去扫描 `.blend1` 这类垃圾文件。固定用同名子目录最干净。

### 想放到别处

侧栏『项目』→ **改位置**。这个选择会**写进 `.blend`**(场景属性 `project_dir`),
下次打开还记得。留空就恢复成"跟着 `.blend` 走"。

### 文件归属:谁能改,谁会被覆盖

| 目录 | 谁生成 | 手改会怎样 |
|---|---|---|
| `scripts/` | Blender 节点图 | **下次导出被覆盖** |
| `scenes/` | Blender 资产导出 | **下次导出被覆盖** |
| `materials/` | Blender NPR 面板 | **同名文件被覆盖** |
| `art/` | Blender 导出 | 导出同名模型时被覆盖 |
| `shaders/` | 插件自带 | 会被插件的版本覆盖 |
| `project.godot` | 首次创建 | **不会覆盖**你的手改 |
| `README.md` | 首次创建 | 同上 |

要加自己的东西,在 Godot 里新建别的目录(比如 `levels/`、`ui/`),
不要和上面这些混在一起。

### 启动 Godot

| 按钮 | 做什么 | 传给 Godot 的参数 |
|---|---|---|
| **打开 Godot** | 启动编辑器打开项目 | `--path <项目> --editor` |
| **运行** | 不打开编辑器,直接跑 | `--path <项目>` |

> **`--editor` 不能省,`--game` 不能用。** 这是踩过的坑,记清楚:
>
> | 参数 | 结果 |
> |---|---|
> | `--path <目录> --editor` | ✅ 打开编辑器 |
> | `--path <目录>` | 运行游戏(**不是**打开编辑器) |
> | `--path <目录> --game` | ❌ `Couldn't detect whether to run the editor, the project manager or a specific project. Aborting.` |
>
> 我一开始以为"裸 `--path` 就是打开编辑器",还自作聪明给运行分支加了
> `--game` —— 结果点按钮弹出一个报错框。`--game` **根本不是有效参数**,
> 加上它 Godot 就无法判断该干什么了。
>
> 现在这个行为被 `tests/blender_project.py` 锁住了(它把 `subprocess.Popen`
> 换成假的,断言实际会传哪些参数)。**之前没有任何测试检查过命令行,
> 所以写错了也一直没人发现。**

**点"运行"但项目还没有主场景时**,不会启动一个立刻崩掉的 Godot,而是
明确告诉你:

```
项目还没有主场景,直接运行会失败。
请先在 Blender 里『导出为 Godot 脚本』并勾选『同时生成示例场景』,然后重试
```

（否则用户看到的是 Godot 一闪而过,完全不知道发生了什么。）

Godot 可执行文件会自动到常见位置找(支持带版本号的文件名,如
`Godot_v4.7.2-stable_win64.exe`),优先选非 console 版。找不到就在
**插件偏好设置**里手动填。

## 二、贴图和模型怎么互通

### 唯一正确的通道:glTF

Blender → Godot 不要用 FBX,用 **glTF 2.0**(`.glb`)。原因:

| | glTF | FBX |
|---|---|---|
| Godot 官方支持 | 原生、直接导入 | 通过 FBX 插件,推荐先转 glTF |
| 材质 | PBR 标准,直接映射 | 需要转换 |
| 贴图 | 可内嵌进单个文件 | 外部依赖多 |
| 骨骼/动画 | 完整 | 完整但坐标轴易出问题 |
| 粒子 | **规范里没有** —— 一个字节都传不过去 | 同样没有 |

> **所以粒子只能是"Blender 标记 + Godot 生成"**(2026-10-05 第二十一轮):
> 在物体上勾『游戏物理』→『粒子特效』→『作为粒子发射器』并填参数,
> 导出时插件在 Godot 里生成 `GPUParticles3D` / `CPUParticles3D`(2D 是
> `…Particles2D`)+ 材质 / 贴图 / 渐变 / 大小曲线,运行时用
> 『特效_播放』『特效_停止』『特效_爆发』控制。**不要**去配 Blender 自己的
> 粒子系统 —— 那一套导出后不会出现在 Godot 里(详见 `examples/demo_curve`)。

### 贴图的两种带法

在 Blender 导出时选 `GLB`(二进制),**贴图会内嵌进 .glb**。
Godot 导入后会自动把 `Base Color` 贴图变成材质的 albedo 贴图。

也可以用 `GLTF + Separate`,贴图导出成外部文件。两种 Godot 都能读。

**关键点:贴图不用手动复制。** glTF 导出器会把 Blender 材质节点里的
`Image Texture` 一起打包。你只要保证贴图在 Blender 里**已经指向真实文件**
(不是"未保存的图像")。

### 本插件做的自动化

点侧栏的 **导出模型到 Godot**,它会:

```
选中/全部网格
   │
   ├── bpy.ops.export_scene.gltf  ──>  <名字>.glb        模型 + 贴图
   ├── 读材质节点的主色和贴图      ──>  materials/*.tres   卡通材质
   ├── 复制 NPR 着色器            ──>  shaders/*.gdshader
   └── 算包围盒 + 读上次导出的脚本  ──>  <名字>.tscn       把上面拼起来
                                        project.godot     可直接打开
```

产出目录直接用 Godot 打开就是一个能跑的角色工程。

### 一个必须知道的坑:导出目录里才能被 Godot 引用

Godot 工程**不能引用工程目录之外的文件**。所以:

- 着色器必须在导出目录里(插件会自动复制进去)
- 导出目录要包含 `project.godot`(插件会自动生成)

## 三、模型的脚本怎么搭载

### 先纠正一个概念

**模型不能"自带脚本"。** Godot 里脚本只能挂在**节点**上,而 `.glb` 导入后
只是一个网格节点(MeshInstance3D),它不是角色,也没有速度、碰撞、状态。

所以要把三件事分开看:

| 层面 | 在 Blender 里 | 在 Godot 里 |
|---|---|---|
| **几何** | 网格、骨骼、动画 | `.glb` → MeshInstance3D |
| **外观** | 材质 | `.tres` + `.gdshader` |
| **行为** | 节点图 | `.gd` 脚本 |
| **装配** | —— | `.tscn` 把上面三者拼成一棵树 |

`.tscn` 就是"搭载"发生的地方。插件生成的装配场景长这样:

```
TestHero (CharacterBody3D)        ← 根节点:挂脚本、带碰撞体
├── script = game_logic.gd        ← 行为
├── Collision (CollisionShape3D)  ← 用模型包围盒自动算出的胶囊体
└── Model (instance of .glb)      ← 几何,作为子节点
```

### 为什么模型要放成子节点

因为角色控制器需要"根节点在脚底、朝向一致"。模型作为子节点可以被单独
旋转/缩放/换装,不影响控制器的物理逻辑。这也是 Godot 官方示例的做法。

### 完整流程

```
1. 节点编辑器里画好逻辑 → 点「导出为 Godot 脚本」   → game_logic.gd
2. 在 Blender 里选中角色网格 → 点「导出模型到 Godot」
       └─ 自动生成 .glb + 材质 + 引用上面脚本的 .tscn
3. Godot 打开导出目录 → 打开 .tscn → F5
```

### 节点图里的"目标节点"和场景树的关系

节点图里节点的"目标"属性有两个特殊值:

- `自身(脚本所在节点)` → 生成 `self`
  → 指脚本挂的那个节点,也就是 `.tscn` 的**根节点**(角色控制器)
- 其它名字 → 生成 `$名字` 或 `@onready var xxx`
  → 指**子节点**,比如 `$Model`、`$AnimationPlayer`

所以:角色自身的行为(移动、跳跃)用"自身";
对模型、动画、碰撞体的操作要填子节点的名字。

## 四、在 Godot 里用 C++ 写脚本

Godot 的 C++ 不是"脚本",而是 **GDExtension**:编译成动态库(`.dll`),
引擎运行时加载。性能接近引擎内核,适合热点逻辑(大量单位、程序化生成、寻路)。

### 和 GDScript 的分工建议

| 用 C++ | 用 GDScript |
|---|---|
| 每帧跑几千个实体的逻辑 | 角色控制、UI、关卡流程 |
| 程序化地形/网格生成 | 快速迭代的游戏规则 |
| 自定义物理/寻路 | 绝大多数游戏逻辑 |
| 需要 SIMD 的数学 | —— |

**不要一上来就全用 C++。** GDScript 写起来快几十倍,优化要基于实测。

### 最小可运行例子

工程里 `examples/gdextension_cpp/` 有一份完整骨架:

```
examples/gdextension_cpp/
├── gk_demo.gdextension     Godot 加载动态库的声明
├── SConstruct              scons 构建脚本
├── CMakeLists.txt          cmake 构建脚本(二选一)
├── build.ps1               一键构建
└── src/
    ├── register_types.cpp  注册入口
    ├── register_types.h
    └── gk_character.cpp    示例类:把节点图生成的参数暴露给 C++
```

### `.gdextension` 文件是关键

```ini
[configuration]
entry_symbol = "gk_library_init"
compatibility_minimum = "4.4"

[libraries]
windows.debug.x86_64 = "res://bin/gk_demo.windows.debug.x86_64.dll"
windows.release.x86_64 = "res://bin/gk_demo.windows.release.x86_64.dll"
```

Godot 会去找 `res://bin/` 下对应平台的库。**改了 C++ 要重新编译并重启编辑器**。

### 构建前置条件

```powershell
# 1. Python + SCons
pip install scons

# 2. godot-cpp(和你的 Godot 版本对应)
git clone -b 4.4 https://github.com/godotengine/godot-cpp

# 3. 编译
cd examples\gdextension_cpp
scons platform=windows target=template_debug -j8
```

> 你没有装 git 的话,也可以直接下 godot-cpp 的 zip 解压到同级目录。
> 你机器上有 `D:\cmake` 和 `D:\vs2026`,所以 CMake 路线也走得通。

**注意**:godot-cpp 的版本必须和 Godot 版本大致匹配
(比如 Godot 4.4 配 godot-cpp 4.4 分支)。版本差太多会在链接时报符号错误。

### 和节点图配合的方式

C++ 类的属性可以被 GDScript / 场景文件设置,所以可以:

1. 用 C++ 写一个 `GKCharacter` 类(继承 `CharacterBody3D`),负责高性能的移动与碰撞
2. 节点图导出的 GDScript 负责输入、状态、动画
3. GDScript 里 `$Character.move_with_input(dir)` 调用 C++ 方法

这就是"脚本写逻辑、C++ 写热点"的分工。

## 五、节点怎么用(和 UPBGE 逻辑砖不一样)

### 它长得像 Blender 节点是故意的

你说得对,**这些卡片确实像 UPBGE 的逻辑砖** —— 但那是外观,不是机制:

| | UPBGE 逻辑砖 | BlenderGameKit |
|---|---|---|
| 本质 | **运行时解释器**,砖块在游戏里执行 | **代码生成器**,节点图编译成 GDScript |
| 产物 | 一堆砖块配置(config) | 一个你能读、能改的 `.gd` 文件 |
| 调试 | 只能在 Blender 里跑 | **Godot 原生调试器**,断点、堆栈都有 |
| 性能 | 每帧解释 | 和手写 GDScript 一样 |
| 能不能脱离 Blender | 不能 | **能**。导出后 Godot 独立运行 |

外观像 Blender 节点是因为它就长在 Blender 的节点编辑器里 —— 用你熟悉的操作方式。

### 核心规则:两条线

```
        金色线 = 执行顺序      ← "先做这个,再做那个"
  事件 ──执行──> 语句 ──执行──> 语句

        灰色线 = 数据          ← "把这个值传给它"
  常量 ──值──> 打印器.内容
```

**金色线是骨架。** 没有金色线,节点就是孤立的,什么都不会发生。

### 每个脚本必须有一个"事件"节点当入口

事件 = "什么时候做"。这是唯一的起点,对应 Godot 的回调函数:

| 事件节点 | 对应 Godot | 什么时候跑 |
|---|---|---|
| **每当_准备** | `_ready()` | 游戏开始时,一次 |
| **每当_每帧** | `_process(delta)` | 每一帧 |
| **每当_物理帧** | `_physics_process(delta)` | 固定频率(默认每秒 60 次) |
| **每当_输入** | `_input(event)` | 按键 / 鼠标事件 |

### 最小可运行例子

```
[每当_准备] ──执行──> [打印_输出]
                        内容: "你好，世界"
```

生成的 GDScript:

```gdscript
extends CharacterBody3D

func _ready() -> void:
	print("你好，世界")
```

**不知道从哪开始时,点侧栏的『生成示例节点图』** —— 它会直接搭出上面这条链路,
你照着改就行。(节点树为空时侧栏顶部也会给这个按钮。)

### 一个像样的例子:2D 角色移动

```
[每当_物理帧]──执行──>[移动_方向]──完成──>[移动_翻转]──完成──>[分支]
   帧间隔             方向 ← [获取_向量]                        条件 ← [与]
                      速度 ← [常量_浮点 220]                    ├ A ← [在_地面?]
                                                                └ B ← [按键_刚按下 "jump"]
                                                                        │
                                                        是 ─────────────┘
                                                         │
                                                        [移动_跳跃]──完成──>[状态_设置 "jump"]
```

这就是 `tests/test_codegen.py` 里真实用例的结构 —— 和 `examples/demo_2d`
用的是同一套节点。想直接看效果就跑 `scripts\godot_verify.ps1`。

### 常见错误

| 现象 | 原因 |
|---|---|
| 导出后脚本什么都不做 | **没有事件节点**。侧栏会警告「还没有事件节点,脚本不会执行任何…」 |
| 节点之间有灰线但没反应 | **缺金色『执行』线**。数据线只传值,不控制顺序 |
| 一个输入引脚接了两条线 | Blender 只允许一条。第二条会被静默拒绝,导出时会警告 |
| 中文节点名生成的函数名很怪 | 函数名会被压成拼音/下划线。要可控就给『自定义函数』填英文名 |

### 和 UPBGE 最本质的区别

UPBGE 的逻辑砖**必须在 Blender 里运行**。这个插件生成的是**标准 GDScript**:

```gdscript
# 你可以直接改它 —— 改完还能用,不会因为"和节点图不一致"而失效
func _physics_process(delta: float) -> void:
	velocity.x = move_toward(velocity.x, direction * SPEED, ACCEL * delta)
	move_and_slide()
```

代价是:**改了代码之后,再导出会覆盖掉你的修改**。所以两条路选一条:
- 逻辑写在节点图里,导出 → 不要手改 `scripts/` 下的文件
- 或者导出一次当脚手架,之后完全手写 → 那就别再点导出了

### 物理与碰撞:在物体属性里设

参考 UPBGE 的做法 —— **碰撞形状属于物体本身**,所以设置在
**物体属性编辑器**(右侧属性栏)里,选中谁就改谁:

```
物体属性 → 游戏物理 (BlenderGameKit)
├── 导出这个物体          ✓
├── 物理类型              [3D 静态碰撞体 StaticBody3D ▾]
├── 碰撞
│   ├── 碰撞形状          [自动 ▾]      ← 按尺寸自动挑球/胶囊/盒
│   │   └── 按尺寸会选: 胶囊            ← 直接告诉你结果
│   ├── 碰撞层 / 检测层
│   └── 作为触发区        ☐
├── 刚体(只有刚体类型才显示)
│   ├── 质量
│   └── 重力倍率
└── 逻辑
    └── 挂游戏逻辑脚本    ☐
```

**为什么不在侧栏的导出面板里?** 那样得"先选中物体,再跳到另一个面板填参数",
两处来回跑,而且没法一眼看出场景里哪些东西有碰撞。UPBGE 放在物体属性里
是对的,这里照做。

#### 自动形状怎么挑

| 物体形状 | 自动选的碰撞形状 |
|---|---|
| 三边接近相等,网格**真圆**(圆度 ≥ 0.85,如球) | **球** SphereShape3D |
| 三边接近相等,网格**不圆**(方块 / 立方体) | **盒子** BoxShape3D —— 球是内切的,八个角漏在外面、斜对角会穿模(第十九轮改的:方块以前也被判成球) |
| 某一轴明显最长(人形、柱子) | **胶囊** CapsuleShape3D |
| 扁平的(墙、地板) | **盒子** BoxShape3D |

> 手动还能选 **『凸包 Convex』**(按网格真实外形,适合石头 / 雕像 ——
> 盒子会"切角"、球会"漏边"的不规则模型)和 **『作为父级的碰撞块』**
> (几个子物体拼成一个碰撞体:人形头/身/腿;子物体本身**不出现在游戏画面里**)。
> 碰撞层 / 掩码写在 **body** 节点上(写 shape 上会被 Godot 忽略)。

面板上会**直接显示**"按尺寸会选: 胶囊" —— 用的是和导出时**同一份逻辑**,
所以看到什么就是生成什么,不会两边不一致。

#### 勾了"挂游戏逻辑脚本"会怎样

导出时那个物体会变成 `CharacterBody3D`(或你选的类型),并且把
`scripts/game_logic.gd` 挂到它上面。这样节点图里的「移动_设置速度」
之类的节点就有作用对象了。

#### 生成出来的结构

```
World (instance of art/World.glb)     ← 整个 Blender 场景
├── CharacterRoot / Body / Box / ...   ← glb 里带过来的(位置和 Blender 一致)
├── Colliders                          ← 自动生成的碰撞体都放这里
│   ├── Body  [StaticBody3D]  位置 = Body 的世界坐标
│   │   └── Collision [CollisionShape3D]
│   └── Box   [StaticBody3D]
│       └── Collision [CollisionShape3D]
```

> 碰撞体**必须写 `transform`**。不写的话它们会全部堆在原点 ——
> 看起来"有碰撞体",但完全对不上模型。这个坑实测踩过:
> Godot 里读回来全是 `pos=(0.00, 0.00, 0.00)`。
>
> 放在 `Colliders` 容器下也有原因:直接挂场景根会和 glb 实例里的同名节点
> 撞名(Godot 里会出现两个同级 `Body`),而且分不清哪些是自动生成的。

### 关掉再打开,状态还在吗

**在的。** 上次导出信息写在 `.blend` 的场景自定义属性里
(`gk_last_export`),打开文件时由 `load_post` 处理器恢复:

| 东西 | 存在哪 | 重开后 |
|---|---|---|
| 项目绑定(`project_dir`) | 场景属性 | ✅ |
| 上次导出(脚本名 / 目录 / 行数) | 场景属性 `gk_last_export` | ✅ |
| 物体碰撞设置 | **物体属性** | ✅ |
| 节点图 | 节点树数据类型 | ✅ |
| 最近使用的节点 | 内存(会话内) | ❌ 有意如此 |

> `@bpy.app.handlers.persistent` 这个装饰器不能省 —— 不带它的话,
> 加载新文件时 Blender 会把这个 handler 一起清掉,只能生效一次。

## 六、速查表:什么放在哪里

| 你想做的事 | 放哪 | 怎么做 |
|---|---|---|
| 摆场景、建模型、做动作 | **Blender** | 就当平时那样做 |
| 模型、贴图、骨骼、动画 | Blender | 用「导出模型到 Godot」导出 .glb |
| 卡通渲染参数 | **Blender**(EEVEE 预览) | 见 [渲染文档](渲染-NPR卡通着色.md) |
| 角色逻辑(移动/跳跃/状态) | **Blender 节点图** | 导出 .gd,自动挂到 .tscn 根节点 |
| 输入映射、分辨率等工程设置 | Godot | `project.godot`(主场景已自动设好) |
| 关卡布局、UI | Godot | 在 Godot 编辑器里搭 |
| 性能热点 | C++ GDExtension | 见上面第四节 |
| **测试与游玩** | **Godot** | 侧栏「运行」直接跑 |

一句话:**除了测试与游玩,其他都能在 Blender 里做完。**

### Shift+A 添加节点(蓝图式)

在游戏逻辑节点编辑器里按 **Shift+A**,菜单**最上面**就是我们的内容:

```
搜索节点…                    ← 打字就出来,和蓝图一样
最近使用 ▸                   ← 最近加过的 8 个
─────────────────────────
事件 / 流程 / 移动 / 动画 / …
─────────────────────────
把选中的两个节点连起来
```

在节点上**右键**也能打开同样的入口。

三个设计细节:

- **放在最上面而不是最下面。** 一开始用 `append` 追加到末尾,结果在默认面板
  高度下正好被截断 —— 表现就是"按了 Shift+A 什么都没有",非常容易误判成
  功能没做。现在用 `prepend`。
- **「最近使用」始终显示,哪怕还是空的。** 一开始写成"空就不画",结果新用户
  第一次按 Shift+A 时菜单里没有这一项,等用过几个节点后菜单**形状变了**,
  肌肉记忆失效。菜单结构应该稳定。
- **搜索是最上面的入口。** 47 个节点靠翻分类找太慢,而且蓝图里本来就是
  "打字搜"最常用。

> **无头模式验证不了"按下去真的弹出来"** —— 那需要一个真实的 NODE_EDITOR 区域。
> `tests/blender_menu.py` 验证到的是:两个菜单回调在正确的节点树里会画出
> 搜索入口 / 全部 10 个分类 / 最近使用,在别的节点树里不画,`prepend`/`remove`
> 都可用,最近使用列表的排序和长度上限正确。
> 剩下那一步请在 Blender 里手工按一下 Shift+A 确认。
