`(0.5, 1.0, 0.5)` —— 那正是这个默认值,不是你手填的。

## 第十六轮:站不住的**真正**原因(第三次才挖到底)

上两轮我改的是"手填尺寸"和"平面零厚度" —— 都是真 bug,但**不是你这个**。
这一轮拿你导出后的 `World.tscn` 逐行对,终于对上了:

```
[sub_resource type="CapsuleShape3D" id="shape_1"]
radius = 0.5   height = 1.0          ← 以**物体原点**为中心的胶囊

[node name="示例角色" ...]
transform = ... 0.0, 0.0, 0.0        ← 角色原点在坐标原点
```

而角色的网格顶点是 **z = 0..1**(原点在**脚底**,不是中心)。
于是胶囊有一半在**地面之下** → Godot 的物理把它往下挤 → 你看到的"站不住"。

**修法**:导出碰撞体时算出「模型包围盒中心 − 物体原点」,写进碰撞节点的
`position`。现在生成的是:

```
[node name="Collision" type="CollisionShape3D" parent="."]
shape = SubResource("shape_1")
position = Vector3(0.000000, 0.500000, 0.000000)     ← 抬到与模型对齐
```

这条对**所有**原点和模型中心不重合的物体都生效(大量建模软件导出的
模型都是"原点在脚底")。

## 第十七轮:找到了 —— **碰撞体尺寸没做轴向换算**

你截图里"地面立起来了"就是铁证。上一轮我修了碰撞体的**位置**偏移,
但**尺寸**一直是按 Blender 的轴序直接写进去的:

```
Blender 里: 地面 = 20 x 20 的平面(Z 方向≈0)      Z 是"上"
Godot  里: size = Vector3(20, 20, 0.1)            Y 才是"上"
           -> 20 宽、**20 高**、0.1 厚的**一堵竖墙**
```

角色撞上的是一堵墙(还只挡住 0.1 米厚的一条线),所以**永远站不住** ——
这也解释了为什么"新建地面也一样",因为**任何**平面都会变成竖墙。

**修法**:自动尺寸补上 `Blender(x, y, z) -> Godot(x, z, y)` 换算
(位置早就有 `_godot_position` 做这件事,尺寸漏了)。现在:

```
地面     -> BoxShape3D size = Vector3(20, 0.1, 20)   ← 20 米见方、10 厘米厚,平放
示例角色 -> CapsuleShape3D  + position = (0, 0.5, 0)  ← 与模型对齐
```

回归断言也加了:**「地面是平的(薄在 Y 轴,不是竖墙)」** —— 以后不会再退化。

> 教训(我记在清单里):碰撞体有**三样**东西都要做坐标转换 ——
> 位置、朝向、尺寸。我修了位置就以为完事了,结果尺寸那一路一直错着。

## 第十八轮:两个小问题
