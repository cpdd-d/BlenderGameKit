# 导出管线:Blender 的材质 / 灯光 / 环境是怎么进 Godot 的

## 2026-10-17：预览一致性修正

“Godot 观感”现在按实际导出路径预览：

* **调色**：Linear 模式在显示 sRGB 空间计算。先应用场景环境调色，再应用执行链上连接的“环境_设置色调”；不再把暗部提前截断成灰色。饱和度、乘法染色、圆形/矩形遮罩、羽化和反选按运行着色器计算，数值 0 也有效。
* **灯光**：临时副本按 Godot 的 sRGB 灯色解释显示冷暖色，同时同步覆盖颜色、射程和投影。原始数据供保存和导出使用，共享灯数据不会被重复缩放。
* **材质**：打开“卡通材质”和“卡通跟随场景光照”时，普通材质临时采用与导出相同的基础色、贴图和透明裁切，以漫反射近似运行材质；恒定环境补光也按运行参数计算。源节点树与共享网格材质不被重建。
* **纹理**：中文贴图名生成稳定且不同的文件名，修复地板和墙面贴图都写成 `texture.png` 后互相覆盖的问题。已有常见 ASCII 路径保持兼容。
* **恢复**：保存、导出和关闭预览会恢复临时数据；自定义合成器不会被接管。原生默认合成器的 Viewer/Reroute 路线可正常预览，关闭后恢复原连线。

安装更新包并重新加载插件后，在“Godot 观感”点击“预览贴近 Godot”。已有项目需重新“导出到 Godot”，才能修复曾被覆盖的贴图。灯光倍率仍可在“游戏环境与后期”调整。

预览期间原生灯光参数可以继续调整，保存/导出会先还原换算。原始材质节点的编辑请先点“还原”，编辑完成后重新开启预览；临时预览材质用于展示导出结果。

这是 EEVEE 对 Godot 的近似预览。逐灯卡通色阶、距离衰减、泛光核、SSAO/SSIL、天空和非 Linear 色调映射仍可能不同；同名 AgX 也不应宣称像素完全一致。严格对照应使用相同机位、分辨率和重新导出的资源。

回归入口：`tests/blender_godot_post.py`（真实像素）、`tests/blender_godot_lights.py`（灯光/导出还原）、`tests/blender_godot_material_preview.py`（GPU、共享网格、保存/导出）和 `tests/blender_texture_identity.py`（中文贴图与引用）。

> 用户问的是:"怎么把 blender 的材质,灯光,环境导出的?在预览状态下正常,
> 但运行时却全黑了" —— 这份就是那条链路的**逐段说明**,外加"全黑"那次
> 的真实根因(已修)。
>
> 目标链路(插件真正要保证的那条):
>
> ```
> Blender 原生画面 ──打开『Godot 观感』──▶ 预览 ≈ Godot 实际运行画面
>        │
>        └──导出到 Godot(一次导完:脚本 + 模型 + 材质 + 场景 + 环境/后期)
> ```
>
> 也就是:**预览要能代表运行**,而不是"两套各调各的"。

## 一、导出入口(只有一个)

`导出到 Godot`(`gk.export_godot`)一次导完下面全部内容 —— 侧栏里那些分散的
导出/运行按钮第一百三十九轮已按用户要求删掉:

| 内容 | 产物 |
|---|---|
| 逻辑脚本 | `scripts/game_logic_<场景>.gd`、`gk_main_ui.gd`、`gk_world.gd` … |
| 模型 / 场景 | `scenes/<场景>.tscn`(几何、灯光、相机、碰撞、实例) |
| 材质 | `materials/<名字>.tres`(含卡通 / NPR 变体) |
| 环境与后期 | `scripts/gk_environment_<场景>.gd` + `shaders/gk_post.gdshader` |
| 资源 | `audio/`、贴图、粒子、`.glb` 等 |

## 二、材质

1. Blender 材质 → 导出时按**节点结构**判定走哪条路:
   * 普通 PBR(`Principled BSDF` + 贴图)→ 导成 glTF PBR,Godot 里是
     `StandardMaterial3D`;
   * 卡通 / 二次元(『显示_卡通风格』那一套:硬阴影步进、暗部色、描边、
     边缘光)→ 导成**自定义着色器材质**(`.tres` 里挂 `shader_type spatial`,
     参数是 `gk_toon.gdshader` 那一套)。
2. 贴图随包复制到 Godot 工程,`.tres` 里写 `res://…` 相对路径。
3. ⚠ 预览不画的部分(如实写在 `godot_look.describe()` 里):**描边**、
   **逐片元面部 SDF** —— 这两样 Blender 视口里做不出同款,导出后按 F5 看。

## 三、灯光

1. 每盏灯导出成 Godot 的 `OmniLight3D` / `SpotLight3D` / `DirectionalLight3D`,
   写 `light_energy` / `light_color` / `omni_range` / `shadow_enabled`。
2. **能量换算**是两边唯一的约定:
   ```
   点光 / 聚光:light_energy = Blender 瓦数 ÷ 1000
   平行光     :light_energy = Blender 辐照度 × 1.2
   ```
   (1000W ≈ 1.0 这条只在"离灯 9.4 米"那一个距离成立 —— 所以想精确调,
   在灯物体上打开『用这里的值导出』,直接写 Godot 侧的值。)
3. **预览侧**为了对上运行画面,有一层"调暗":
   * 场景级 `预览灯光倍率`(默认 **0.06**,实测标定:预览 0.9130 vs 运行 0.3953);
   * 逐灯 `预览补偿`(默认 1.0,第一百三十八轮加的)。
   ⚠ 这两个**只影响预览**,导出能量一个字节都不看它(自查里钉着)。

## 四、环境与后期

1. 场景设置里的 `env_*`(背景 / 环境光 / 雾 / 泛光 / 色调映射 / 曝光)导出成
   场景里的 **`WorldEnvironment`**(`environment = SubResource(...)`)。
2. 『游戏环境与后期』图那一支(`环境_默认环境 → 环境_设置色调 → …`)导出成
   **全屏后期层**:`CanvasLayer(layer=100)` + `ColorRect` + `gk_post.gdshader`,
   参数是 `grade_on / brightness / contrast / saturation / tint / mask_* /
   eye_*`。它的 `_enter_tree()` 把自己加进 `gk_post` 组,逻辑图的
   『后期_播放睁眼』按组找它。
3. 天空 / 昼夜 / 云 / 太阳是**运行时天空着色器**(`gk_sky.gdshader`),
   Blender 预览只能按"当前时刻铺一层天色"近似。

### 那次"运行时全黑"的根因(已修,第一百三十九轮)

症状:预览正常,一进游戏**整个画面全黑**,只剩 HUD。

逐行查的结果:

* 示例的开场过场会把世界冻住(`tree.paused = true`);
* 『环境_睁眼效果』是**进关卡自动播**(`gk_trigger = AUTO`),它用一个
  `create_tween()` 把眼皮从 `slit = 0.06` 张到 `1.0`;
* GDScript 的 `Tween` 默认是 **`TWEEN_PAUSE_BOUND`** —— 世界一冻,
  tween **跟着停**,眼皮就**卡在 6% 那条缝上** = 94% 黑 ✓
  (真机探针:冻住时 `eye_on=1.0 amount=0.06`)。

修法两条(都在 `asset_export._post_eye_lines` 出码里):

1. `_gk_post_eye_tween.set_pause_mode(Tween.TWEEN_PAUSE_PROCESS)` ——
   世界冻着也照样张开;
2. 兜底:`process_always = true` 的定时器 + 令牌,到点还没张开完就
   **直接把眼皮掀开并关掉**(tween 被谁 kill 了也不会永远黑着)。

真机回归钉子(`check_story_demo.py` 的 `STORY_EYE_GUARD`):
世界冻着时 `on=0.0 amount=1.0` ✓

## 五、排查顺序(以后遇到"预览对、运行不对")

1. **先看是不是"被冻住/被暂停"的动画** —— tween / `create_timer` 默认都跟着
   `tree.paused` 停;需要它照跑的必须显式声明(`TWEEN_PAUSE_PROCESS` /
   `create_timer(t, true)`)。
2. 再看后期层参数:开上帝机按 F5 进游戏,`gk_environment_<场景>.gd` 里那几个
   `set_shader_parameter` 是不是你要的值(`eye_on` 卡在 1.0 就是眼皮没张开)。
3. 灯光/环境量纲:导出能量是 `瓦数 ÷ 1000`,不是瓦数本身;预览那层"调暗"是
   **预览专用**,不要去改它来修游戏里的亮度 —— 那只会让两边越差越远。
