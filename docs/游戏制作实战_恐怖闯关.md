## 一、认知地图:你连的线是怎么变成游戏的

```
你在 Blender 侧栏连的节点图                    Godot 里跑的东西
─────────────────────────                   ────────────────
『游戏逻辑』图 (关卡图)  ──┐
『游戏AI』图            ──┼── 导出 ──►  scenes/*.tscn  +  scripts/game_logic_*.gd
『界面设计图』          ──┘                (每个 Blender 场景 = 一张 .tscn)
                                                  │
Blender 物体/灯光/材质 ─────────────────────► art/*.glb + materials/*.tres
                                                  │
                                            音频/着色器/曲线
```

三条铁律(违反任何一条,现象都是"我明明连了线却不动"):

1. **一张图必须有『事件』节点当入口**(『每当_准备』『每当_物理帧』『每当_输入』『进入区域』…)。
   没有事件 = 图再漂亮一行都不会跑。
2. **金线是先后,灰线只传值**。一条金线输出只能接一条线,要分叉用『流程_序列』,要条件用『如果_否则』。
3. **物体要勾『脚本挂载目标』**(物体属性里的「游戏物理 (BlenderGameKit)」面板)。
   不勾不报错,只在导出报告里给一条告警——这是"角色不动"的头号原因。

一个 Blender **场景** = 一关 = 一张 `.tscn`。关与关之间用『场景_切换关卡』,**不是**加载新场景树,
所以玩家实例、`[autoload]` 里的东西能跨关存活(示例里"同一个玩家"就是这么活的)。

## 二、开工前先写四句话,别先开 Blender

恐怖游戏最容易死在"走廊加长、纸条变多、怪物变快"——时长涨了,体验更空。
先钉死这四条,后面所有取舍都拿它当尺子:

| 问题 | 本示例的答案 | 为什么这么定 |
|---|---|---|
| 玩家在**怕**什么 | 黑暗里有个会听声音的东西 | 明确恐惧源,才知道该做什么反馈 |
| 玩家**能做什么** | 走/跑/蹲/手电/敲击/交互 | 每个动词都得对玩法有用,否则是噪音 |
| **失败**的代价 | 回最近安全屋,保留已有纸条 | 回太远玩家弃游;不保留等于惩罚练习 |
| 一局多长 | 5–8 分钟(短篇)→ 目标 60–90 分钟 | 先短篇跑通闭环,再填内容 |

## 三、搭一关的顺序(灰盒 → 交互 → 光 → 相机)

**别一上来做美术。**示例里全是方块,但它好玩,因为反馈是通的。

1. **灰盒**:地面 + 四壁 + 门框。用 `solid_box()` 建(带碰撞),装饰件用 `decor()`(不带碰撞)。
   > 血泪:装饰件如果按结构件导出,一棵门框会长成 **半径 6.5 米的球**把走廊堵死。
2. **触发区**:『进入区域』的判定体。它们是 Area3D,必须 `hide_render`(只留碰撞,不渲染),
   否则玩家会在门口看到一块**亮蓝地板贴片**——这就是本轮截图里抓到的真问题。
3. **灯光**:恐怖片一半是影子。三件事:主光要暗、功能光要准(手电/台灯)、别让深色灯罩贴着点光(会爆白团)。
4. **相机**:第三人称用弹簧臂。**机位距离是玩法参数,不是美术参数**——本轮就发现白盒子角色占了 35% 画面高度,怼脸。

每加一样东西,立刻按 F5 看一眼。**预览和真机观感差别很大**(雾、PBR、亮度都会飘),
唯一可信的是 Godot 里的画面——所以下一节用截图验收。

## 四、玩家 = 输入 + 移动 + 相机(用预设,别手搓)

侧栏『游戏逻辑』→『预设』→ **生成第三人称角色**,一条命令给你输入/移动/跳跃/相机/动画。
然后只改你要改的那一处。示例里角色图(公共)只放"人":移动速度、视角、手电、蹲跑;
**HUD / 存档 / 触发区 / 失败判定全在关卡图里**——这条分工是本项目最值钱的经验:

| 图 | 挂在哪 | 只放什么 |
|---|---|---|
| 角色图(公共) | 每关的角色物体 | 输入 / 移动 / 视角 / 手电 / 蹲跑 |
| 关卡图 | 每关的场景根 | HUD / BGM / 触发区 / 存档 / 切关 / 失败 |
| AI 图 | 由关卡图『AI_启用』拉起 | 巡逻 / 听见 / 去查看 / 追击 |

> 坑:角色预设的速度是**检查器参数** `@export move_speed`。你在图里用『变量_设置』写一个同名变量,
> 导出侧会把变量改名(`move_speed_param`),而移动代码读的是改名后的那个 → **蹲跑静默失效,不报错**。
> 正解:把变量接到『移动_按方向』的**速度引脚**上。

## 五、让关卡"有事发生":交互、HUD、存档、失败

一个关卡的最小闭环(缺一条就不像游戏):

```
进关 → 目标(先找齐 3 张纸条) → 交互拿东西 → 计数器涨 → 门口校验 → 放行
   ↑                                        ↓
   └──────── 存档 / 检查点 ←── 失败(被抓) ──┘
```

- **交互**:示例用「靠近(Area3D)+ 按 E」,屏幕出 `[E] 推开门`。
  比"踩进去自动拿"好在:玩家有决定权,能在门口反复进出而不误触发。
  > 想做准星射线要一张"起点=相机、方向=相机朝向"的卡片;现有『射线_检测』的起点是脚本宿主、方向是静态属性,拼不出来。
- **HUD**:目标一句话 + 计数 + 资源(手电电量)。**别在 HUD 上写说明文**,名称能说明功能就够了。
- **存档**:『存档_写入』落盘 `user://gk_*.json`。检查点 = 一个位置 + 一个字符串变量。
- **失败**:别重载整关。示例改成「被抓 → 冻世界 → 两个按钮(回到安全屋 / 回到标题)」,
  **回到安全屋后纸条数保留**——这一条直接决定玩家会不会骂人。

## 六、怪物:规则写在 AI 图里,不写在玩法图里

`AI_状态` + `AI_转场`:**起始状态是没有任何转场指向它的那个**。示例的状态机:

```
巡逻 ──看见──► 追击 ──失去目标──► 去查看 ──到达没发现──► 巡逻
  ▲                                                        │
  └────────────────── 听见动静(K / 跑动)───────────────────┘
```

声音是资源:跑动发 6 米噪音、蹲走 0 噪音、按 K 主动敲。**噪音是"敌人听得见"的接口**,
不是播放一段音效——示例里 `弄出动静` 节点直接把响度喂给 AI 的听觉通道,玩家按 K 之后 AI 状态真的会变 `去查看`。

> 坑:两个 Area3D 相邻时,离开/进入落在**同一物理帧**,顺序不确定。
> 无条件"离开就清交互目标"会抹掉刚设好的新目标 → 要写成"离开时目标还是我才清"。

## 七、导出 + 跑起来:黑屏/不动的排查顺序

导出是生成脚本最后一步(`project.create_project` + 逐场景导出),产物:

```
examples/demo_horror/
├─ 恐怖示例.blend              ← 4 个 Blender 场景
└─ 恐怖示例_godot/
   ├─ scenes/  标题.tscn 教室.tscn 走廊.tscn 楼梯间.tscn (+3 个角色 tscn)
   ├─ scripts/ game_logic_*.gd (节点图生成的代码)
   ├─ art/ materials/ audio/ shaders/
   └─ project.godot  ([autoload] 主界面、输入动作 key_* 都在这)
```

| 现象 | 先查什么 |
|---|---|
| 一片黑 | 相机是否存在并 `current`;FOV 是不是被写成 22.9°(长焦怼屏);雾色是不是被 sRGB 转错成牛奶灰 |
| 角色不动 | 物体勾了『脚本挂载目标』吗;图里有事件节点吗 |
| 相机穿模 / 贴脸 | 弹簧臂长度与相机 near 平面;运行时别让两套脚本抢同一台相机 |
| 过场/演出冻住 | Tween 有没有 `TWEEN_PAUSE_PROCESS`;`create_timer(t, true)` 的第二个参数 |
| HUD 被 3D 挡住 | 层级(CanvasLayer);半透明底会不会被亮模型穿透 |
| 改图不生效 | 装进 Blender 的是**副本**,改完仓库要重装扩展并重启 Blender |

## 八、自动试玩:为什么必须真的玩一遍

静态断言只能证明"节点连对了",证明不了"玩起来不难受"。
示例这次用 `scripts/play_horror_full.py` 做真窗口试玩:

```
拷工程到 _dist/ → 注入一个挂 [autoload] 的探针(跨场景存活)
   → 真窗口 1280x720 跑起来 → 真点按钮 / 真走触发区 / 真按键
   → 每步一张 png + 一行 PLAY_xxx 日志 → 总结论 + 退出码
```

它一上来就抓到 8 条**静态断言永远抓不到**的问题(逐条表见 `examples/demo_horror/README.md` 的「第二轮」一节),
其中最阴的一条是:

> 按住 K 引怪时,前后两帧截图**逐字节相同**(sha256 一致)。
> 也就是说那 0.6 秒里玩家屏幕上一个像素都没变——
> 逻辑上 AI 状态确实变成了 `去查看`,但**玩家完全无法判断自己有没有成功**。

这叫"逻辑正确、体验为零"。判断标准很简单:**玩家能不能从画面上看出因果**。

### 8.1 探针自己也会撒谎：三个坑（2026-10-28 补）

写自动化试玩时踩到的，每一个都能让你**误判成"游戏坏了"**：

| 坑 | 现象（很像 bug） | 真相 |
|---|---|---|
| **暂停时物理不推进** | 把玩家传送到侧门、等 90 帧，`Area3D.get_overlapping_bodies()` 里**永远没有玩家**，`body_entered` 也不派发 | `get_tree().paused == true` 时物理服务器整个停下，overlap 集合被冻住。传送也没用。**每步之前先断言 `paused == false`**；真被抓了就先点『回到安全屋』解冻 |
| **暂停后 `await get_tree().physics_frame` 不返回** | 协程像卡死，日志停在半截 | 同上：暂停时物理帧信号不发。用 `create_timer(秒, true, false, true)`（第 4 个参数 `process_always=true`） |
| **传送当帧就读 / 就按 E** | 传送到门口按 E 没反应；同一段代码在别的关卡却能用 | 传送那一帧 `overlaps=0`（连地面都还没进），**+1 帧**只有地面，**+2 帧**才出现玩家、`交互目标` 才变成门名。**至少要等 2 个物理帧**，或者轮询「交互目标 == 门名」再按 |

> 还有一条 **headless 专属**：`--quit-after N` 数的是**帧**，`create_timer` 数的是**墙钟**。
> headless 跑得远快于实时，400 帧不到 2 秒就把进程杀了 —— 等墙钟的探针要按几千帧给预算，否则表现为"跑到一半没有任何输出"。

**怎么定位这类问题**：不要一开始就怀疑游戏，先做**二分**。这次把一个"侧门永远打不开"的悬案，用六组对照钉在了"暂停"上：

```
A  进关 → 直接到门                 PASS（overlaps 有玩家、target=门名）
B1 躲藏 + 退出 → 到门              PASS
B2 只看 3 页病历 → 到门            PASS
B3 躲藏 + 病历 → 到门              PASS
B4 躲藏 + 病历 + 被抓一次 → 到门    paused=true  overlaps 只有地面
B5 只被抓一次（没躲没拣）→ 到门     paused=true  同上   ← 这一组才把元凶抓出来
```

**教训**：`B4` 会让人以为是"躲藏或病历弄坏了门"；只有再加一组 `B5`（只留被抓）才看得出真因是暂停。
**二分要一次只留一个变量，而且一定要有"只留嫌疑最小的那个"的对照组。**

## 九、实战:这一轮给示例加了什么(逐条讲怎么落)

起点是 5–8 分钟的短篇,缺 5 样东西(缺口是搜代码确认的,不是猜的)。

### 9.1 手电 + 电量(F)

- **为什么**:恐怖游戏里"光也是资源"——照亮路,同时暴露自己;电池有限就是持续选择。
- **怎么落**:`灯光_设置` 控制手电筒灯的开关,`变量` 存电量,`每当_物理帧` 里递减,`界面_文本` 显示。
- **判据**:电量从 100 递减(每秒 1.5),耗尽自动关灯,HUD 同步。

### 9.2 蹲走 + 跑动噪音(LeftCtrl / LeftShift)

- **为什么**:给玩家一个"潜行预算"——快就吵,慢就安全。
- **怎么落**:`每当_物理帧` 里三条 SetVar(Ctrl / Shift / 都松)写**移动速度**,
  再把该变量接到『移动_按方向』的**速度引脚**;跑动时调用 `弄出动静`(响度 6、类型"脚步"),
  与"没在蹲"相与后喂给 AI 听觉。
- **坑 1**:写同名变量会被改名 → 蹲跑静默失效(见第四节)。
- **坑 2**:相机压低这件事**节点做不到**——弹簧臂每物理帧把相机拽回"枢轴+1.4m",
  任何节点改相机都会在下一帧被覆盖。正解是让一个小脚本排在角色脚本**之后**跑(`process_physics_priority = 100`)。

### 9.3 射线/靠近 + E 交互

- **为什么**:把"踩进去自动拿"换成"我看得见、我按 E、它才没",玩家才有掌控感。
- **怎么落**:每张纸条旁边一个 Area3D:进入 → 写 `交互目标` + 出 `[E]` 提示;
  按 E → 纸条+1、字幕、写日志行、销毁纸条、清提示。门口同样一条链(E 推门,不够就显示"还差 N 张")。

### 9.4 笔记日志(J)

- **为什么**:线索驱动。玩家得能回头看自己收集了什么,否则"剧情"只是路过。
- **怎么落**:`界面_面板` + 三行文本,一开始就藏;J 开关,Esc 关。层级要在 HUD 之上、暂停之下。
- **本轮限制**:日志只在教室(笔记所在关)。跨场景要先把"已读"塞进存档信封。

### 9.5 安全屋 + 检查点

- **为什么**:失败惩罚决定玩家敢不敢探索。
- **怎么落**:走廊里 `安全屋`(Node3D 标记)+ `安全屋区域`(Area3D):进入 → 存盘 + 写 `检查点`;
  被抓 → 冻世界 → 两个按钮;点『回到安全屋』→ 解冻、传送、**保留纸条数**,不重载场景。
- **坑**:回安全屋后忘了收起"你被抓住了"面板 → 玩家站在安全屋里看着失败界面。本轮截图直接抓到了。

## 十、从 5 分钟做到 1–2 小时:先算账,再动手

**别直接把走廊拉长。**先把时长拆成"可数的内容单元":

| 内容单元 | 一个值多少分钟 | 1–2 小时要几个 |
|---|---|---|
| 一章(探索+找 3 样东西+一次追逐+出口) | 12–20 | 5 章 |
| 一个可读文本(笔记/病历/录音) | 1–2 | 10–15 |
| 一次机关解谜(保险丝/录音机/密码门) | 3–5 | 3–4 |
| 一次"安全屋存档" | — | 每 5–8 分钟一个 |
| 一次新机制登场(手电/蹲走/躲柜/断电) | — | 每章 1 个 |

合计 71–96 分钟是**能算出来的**,不是拍脑袋。低于这个密度,时长一定靠"走路"堆出来。

**下一版做什么**(完整版设计见 [`恐怖示例_1-2小时设计.md`](恐怖示例_1-2小时设计.md)):

1. 先把 **20–30 分钟纵切片**(教室+走廊)打磨到"失败回安全屋不超过 5 秒、每 3–5 分钟有一次信息或压力变化";
2. 再铺第 3–5 章(**填内容,不改架构**);
3. 最后才是美术/动画/音频定稿。

## 十一、你自己动手的 5 个练习(从易到难)

1. **改一句话**:把教室的目标文案换掉,重建、门禁、试玩,看 HUD 变了没有。
2. **加一张纸条**:第 4 张纸条 + 门口校验改成 >=4。体会"内容 = 一个 Area3D + 一条计数链"。
3. **加一个吓人点**:用『恐怖_断电』或『恐怖_音效』挂个定时器,每 26 秒来一次。
4. **让日志跨场景**:把 3 个"已读"布尔塞进存档信封,走廊也能按 J 看教室的笔记。
5. **加一个真射线交互**:写一张"起点=相机、方向=相机 forward"的卡片,替掉靠近判定。

每做一个,都跑一遍 `python scripts\check_horror_demo.py` + `play_horror_full.py`。
**你的验收标准不是"我想通了",是"探针绿了 + 截图里玩家看得出因果"。**
