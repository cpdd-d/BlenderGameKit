# Blender / Godot 预览一致性验证（2026-10-17）

本次修正了预览调色、灯色解释、恒定环境补光、受光边缘光、普通材质替换以及中文贴图文件名冲突。测试使用用户截图对应的 `examples/demo_story/恐怖闯关示例.blend` 的“大堂”场景，原工程没有覆盖。

## 同机位结果

Blender 4.5.5 EEVEE 与 Godot 4.7.2 Vulkan Forward+；960×540。Blender 相机位置 `(-38,-2,6)`、目标 `(0,0,3)`、34 mm 镜头/36 mm 传感器，对应 Godot 位置 `(-38,6,2)`、目标 `(0,3,0)`、垂直视角 33.16644°。Godot 隐藏 HUD，保留运行后期。

指标为 RGB 每通道归一化到 0–1 后的平均绝对像素差，数值越小越接近。两组 Blender 都与**修复贴图冲突后重新导出的同一份 Godot 参考图**比较。

| 区域 | 修改前（原倍率 0.06） | 修正并标定后（倍率 0.18） | 差异下降 |
|---|---:|---:|---:|
| 整幅画面 | 0.08268 | 0.03943 | 52.3% |
| 大厅区域（x 15–919，y 200–434） | 0.11899 | 0.08454 | 29.0% |

0.18 是此场景、此机位在多档实测后的折中，只写入 `_dist/preview_match/恐怖闯关预览校准.blend` 的大堂场景。插件全局默认与用户原工程中的灯光倍率保持原值。原倍率 0.06 下背景与冷暖色有所修正，但大厅整体亮度仍偏暗，不能把标定后的收益当成所有场景的默认收益。

这不是像素完全一致。不同区域最合适的灯光倍率不同，后墙误差没有改善；EEVEE 与 Godot 的距离衰减、阴影滤波、泛光核、SSAO/SSIL及逐灯卡通色阶仍不同。非 Linear 色调映射、动态天空与演出效果也仍有边界。

## 可复跑（2026-10-30）

上面那些数字原本只有 `.audit/preview_match/` 里的一次性脚本能算出来，换台机器
或过几个月就没法复现。现在压成两条命令（`scripts/check_preview_match.py`）：

```powershell
# 1) Blender 侧出图（自动打开 .blend、套『Godot 观感』、按固定机位渲染）
blender -b --python scripts\check_preview_match.py -- --render --out .audit\preview_match\run\blender.png

# 2) Godot 侧抓帧（临时挂一个 autoload 脚本，跑完删除、project.godot 原样还原）
python scripts\check_preview_match.py --capture --project examples\demo_story\恐怖闯关示例_godot --out .audit\preview_match\run\godot.png

# 3) 比对（加 --check 时超阈值非零退出，可当门禁用）
python scripts\check_preview_match.py --blender .audit\preview_match\run\blender.png --godot .audit\preview_match\run\godot.png --out .audit\preview_match\run --check
```

也可以一步走完：`--full`（Blender 渲染 → Godot 抓帧 → 比对），输出
`blender.png` / `godot.png` / `diff.png` / `preview_match.json`。

**顺序不能反也不可省**：先在 Blender 里『导出到 Godot』，再抓帧，再比对。
2026-10-30 实测：工作区的 `.blend` 已经改过多轮，而 Godot 工程还是旧导出，
直接比得到 **0.17238 / 0.13589**（远差于表中的 0.03943 / 0.08454）。
这个数字说明的是"两边不是同一版内容"，不是"预览变差了"。

两条可信度证据：

* 用新工具复跑 2026-10-17 留下的旧样本，得到的正是 **0.03943 / 0.08454** ——
  说明指标口径（RGB 归一化后的平均绝对差）没有漂；
* 抓帧跑完后工程里没有残留脚本、`project.godot` 与原来一致（已实测）。

> 无头导出目前不可用：`gk.export_godot` 在后台模式下拿不到"用哪棵逻辑树",
> 会报『有 4 棵游戏逻辑节点树，无法确定用哪棵』；用"选中节点"的退路能过这一关，
> 但下一关会停在『默认角色导出失败：请给默认角色指定一张角色逻辑图』。
> 所以**导出仍然要在界面里点一次**，脚本只负责渲染/抓帧/比对。

## 使用

1. 安装 `_dist/preview_match/blender_game_kit-0.1.0.zip`，重新加载插件或重启 Blender。
2. 打开校准副本，在“Godot 观感”点击“预览贴近 Godot”。
3. 原有项目重新执行“导出到 Godot”，以更新之前撞名覆盖的纹理。
4. 查看同目录的 `compare.html` 和预览/运行截图。编辑原始材质节点前先点“还原”，完成后再开启预览。

复现脚本、原始测量数据和隔离导出的 Godot 项目保存在 `.audit/preview_match/`，没有替换用户现有的 Godot 项目。
