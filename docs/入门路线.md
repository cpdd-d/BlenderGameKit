# 入门路线 —— "我想做 X,该连哪几个节点?"

这一页不解释节点,只回答**"要做某件事,从哪下手"**。
每条路线都是:要放哪几个节点 → 怎么连 → 看哪个示例 → 会踩什么坑。

> 想知道某个节点的全部参数?看 [节点手册.md](节点手册.md)(从代码自动生成)。
> 想知道"执行线 / 值线"这些概念?看 [节点怎么连.md](节点怎么连.md)。

---

## 零、三条必经规则(不记住这三条,后面全是白试)

**1. 每个逻辑都要有一个『事件』节点当入口。**
『每当_准备』『每当_物理帧』『每当_输入』『进入区域』…… 这些都是事件。
没有事件节点 = 图再漂亮也不会跑一行。

**2. 金色『执行』线决定先后顺序,灰线只传值。**
"先做 A 再做 B" 是把 A 的『执行』接到 B 的『执行』。
"把这个数给那个节点" 才是把灰线接过去。
⚠ 一条『执行』输出**只能接一条线** —— 想分两路就用『流程_序列』,
想按条件分就用『如果_否则』。

**3. 物体必须勾『脚本挂载目标』,否则角色不动。**
在物体的『游戏物理 (BlenderGameKit)』面板里勾。
**不勾的话导出不会报错,只在导出报告里给一条告警** —— 这是
"我明明连了线却不动" 的头号原因。

## 一、让角色能跑能跳(第三人称)

**最快**:侧栏『游戏逻辑』→『预设』→ **生成第三人称角色(预设)** ——
一条命令生成输入 / 移动 / 跳跃 / 相机 / 动画,然后在上面改。

**手动搭**(想自己控制每一处时):

| 放什么 | 连到哪 |
|---|---|
| 『每当_物理帧』 | → 『移动_按方向』(走出来 WASD 移动) |
| 『每当_输入』(或『输入_按键』+『如果_否则』) | → 『移动_跳跃』 |
| 『每当_准备』 | → 『相机_启用』 |
| —— | 加一个『相机_弹簧臂』,把主相机挂到角色身上 |

**让走↔跑过渡自然**(第六十一轮):别用状态机硬切,用**混合树**。
```
每当_准备 → 动画_混合树(混合点 = 走:0|慢跑:1|冲刺:2,参数 ← 变量_读取(速度))
每当_物理帧 → 变量_设置(速度 = 角色当前速度)   ← 参数每帧跟着速度走
```
* 参数落在 0 和 1 之间时,姿势是两段动画**按比例叠的** —— 速度一变,
  步幅跟着连续变化,不会"啪"地一下换动作;
* 『循环播放』**保持勾上**:glTF 导进来的动作默认不循环,播一遍就停在
  最后一帧(走路 / 跑步这类循环动作必须循环);
* **某一段想放快放慢**(第七十三轮):混合点写成 `动画名:位置:速度`,
  例如 `走:0|跑:1:1.4` —— 跑步这段就按 1.4 倍速播(不用改美术的动作);
* ⚠ 一个播放器要么交给混合树、要么交给『动画_播放』/『动画_状态机』,
  **别两边都驱动**(会互相覆盖)。

**要按"往哪个方向走"混**(第七十二轮):用**『动画_混合树2D』** —— 它用
X / Y 两个参数当平面坐标,四个角各放一段动画:
```
每当_准备 → 动画_混合树2D(混合点 = 待机:0:0|前走:0:1|左走:-1:0|右走:1:0)
每当_物理帧 → 变量_设置(X = 输入左右,Y = 输入前后)   ← 两个参数每帧跟着走
```
* 这就是 UE 里的 `Blend Space 2D`,八个方向的走跑过渡都靠它;
* **至少三个点**才围得成面(少于三个会提示,不会硬生成);
* 混合点**不用手打**:卡片上点『挑动画…』,一行一个点、动画名从下拉里挑
  (1D 那版也有了这个按钮);『位置 / X / Y / 速度』还是能直接改。

**状态机也能不硬切**(第七十五轮):走↔跑这种"没有明确切换点"的,混合树仍是
首选;但"待机 → 攻击 → 回待机"这类**有明确切换点**的,用状态机加**过渡时长**
就够了 —— 『动画_状态』上填一个默认秒数(比如 0.2),某条转场要不一样,就在
**『动画_转场』**上单独填(填了盖过状态上那个)。都不填 = 硬切。

**动画播到某一刻做点事**(第七十六轮):用**『动画_事件』** —— 填『动画』+
『第几秒』,播到那一刻触发一次(攻击挥到一半出判定框、脚步落地出声)。
```
每当_物理帧 → 动画_事件(动画 = 攻击,第几秒 = 0.4)
                  └ 触发时 → 『音效_播放』 / 判定 / 施加冲量…
```
* 一段动画只响**一次**;循环动画**每圈响一次**(走路脚步声挂一个就够了,
  不用自己数圈数);
* 一个时间点一个节点,多个就用『完成』口串成一条线;
* ⚠ 『第几秒』别超这段动画的长度(超了就永远不响)。

**要叠一层受击 / 挥砍**(第七十三轮):那叫**叠层** —— 一次性动作盖在
走路之上,**不打断走路**,播完自己收回去。
```
① 在『动画_混合树』卡片上填『叠层动画』= 受击(填了才会多出那一层)
② 玩法图:每当_物理帧 / 进入区域 → 动画_叠层(动作 = 播放叠层)
```
* 同一个动作不用再单独做"受击时也能走的走路动作" —— 叠层是在基准动画
  之上混出来的;
* 『保持秒数』0 = 让受击那段自己播完(推荐);填个数 = 到点强行收起;
* ⚠ 那段叠层动画**不要设成循环** —— 循环的东西播不完,人会一直僵在
  受击姿势上(插件会在导出时把它摁成"播一次",但你自己也别特意去勾循环)。

* **看示例**:`examples/demo_blend`(一个方块走↔跑,按 1 / 2 看差多少)
* **看示例**:`examples/demo_game`(小游戏)、`examples/demo_physics`(物理测试场)
* **坑**:角色物体要有**碰撞体**(不是"网格"),不然会穿地/悬空;
  2D 项目记得『导出设置』里选 2D,基类才是 `CharacterBody2D`。

## 二、做一个小怪追你

AI 的规则**不写在玩法图里** —— 单开一张『游戏AI』图(侧栏『游戏逻辑』→
『游戏AI』→ 打开/新建 AI 图),玩法图只放一个『AI_启用』引用它。

**AI 图里**:『AI_状态』+『AI_转场』,起始状态 = **没有任何转场指到它的那个**。

| 状态 | 行为 | 转场(条件来源直接填在卡片上) |
|---|---|---|
| 巡逻 | 巡逻(填两个巡逻点) | → 追击:『看见目标』(填视野距离) |
| 追击 | 追击(目标选玩家) | → 巡逻:『丢失目标』(填跟丢距离) |

**玩法图**:『每当_准备』→『AI_启用』(『作用在谁』选那只怪)。

* **看示例**:`examples/demo_ai` —— 巡逻 / 追击 / 去查看 三条路都搭好了
* **坑**:『作用在谁』那个物体必须是**角色体**(行为都是 velocity +
  move_and_slide),所以它得有碰撞体、基类是 CharacterBody。

## 三、让怪物**听见动静**过来查看(恐怖游戏的核心机制)

这是"扔石头把怪物引开"的那一套。

**玩法图**(弄出动静的那一方,比如玩家):

```
每当_物理帧 → 输入_按键(按住 K) → 如果_否则 → 声音_发出噪音
```

* 『声音_发出噪音』的**『响度』= 这声音能传多远**(跑步 8 / 开门 12 / 摔碎 20);
* **『间隔秒』必须填**。不填的话每帧都广播,怪物的"最后听到时间"永远是
  最新一帧,『安静下来』永远不成立 —— 它会一直黏在噪音点。

**AI 图**(听的那一方):

| 状态 | 行为 | 转场 |
|---|---|---|
| 去查看 | **去查看**(朝最近听到的噪音点走过去) | → 巡逻:『安静下来』(填记忆秒数) |

* **坑(一定会踩)**:『看见』的距离必须**小于**噪音『响度』,否则你
  "听得见"的那个距离上早就被**看见**了,直接走追击、听觉那条路根本轮不到。
  示例里视野 9 米、响度 16 米 —— 在 13 米处引怪,它只会朝声音过来
  (它知道"那边有响动",**不知道你在哪**)。
* **看示例**:`examples/demo_ai`(按住 **K** 试试)
* 想用"看见"和"听见"配合:两条转场都留着,注意『AI_状态』的
  **『入口数量』**要够(一个输入引脚只允许一条线,两条转场指进同一个状态
  就要调大,第二条接『进入 2』)。

## 四、捡东西 / 收集 / 计分

| 放什么 | 说明 |
|---|---|
| 『进入区域』(触发器;把玩家走进的那个范围设成它) | 事件:有人进来了 |
| →『变量_增减』(金币数 +1) | 记分 |
| →『界面_文本』(把金币数写进 HUD) | 显示 |
| 『每当_物理帧』+『如果_否则』(金币数 ≥ N) | 通关判定(推荐放物理帧里判,别放在拾取那一刻) |

* ⚠ **多个金币要各用一条独立的执行线**(或者各自一个『进入区域』)——
  "一个执行引脚只接一条线",接成一条的话只有最后一个会被处理。
* **看示例**:`examples/demo_game`(金币 / 守卫 / HUD / 胜负 / 按 R 重开)

## 五、做剧情对话(带选项分支)

| 节点 | 作用 |
|---|---|
| **『界面_对话框』** | 逐字冒出的对话,点一下跳过 / 继续 |
| **『对话_选择』** | 1~6 个选项,鼠标点或按数字键 1~6;输出"选了第几个"+ 每个选项一条执行出口 |

* 面板**不吃鼠标事件**,点击会穿透到下面的按钮 —— 所以对话中照样能点 UI。
* 选项文字用 `|` 分隔(留空自动补『选项N』)。
* **看示例**:`examples/demo_ui`(对话 + 暂停菜单 + 图片面板)

## 六、做门 / 机关(走过去就开)

```
进入区域 → 定时_缓动属性(把门的高度从 A 缓动到 B)
```

* 要**好几样东西一起动**(门 + 灯 + 音效)?用『定时_时间轴』——
  它本身就是「一条轨道一个『定时_缓动属性』」,几条串起来 = 整体联动;
  选中它点『预览』能在视口里看时间轴效果。
* ⚠ **动的是 glb 里看得见的那块**。碰撞代理是**另一个物体**
  (`Colliders/门`),挪门的时候要让它跟着动 —— 否则门看着开了、人还是走不过去。
* **看示例**:`examples/demo_curve`(开场运镜 + 门升起 + 触发区重播)

## 七、做恐怖氛围(幽暗 + 手电筒 + 暗角)

三件事,分别在三个地方设:

| 想要的效果 | 在哪设 |
|---|---|
| **暗**、有雾、有一点泛光 | 侧栏『游戏逻辑』→『游戏显示』→ 打开显示设置图 → **『显示_环境氛围』** |
| **手电筒 / 一盏灯** | 玩法图放 **『灯光_设置』**(类型选聚光 / 点光);手电筒勾『跟随相机』 |
| **画面四角压暗**(恐怖片那种视线收窄) | 玩法图放 **『屏幕_暗角』**(强度 / 内圈半径 / 边缘柔和 / 颜色 / 过渡秒数) |
| 受击整屏变红 | **『屏幕_滤镜』**(和暗角各占一层,可以叠着用) |
| **心跳:越紧张跳得越快越响** | **『氛围_心跳』**(每物理帧,紧张度引脚接『氛围_紧张度』) |
| **受惊一下:震屏 + 闪白 + 一声** | **『惊吓_事件』** —— 三样一个节点全做(它自己会震 / 闪 / 响) |
| **BGM 压低 / 整体音量淡出** | **『音效_总线音量』**(填总线名和分贝,可渐变) |

**心跳怎么搭**(第五十九轮):
```
每当_物理帧 → 氛围_心跳(紧张度 ← 氛围_紧张度)   ← 心跳那条
氛围_紧张度:『威胁』选那只怪,『近距』3 / 『远距』14
```
* 『氛围_紧张度』输出 0~1(离威胁越近越高);喂给『氛围_心跳』,
  心跳就会**越近越快越响**;低过『安静阈值』自己停(平常不咚咚咚)。
* 也能把紧张度接到『屏幕_暗角』的强度 —— 危险越近,视线越窄。
* ⚠ 心跳要**每帧跑**(接『每当_物理帧』);它按物理帧计时,不依赖 delta。

**惊吓怎么搭**:野外/门口摆一个触发区,`进入区域 → 惊吓_事件`;
想受惊时把音乐压低就再接一个『音效_总线音量』。

* **看示例**:`examples/demo_horror`(**四幕一条龙**:标题 -> 教室找纸条
  (带开场俯冲运镜)-> 走廊躲听觉怪物 -> 楼梯间选结局后回标题;
  手电筒 + 心跳 + 惊吓 + 存档;按住 **K** 弄出动静引怪)、
  `examples/demo_env`(白天 / 幽暗两关对比)、
  `examples/demo_lights`(三种灯 + 手电筒 + 数字键开关灯 + 暗角)

## 八、做 UI / HUD / 暂停菜单

* **HUD**(血条 / 分数 / 提示):『界面_文本』『界面_进度条』『界面_图片』;
* **暂停菜单**:『界面_暂停游戏』(Esc 一按世界全停,鼠标放出来);
* **好看的排版**:在『游戏界面』里建一张**界面设计图**,
  用『界面_面板』『界面_图片』『界面_文本』摆好,玩法图里一个
  **『界面_套用设计』** 就整张套过去(改设计不影响逻辑);
* **飘字**(+10 那种):『界面_飘字』;
* **列表 / 输入框 / 九宫格**:『界面_列表』『界面_输入框』『界面_九宫格』。

* **看示例**:`examples/demo_ui`

## 九、存档 / 读档

『存档_写入』(写一个值)→『存档_保存』(落盘);下次『存档_是否存在』→
『存档_载入』→『存档_读取到变量』。

* **看示例**:`examples/demo_platformer`(最高分真的落到磁盘上,探针验过)

## 十、切关卡 / 多场景

1. **一个 Blender 场景 = 一关 = 一张 `.tscn`**;
2. 每关各自建一张**游戏逻辑图**,在『导出设置』里给这一关选『逻辑图』;
3. 通关时用 **『场景_切换关卡』**(或『实例_重载场景』重开本关)。

* **跨关的数据**走**存档**:前一关 `存档_保存` 落盘,下一关开局
  `存档_载入` + `存档_读取到变量` 读回来(场景一切换,内存里的变量就没了)。
* **看示例**:`examples/demo_horror`(标题 / 教室 / 走廊 / 楼梯间 四幕,
  按钮与关底自动切、结局演完回标题)、
  `examples/demo_level`(关卡1 通关后切关卡2)

## 十一、做开场镜头 / 过场

1. 在 Blender 里画一条**曲线**(运镜轨道);
2. 玩法图放 **『相机_路径』**,把曲线选上,用『定时_时间轴』控制进度;
3. 选中运镜节点点 **『预览运镜』** —— 在 Blender 视口里直接看效果;
4. 想"走进门口重播开场":『进入区域』→ 重播时间轴
   (⚠ 时间轴从多处启动要用"变量当播放请求 + 分支启动",因为一个执行引脚
   只接一条线)。

* **看示例**:`examples/demo_curve`

## 十二、发布:从 Blender 里直接出 `.exe`

侧栏『项目』→ **打包成可执行文件**。

* 会先自动保存 + 导出,再调 Godot 的 `--export-release`;
* **需要先在 Godot 里装一次导出模板**(编辑器菜单『编辑器 → 管理导出模板 →
  下载并安装』)。没装的话插件会直接告诉你装法和期望路径;
* 已经有的 `export_presets.cfg` **不会被覆盖** —— 你在 Godot 里配的图标 /
  架构 / 打包方式都保留。

## 十三、卡住了怎么办

侧栏『游戏逻辑』→ **『出问题了? / 项目顾问』**:

* **问 AI**:写一句你卡在哪 → 点『问 AI』。它会**自己去看**你的节点图 /
  导出报告 / Godot 状态,再给下一步(回复写在文本块『GK 对话记录』里,
  点『查看对话』在文本编辑器里读);
* 它**不会擅自改你的工程** —— 要改会给你一张**待确认卡片**,你点『执行』
  才生效;
* 没配 AI 也行:点『复制诊断』,把那份快照粘到别处问同样有效;
* 想自己看:点『导出诊断信息』,得到一份纯文本,发出来就能让人看懂。

## 附:节点菜单怎么找

* **Shift+A** 或右键 →『添加游戏逻辑节点』,菜单是**两级**的
  (『运算』下面是 常量/数学/向量/逻辑/转换;『输入』下面是 键盘/鼠标/手柄/触屏);
* 记不住在哪个分类?用『搜索与常用』(/ 键也行)—— 输入名字直接搜;
* 最近用过的节点会自动进『最近使用』,不用每次翻分类;
* **一个节点能放进哪种图是定死的**:在玩法图里找不到『AI_状态』,
  因为它只属于『游戏AI』图(具体看 [节点手册.md](节点手册.md) 每条上面的
  "只能放进 …")。
