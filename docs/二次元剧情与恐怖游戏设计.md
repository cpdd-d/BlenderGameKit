# 二次元 3D 剧情 / 恐怖游戏 设计方案

> 你 2026-10-07 的规划问题:"当前项目情况是否还有未设计的?是否可以进行一个
> 二次元3D剧情,恐怖游戏设计。"
>
> 这份文档回答三件事:**①现在就能用的**(能力盘点)②**还缺什么**(差距,
> 按优先级排)③**怎么落地**(示例关卡蓝图 + 分阶段路线图)。
> 所有"现状"都标了源码位置,可复查。

## 一、结论

**可行,而且底子比想象的好。** 恐怖游戏要的"骨架"——场景 / 角色 / 状态机动画 /
第一三人称 / 敌人 AI / 对话框 / 存档 / 音频 / 惊吓表现——**大部分已经有了**
(见第二节);真正缺的是三块**氛围与叙事**能力:

| # | 缺什么 | 为什么卡住 |
|---|---|---|
| P0-1 | **灯光只导一盏太阳** | [asset_export.py:2743-2754](../BlenderGameKit/asset_export.py#L2743-L2754) 遇到第一盏 SUN 就 `break`,点光 / 聚光直接忽略;模板只有强度,没有颜色 / 阴影([asset_export.py:108-112](../BlenderGameKit/asset_export.py#L108-L112))→ **手电筒、幽暗教室、月光+台灯 做不出来** |
| P0-2 | **没有环境 / 后处理** | 场景里挂的是普通 `Node`,不是 WorldEnvironment([asset_export.py:1360-1366](../BlenderGameKit/asset_export.py#L1360-L1366));没有雾 / 泛光 / 暗角 / 环境光,背景色只能靠 `project.godot` 的 default_clear_color → **恐怖片的"空气感"没有** |
| P0-3 | **对话框没有选项分支** | 『界面_对话框』只能一路点下去([_display.py:1436](../BlenderGameKit/nodes/_display.py#L1436));要选项得手工拼『界面_按钮』+『如果_否则』→ **剧情分支成本高、容易连错** |

三块都是"加能力",不是"改架构";做完再补 P1 氛围套件(手电筒 / 听觉 AI /
BGM 切换),就能搭出完整短篇。

## 三、差距清单(要新造的)

### P0-1 灯光扩展(建议一轮)

* 现状:只取第一盏 SUN、无颜色、无阴影(见第一节)。
* 要做:
  1. **全类型灯光导出**:SUN→`DirectionalLight3D`、POINT→`OmniLight3D`、
     SPOT→`SpotLight3D`(Blender 的 `spot_size` → `spot_angle`);
  2. 每盏灯带**颜色 / 能量 / 阴影开关**(`shadow_enabled`),不再"只第一盏";
  3. **手电筒** = 聚光灯跟随相机:加一个『灯光_跟随』件(或直接给
     『相机_弹簧臂』补一个"挂载点"),开关 / 闪烁用变量 + 定时就能拼;
  4. 卡通材质的"光照跟随"现在只同步第一盏方向光(asset_export 里的
     `follow_scene_light`)→ 扩展成"**主光跟随 + 其余补光近似**",
     近似边界在文档里写明(见第七节风险)。
* 验收:`check_lights` 探针断言类型 / 颜色 / 阴影 / 多盏;示例里手电筒可开关。

### P0-2 环境与后处理(建议一轮)

* 要做:导出 **WorldEnvironment + Environment 资源**:
  背景(纯色 / 天空)、环境光、**雾**(开关 / 浓度 / 颜色)、**泛光**(glow)、
  **暗角 / 色调**;
* 入口放『游戏显示』设置图:新增一张 **『显示_环境氛围』卡**(雾 / 泛光 /
  背景色 / 环境光),与现有四张设置卡并列(写穿场景设置,不用点"应用");
* 验收:探针断言 Godot 里 Environment 各字段;两个示例(白天 / 幽暗)对比。

### P0-3 对话框选项分支(建议一轮)

* 现状:对话框无分支;手工拼按钮成本高。
* 要做:**『对话_选择』节点** —— 最多 N 个选项(选项文字 + 每个选项一个
  执行出口 + 『选了第几个』输出),样式跟对话框同族(复用 UI 层);
* 验收:UI 探针:点第 2 个选项 → 走第 2 条链 → 变量写回 → 对话继续。

### P1 恐怖氛围套件(建议和示例一起做)

* **手电筒**:电量(变量)/ 闪烁 / 点击开关(接 P0-1);
* **BGM 切换与淡入淡出**:『音效_音乐』补"音量渐变 / 总线音量"
  (现在只有启停);
* **心跳 / 紧张度**:变量驱动音量 / 滤镜(变量 + 定时已够,做成模板);
* **暗角 / 视线受限**:接 P0-2;
* **惊吓件**:镜头抖动 + 闪白 + 音效 三连(零件都有,做成"惊吓_事件"模板)。

### P1 AI 听觉(半轮)

* 现状:AI_看得见 = 距离 + 视野角,**无听觉**。
* 要做:『AI_听见』(噪声事件:跑动 / 开门 / 打翻东西时广播"在哪 / 多大
  声音"→ 半径判定)→ 『AI_转场』条件里多一项"听见"。
* 验收:demo 里"蹲走无声 / 跑动拉仇恨"。

### P2 收尾

* 『游戏音乐设置』编辑器(老待办):音量 / 循环 / 场景规则;
* UI 示例的存档槽**真接**『存档_*』节点(完善 1 的一部分)—— 真存档能力
  早就有了(见第二节),差的只是示例示范。

## 四、示例关卡蓝图:demo_horror(短篇 5~8 分钟)

**故事**:晚自习后,教学楼熄灯。二次元女高中生(玩家)在教室醒来,走廊里
"有东西"。找到 **3 张纸条**(线索)→ 打开楼梯间门 → **结局分支**:
回头救同学 / 独自逃出(两个结局变量,真存档记录)。

| 场景(一个 .blend,导出三个场景) | 内容 | 用到的能力 |
|---|---|---|
| 教室 | 月光(SUN 淡)+ 台灯(点光)、3 张可拾取纸条 | P0-1;射线拾取;对话框 |
| 走廊 | 手电筒(聚光)、雾、巡逻敌人 | P0-1 + P0-2 + AI 巡逻 / 听觉 |
| 楼梯间 | 开门演出、结局分支 | P0-3;时间轴;切关卡 / 结局 |

**流程(节点图侧)**:
开场曲线运镜(俯冲进教室)→ 旁白对话框(逐字)→ 放开鼠标(选单态,
复用第四十六轮)→ 探索(射线拾取 3 张纸条,计数 HUD)→ 拾满 → 敌人激活
(AI 图:巡逻 → 听见 → 追击;追击时 BGM 切换 + 暗角加深)→ 到门口触发
『对话_选择』→ 分支结局 → 『存档_保存』写结局标记。

**探针(check_horror_demo.py)断言**:
灯光类型(方向光 + 点光 + 聚光各 ≥1)/ 雾启用 / 手电筒跟相机 /
纸条计数到 3 / 敌人从巡逻变追击 / 选项走对分支 / 结局变量写进存档文件。

## 七、风险 / 取舍(先声明,免得期望错位)

1. **多光源卡通近似**:Blender 端 NPR 是自研的,Godot 侧"光照跟随"目前只
   同步**一盏**方向光;多灯下只保证"主光方向 + 整体亮度对得上",逐像素
   一致做不到 —— 文档与 UI 里都会写明。
2. **手电筒阴影**:SpotLight 的 shadow 影响性能;默认开,移动端可关。
3. **恐怖氛围每项都要有开关**(雾 / 泛光 / 暗角 / 滤镜)—— 免得"想做个
   明亮剧情段落却摘不掉"。
