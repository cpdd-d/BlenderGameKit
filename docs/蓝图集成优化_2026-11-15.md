# 蓝图式 Blender / Godot 集成优化（2026-11-15）

> 本文保留首轮基线。双门多实例、诊断定位、PNG/音频与多灯复核的后续实现及最新验证见[第二轮报告](蓝图多实例与资产优化_2026-11-16.md)。

本轮从文档和示例反查框架，目标是让 Blender 承担制作与逻辑编辑，Godot 承担运行、碰撞和渲染。工作区已有的 Minecraft、内容包、UV、相机等未提交开发保持原样；本报告只记录本轮新增工作，历史测试数量不作为当前结果。

## 文档核查与架构取舍

核查入口：README、蓝图化总清单、待办清单、2026-11-08 优化总结、Blender与Godot互通、导出管线、资源包与数据包缺口报告、Minecraft M2a 测量报告，以及 demo_game、demo_horror、demo_assets 的说明和生成器。

已有能力包括角色 / 关卡图、函数、信号、状态机、动画树、UI 设计图、资源卡、glTF 导出、物理代理与可选 C++ 热路径。归档规划中的“缺失”不能直接当成当前待办。继续沿用现有编译器和原生 Godot 节点，避免引入第二套运行时解释器。

| 蓝图概念 | 本项目职责与边界 |
|---|---|
| Actor / Pawn | Blender 对象绑定角色图；Godot CharacterBody 与模型子树承载移动、碰撞和表现 |
| Level Blueprint | 场景绑定关卡图；负责交互规则、目标与通关状态 |
| Function / Event | 函数封装可复用流程，事件启动执行链；数据连线只传值 |
| Widget | 独立 UI 设计图负责控件构建；玩法事件在状态改变时更新 HUD |
| Animation / Sound Asset | Blender Action 和声音卡是制作端来源；导出后使用 AnimationPlayer 与独立播放实例 |
| Compile Results | 编译返回结构化 Diagnostic；报告保留节点定位和修复建议 |
| Cook / Runtime | glTF + GDScript + 场景装配；文本资源按内容增量写入，原子替换保障单文件完整性 |

## 整合后的优化清单

优先级以“会导致行为失效 → 可复用性 → 规模和观感”排序。完成项与候选项明确分开。

| 范围 | 从示例 / 代码得到的证据 | 本轮落实 | 后续验收项 |
|---|---|---|---|
| 节点图 | 恐怖示例 HUD 曾只接文字、未接执行；视觉上连好但无运行行为 | 新增执行流可达性诊断；覆盖断开的整段链、转接点、函数和回调 | 执行引脚级路径分析、跨图引用导航、运行时断点与节点追踪 |
| 编译反馈 | 报告先登记文本再添加条目，导致无 hint 的诊断丢失；同文案不同节点被合并 | 先保留结构化诊断，按级别/代码/节点去重，再折叠字符串副本 | 用图的稳定标识补足跨图同名节点定位 |
| 游戏逻辑 | 多章交互与提示易复制，规则和移动混杂后不易迁移 | 新示例分角色图 / 关卡图；交互反馈收进函数，一次性触发 | 将完整关卡规则抽成组件接口与可配置数据；状态存档版本化 |
| 游戏界面 | HUD 与状态变化脱节，逐帧重建控件成本高 | 新示例独立 UI 设计图；状态变化才更新 HUD | 键盘/手柄焦点、不同宽高比、字体大小与暂停返回路径验收 |
| 游戏渲染 | Minecraft M2a 已减少 draw calls，但单段首建 p99 仍未到 4ms | 保留既有渲染架构；新示例使用明确灯光、材质分区和实机画面检查 | 分段网格继续细分构建任务，固定场景/相机测 p99；多灯 NPR 与预览一致性专项 |
| 游戏音效 | 缓存的 AudioStream 被直接改循环标志，会影响同素材其他播放；旧淡出可误停重播 BGM | 播放实例隔离循环设置；一次性音效显式关循环；BGM 管理淡入/淡出生命周期 | 声部预算/优先级、空间衰减与音量主观试听 |
| 游戏动画 | Blender Action 到 Godot 动画播放器的整条路径比只检查脚本更有价值 | 新示例用 Blender 原生门动画，并在 Godot 验证实际变换 | 骨骼根运动、动画通知、受击/死亡中断及 AnimationTree 参数契约 |
| 游戏资产 | 相同材质/着色器/脚本每次重写，触发不必要文件变化 | 内容相同不写；变更仍原子替换；未变化文件继续纳入导出清单 | GLB/贴图依赖哈希、内容包依赖/版本、丢失资源汇总 |
| 验证流程 | 单测通过不能证明场景可玩；旧示例存在大量人工经验补丁 | 新增可重建的集成示例、行为探针与门禁入口 | 用相同契约逐步覆盖现有大型示例，不把所有长测塞入每次开发 |

## 从示例反向提炼的规则

1. **交互不是轮询表现。** 每帧只检查输入和必要条件；确认状态改变后才执行函数，触发 HUD、动画和声音。一次性奖励应在等待动画之前锁定状态，避免重复按键重入。
2. **数据线不启动执行。** 新诊断检查从事件 / 函数入口是否结构可达；不推断条件恒真恒假，也不声称覆盖运行时的每个分支。未使用的备用逻辑移出当前导出图。
3. **资源定义和播放状态分离。** 同一素材可以同时用于循环背景和一次性提示；缓存源资源不能携带某个播放实例的循环状态。
4. **生成物归属和实际写入次数分离。** 未变化文件仍属于本次导出，避免后续清理误删；没有内容变化就不触发磁盘替换。
5. **验证观察结果。** 角色是否移动、交互是否只执行一次、门是否位移、HUD 是否变化、播放节点是否释放，都应在 Godot 中断言，不能仅靠搜索生成代码字符串。

## 实现入口

- `BlenderGameKit/codegen/graph_audit.py`：执行流结构诊断，接入正常代码生成和项目诊断；按生成器规则识别有效函数入口。
- `BlenderGameKit/export_report.py`：诊断去重与节点信息保留。
- `BlenderGameKit/codegen/services.py`：音频资源实例与 BGM 淡变生命周期。
- `BlenderGameKit/exporter.py`、`asset_export.py`：脚本、场景、环境脚本、材质、着色器按内容写入。
- `examples/demo_blueprint_lab/`：新增集成示例；生成器和检查器分别为 `scripts/make_blueprint_lab.py`、`scripts/check_blueprint_lab.py`。

新示例用独立目录保留旧示例，既能复用其交互经验，又避免重建覆盖正在编辑的 Minecraft / 恐怖工程。它是架构验证用的小关卡，不代表已有大型游戏内容完成重制。
