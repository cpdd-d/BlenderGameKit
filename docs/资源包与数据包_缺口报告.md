# 资源包 / 数据包：现状缺口报告

调研对象：`BlenderGameKit` 本体（导出器 + 代码生成 + 生成物管理）与
`examples/demo_minecraft/我的世界_godot` 这个已导出的运行时工程。
调研时间：2026-11-10。

结论先行：**当前插件对“外部资源覆盖”和“数据驱动内容”都是零支持**。
资源引用在生成代码和 `.tres` 里被写死，数据（方块/物品/配方）全部硬编码在
示例脚本里，导出流程没有任何包发现、清单、启用或运行时切换的概念。
好的一面是，现有代码里已经有一套成熟的 autoload 注册模式（主界面 / 玩家偏好 /
跨关卡角色）和生成物清理约定，可以直接复用，不需要新发明基础设施。

---

## 一、真实缺口

### A. 资源覆盖（shader / 材质 / 贴图）

| # | 现状 | 缺口类型 | 具体表现 |
|---|---|---|---|
| A1 | `asset_export.py` 每次导出都会重写 `art/` 贴图、`materials/*.tres`、`shaders/*.gdshader` | 硬缺失 | 用户放在项目里的同名资源会被导出覆盖；没有“后置覆盖”入口 |
| A2 | 生成脚本里的资源引用是散落的 `load("res://...")`（示例 `script_eb4b380d.gd:92`、`script_745843fd.gd:157`） | 硬缺失 | 没有集中资源解析层，无法通过替换路径 / 虚拟文件系统拦截 |
| A3 | 材质 `.tres` 用 `ext_resource` 直接引用贴图与 shader | 硬缺失 | 想换贴图只能改材质资源本体或重新导入，不能运行时换 |
| A4 | 打包（`packaging.py`）只把导出模板和资源嵌进 `.pck` | 硬缺失 | 没有使用 `ProjectSettings.load_resource_pack`，也没有 `.zip/.pck` 热加载 |
| A5 | 没有 `resourcepacks/`（或类似）目录约定、`pack.json` 清单、启用状态 | 只差一层约定 | 目录、清单格式、优先级、切换 API 都还没有 |
| A6 | 覆盖必须可逆：示例里同一份材质被大量方块共享（`script_eb4b380d.gd` 的 `_materials` 字典） | 设计约束 | 直接改共享材质会同时影响所有实例；切换/关闭包时必须能恢复原资源 |
| A7 | 源工程与导出工程对贴图的处理不同（`.png` vs `.import` + `.ctex`） | 设计约束 | 包内贴图不能依赖 Godot 导入缓存，必须直接从包字节解码成 `ImageTexture` |
| A8 | 生成物清理只认 `scripts/ scenes/ art/ materials/ shaders/ curves/ audio/` | 设计约束 | 用户包目录不能被当成插件生成物清理；运行时脚本必须带“由 BlenderGameKit 自动生成”头才能被认领 |

### B. 数据驱动内容（方块 / 物品 / 配方）

| # | 现状 | 缺口类型 | 具体表现 |
|---|---|---|---|
| B1 | 方块名、贴图、硬度写死在示例脚本（`script_745843fd.gd` 的 `NAMES/TEXTURES`、`script_eb4b380d.gd` 的地形方块表） | 硬缺失 | 增删一个方块必须改 GDScript |
| B2 | 没有 JSON schema、注册表、加载顺序、冲突覆盖规则 | 硬缺失 | 没有“数据包”概念 |
| B3 | 没有把数据内容落到场景的通用消费者 | 硬缺失 | 即使读进注册表，也没有任何节点会使用它 |
| B4 | 没有 `datapacks/` 目录与包清单约定 | 只差一层约定 | 目录、清单、打包格式都没有 |
| B5 | `export_report.py` / `project/metadata.py` 用 JSON 只是插件内部状态 | 可复用 | 说明 JSON 读写本身没有障碍，缺的是运行时契约 |

### C. 可复用的现有基础设施（只差接线）

- **autoload 注册**：`asset_export.ensure_main_ui_autoload`（6278 行）、
  `ensure_player_prefs_autoload`（6460 行）、`persistent_player._autoload`
  （219 行）已经解决了“写脚本 + 改 `project.godot` + 取消时摘注册”这套流程。
- **生成物认领**：`generated_files.is_generated_file` 用脚本头
  `由 BlenderGameKit 自动生成` 判断归属，新增运行时脚本天然可被清理链管理。
- **导出收口**：`asset_export.export_all_scenes`（12046 行）在所有场景导完后
  统一处理主界面 / 玩家偏好 / 输入映射 / 旧文件清理，是安装包运行时的正确位置。
- **无头验证**：`tests/blender_script_references.py` 已示范如何用
  `Godot --headless --script res://runner.gd` 在临时工程里跑运行时断言。

## 二、最小实现范围（本次）

### 资源包

- 目录约定：
  - `res://resourcepacks/<包名>/pack.json`（目录包）
  - `res://resourcepacks/<包名>.zip`（压缩包）
  - `user://resourcepacks/...` 同构，优先级更高（后扫到的同 id 覆盖先扫到的）
- `pack.json`：
  ```json
  {
    "id": "classic",
    "name": "经典材质",
    "overrides": {
      "res://art/mc_grass.png": "overrides/mc_grass.png",
      "res://shaders/gk_toon.gdshader": "overrides/gk_toon.gdshader"
    }
  }
  ```
- 运行时 `GkPacks` autoload：
  - 发现目录包 / zip 包；
  - `activate(id)` / `deactivate()` / `cycle()` 运行时切换；
  - 遍历当前场景，替换材质 `albedo_texture`、`ShaderMaterial.shader`、
    `ShaderMaterial` 的 `shader_parameter/*` 贴图参数、以及
    `Sprite2D/TextureRect/TextureButton` 的贴图；
  - 记录并恢复原资源，切换包或关闭时不留痕迹；
  - 贴图从包字节直接解码（PNG/JPG），绕开 Godot 导入缓存。
- 只覆盖贴图与 shader；`.tres` 整体替换、音频、字体不在最小版本内（见下）。

### 数据包

- 目录约定：`res://datapacks/<包名>/pack.json` 或 `<包名>.zip`；
  `user://datapacks/...` 同构。
- `pack.json` 至少支持 `blocks`，另带 `world_blocks` 让内容真正落到场景：
  ```json
  {
    "id": "ruby",
    "name": "红宝石扩展",
    "blocks": [
      {"id": "ruby_block", "name": "红宝石块",
       "texture": "textures/ruby.png", "color": [0.8, 0.1, 0.2], "hardness": 3.0}
    ],
    "world_blocks": [
      {"block": "ruby_block", "scene": "World", "position": [0, 1, 0]}
    ]
  }
  ```
- 运行时 `GkContent` autoload：
  - 解析所有数据包，按 id 合并方块定义，暴露
    `get_block(id)` / `has_block(id)` / `block_ids()` / `get_recipe(id)`；
  - `world_blocks` 在进入匹配场景时自动生成方块网格 + 静态碰撞体，
    **不改任何 GDScript** 即可看到数据包内容；
  - `reload()` 支持切换场景/重读数据包。
- 配方只做“读入并可按 id 查询”，不实现合成逻辑（最小版本）。

### 导出侧

- 新增 `BlenderGameKit/packs.py`：包发现与校验、运行时脚本模板、
  autoload 安装 / 卸载；无包时不写文件、不改 `project.godot`，
  保证“没有包时产物不变”的既有约定。
- `export_all_scenes` 收口处调用一次（排在主界面 / 玩家偏好之后、旧文件清理之前）。

## 三、明确不在最小版本内的能力

1. `.pck` / 加密包；只支持普通目录与 `.zip`。
2. 材质 `.tres`、场景 `.tscn`、音频、字体的整体覆盖。
3. 资源包依赖、版本约束、加载顺序声明。
4. 数据包里的物品 / 掉落表 / 合成逻辑 / 配方 UI。
5. 编辑器 UI（在 Blender 侧勾选包）；本次只做目录约定 + 导出时自动安装。
6. 包的启用状态持久化；当前由运行时 API 控制。

这些都可以在现有结构上继续加，不需要推翻本次实现。
