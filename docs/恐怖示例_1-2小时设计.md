# 恐怖示例 · 1–2 小时完整版设计

> 基于 2026-10-25 的一次完整实机游玩（标题 → 教室 → 走廊失败/重试 →
> 楼梯间 → 结局 → 回标题 → 二周目）整理。当前示例的实机问题与修复见
> [`examples/demo_horror/README.md`](../examples/demo_horror/README.md)；
> 关键截图与自动游玩日志留档在 `.audit/horror_play_20261025/`。
>
> 这份文档回答三件事：
> **① 现在这个示例离"1–2 小时"还差什么；② 下一版具体做成什么样；
> ③ 按什么顺序做、怎么验收。**

---

## 一、先定规模：不要直接做 2 小时

当前示例是一条 **5–8 分钟** 的短篇。直接把它拉成 2 小时，最容易变成
"走廊加长、纸条变多、怪物变快"——时长上去了，体验反而更空。

建议的目标是：

| 项 | 目标 |
|---|---|
| 一周目主流程 | **60–90 分钟** |
| 含可选笔记 / 隐藏房间 | **90–110 分钟** |
| 章节数 | **5 章 + 标题 + 结局** |
| 结局 | 2 个（普通 / 真结局），可选第 3 个 |
| 战斗 | **无**（逃跑、躲藏、机关、解谜） |
| 单章时长 | 12–20 分钟 |
| 失败惩罚 | 回**最近安全屋**，不重开整章 |

**不做什么**（第一版明确砍掉）：

- 不做战斗、Boss 血条、武器；
- 不做配音、多语言、成就、云存档、联网；
- 不做开放世界；整栋教学楼是**同一套几何反复用不同状态**；
- 不做复杂过场动画；用运镜 + 字幕 + 音效讲完。

## 二、设计支柱

1. **声音是资源**：跑步、开门、按 K 敲击都会把怪物引过来；
   蹲走和绕路是玩家的"潜行预算"。
2. **光也是资源**：手电筒照亮路，也让怪物更容易发现你；
   电池有限，开关手电是一个持续选择。
3. **失败只回安全屋**：被抓 → 黑屏 → 回最近安全屋，保留已拿到的
   关键道具和笔记；不惩罚玩家重走 10 分钟。
4. **同一栋楼，五个状态**：教室 / 走廊 / 音乐教室 / 医务室 / 楼梯间
   都复用教学楼语汇；换的是灯光、雾、道具、怪物行为和声音。
5. **线索驱动**：每章至少 2 条可读文本，解释"为什么这层楼变成这样"；
   集齐全部笔记解锁真结局线索。

## 三、章节与时长

| 章 | Blender 场景 | 目标 | 主要内容 | 新机制 | 时长 |
|---|---|---|---|---|---|
| 0 | 标题 | 新游戏 / 继续 / 设置 / 退出 | 菜单、读档、清档 | 设置菜单 | 2–3 min |
| 1 | 教室 | 找到 3 张纸条，离开教室 | 教学：移动 / 手电 / 蹲 / 噪音；第一张纸条；怪物第一次路过 | 交互提示、纸条日志、蹲走 | 12–15 min |
| 2 | 走廊 | 找到 3 个保险丝，恢复走廊灯，拿到音乐教室钥匙 | 巡逻怪、听觉、保险丝盒、第一次追逐 | 保险丝解谜、安全屋存盘、失败回检查点 | 15–20 min |
| 3 | 音乐教室 | 用录音机放出一段声音，引开怪物，拿到磁带 | 录音机顺序谜题、钢琴房、磁带、上锁的门 | 声音诱饵、顺序输入 UI | 15–20 min |
| 4 | 医务室 | 拿到校工钥匙，读懂病历 | 黑暗迷宫、病床帘、病历、惊吓演出 | 躲藏点、手电电池、可选笔记 | 15–20 min |
| 5 | 楼梯间 / 天台 | 最终追逐 + 结局选择 | 断电、追逐、两选一、真结局条件 | 追逐段、结局分支、制作名单 | 12–18 min |
| 合计 | 7 张 `.tscn` | — | — | — | **71–96 min** |

> 可选内容（约 15 分钟）：每层的隐藏笔记、音乐教室的旧磁带、
> 医务室的病历页。集齐后第 5 章多一个"回头救人"的真结局选项。

## 四、核心循环

```
进章 → 安全屋（存档 / 目标 / 补给）
   ↓
探索（手电 / 蹲走 / 听声辨位）
   ↓
找关键道具（钥匙 / 保险丝 / 磁带 / 病历）
   ↓
解一个环境谜（保险丝盒 / 录音机 / 密码门）
   ↓
怪物压力（巡逻 → 听见 → 查看 → 追逐）
   ↓
出口 / 安全屋 → 下一章
```

**每 3–5 分钟**要有一次"信息或压力"的变化：
一条新笔记、一盏灯灭、怪物换巡逻路线、一个门打开、一次远处的声音。
不要连续 5 分钟只有走路。

## 五、系统设计

### 5.1 玩家（角色图，所有章节共用一张）

角色图只放"人"：

- 输入：WASD / 空格 / 鼠标 / Shift 跑 / Ctrl 蹲 / F 手电 / E 交互 / K 敲击；
- 移动：走 / 跑 / 蹲的速度与相机高度；跑动自动发噪音；
- 视角：侧视 / 俯瞰 / 第一人称（可选）/ 弹簧臂；
- 手电：开关、电量、低电闪烁（灯对象由关卡图提供，角色图只改状态）；
- 对外端口：位置、在地面、蹲下、跑动、手电开、电量。

> 跨章节复用的关键：**机位名统一**（侧视机位 / 俯瞰机位），
> 同一个相机物体链接进所有章节。不要每关各建一台。

### 5.2 关卡图（每章一张，挂场景根）

每章关卡图固定分五个分组框：

| 分组 | 放什么 |
|---|---|
| ① 开局 / 环境 | BGM、暗角、雾、开场运镜、章节卡、玩家出生点 |
| ② HUD / 目标 | 当前目标、纸条计数、电量、交互提示、字幕 |
| ③ 交互 / 道具 | 拾取、读笔记、开门、保险丝盒、录音机、密码门 |
| ④ 敌人 / 威胁 | AI 启用、追逐音乐、心跳、惊吓区、失败判定 |
| ⑤ 出口 / 存档 | 安全屋存盘、检查点、切章、结局 |

**通用系统用 Python 生成器函数复用**（和当前 `_hud_count` 一样），
不要在每个关卡图里手连一遍：

```
build_common_hud(logic, prefix, objective, show_notes, show_battery)
build_common_safe_room(logic, marker, save_slot)
build_common_fail(logic, spawn_marker, chapter_id)
build_common_interact_prompt(logic)
build_common_chapter_card(logic, title, subtitle)
```

这样"HUD 长什么样""失败回哪"只有一份逻辑，章节图只放本章内容。

### 5.3 敌人（AI 图，按行为分 2–3 张）

| AI 图 | 用途 | 状态 |
|---|---|---|
| `巡逻怪` | 走廊 / 医务室常驻 | 巡逻 → 听见 → 去查看 → 追击 → 丢失 → 搜索 → 回巡逻 |
| `追逐怪` | 第 5 章最终追逐 | 潜伏 → 追逐 → 冲刺 → 被门挡住 → 重置 |
| `影子`（可选） | 剧情演出 | 只出现 / 消失，不做寻路 |

每张 AI 图对外输出：

- `is_chasing`（紧张度、追逐音乐、失败判定）
- `is_investigating`（换氛围音）
- `alert_level`（0/1/2，给 HUD 或灯光）

**关键规则**：

- 怪物在追逐时的停距要**大于**"抓取判定距离"（当前 `CHASE_STOP=1.6`
  < `CATCH=1.9`，所以它会主动贴上来被抓）；如果要"贴脸才失败"，
  两值要留出 0.2–0.4 米。
- 失败判定用"距离 + 是否在追击 + 是否躲藏"三条件，避免隔着墙被抓。

### 5.4 失败、检查点、安全屋

**不做"整章重开"**。数据分层：

- 关键道具 / 笔记 / 章节进度：**跨失败保留**（存 `progress` 槽）。
- 本章临时状态（怪物位置、门开没开）：失败后重置。
- 玩家位置：回到本章**最近安全屋的出生标记**。

实现方式（现有节点即可）：

1. 安全屋放一个空物体 `安全屋_走廊_出生点`；
2. 交互存盘时把 `checkpoint` 写进存档（`存档_写入` + `存档_保存`）；
3. 进章 `每当_准备`：`存档_载入` → `存档_读取到变量` 读 `checkpoint`
   → 用 `取值_获取节点` 找到对应出生点 → `对象_设置位置` 放玩家；
4. 被抓：黑屏 → `实例_重载场景`（或切回本章场景）→ 上面的出生点逻辑生效。

> 当前示例的失败是"重载本关"；正式版要加 `checkpoint` 变量，
> 否则每次失败都回章节开头。

### 5.5 物品、线索、日志

存档 schema（JSON，和现有 `save1` 兼容）：

```json
{
  "chapter": 2,
  "checkpoint": "走廊_安全屋",
  "items": {"保险丝": 3, "音乐教室钥匙": 1, "手电电池": 2},
  "notes": ["note_101", "note_102", "note_205"],
  "flags": {"走廊灯修好": true, "录音机谜题": false},
  "ending": 0,
  "play_time": 2831.5
}
```

- 关键道具用 `列表_*` / `字典_*` 节点维护；UI 用 `界面_列表`。
- 笔记 = `id + 标题 + 正文`；日志面板用 `界面_列表` + `界面_文本`
  或 `界面_对话框` 的回顾模式。
- 每章开头显示 `目标：...`；目标文本从关卡图的变量来，不写死在 UI 里。

### 5.6 交互

统一一条"交互"链，而不是每件道具各写一套：

1. 玩家面前的 `射线_检测` / `取值_距离` 找到可交互物体；
2. `界面_文本` 显示 `[E] 读纸条` / `[E] 开门`；
3. 按 E → 当前目标类型的分支（拾取 / 阅读 / 开门 / 存档 / 谜题）。

> 当前示例用"踩进 Area3D"拾取；正式版建议改成**射线 + E**，
> 避免玩家在门口反复进退触发，也更像恐怖游戏。

### 5.7 谜题

| 谜题 | 玩法 | 现有节点 |
|---|---|---|
| 保险丝盒 | 找到 3 个保险丝，靠近按 E 逐个安装；装齐恢复走廊灯，但灯亮会吸引怪物 | 变量 / 比较 / 分支 / 灯光_设置 |
| 录音机 | 从笔记里得到 4 个音的次序，按 1–4 播放；正确后播放磁带、开门 | 界面_按钮 / 对话_选择 / 变量 |
| 密码门 | 三张笔记各给一位数字，输入 4 位密码；错误两次触发警报 | 界面_输入框 / 界面_按钮 / 比较 |
| 电闸 | 限时拉 3 个电闸（每个都在怪物巡逻路线上） | 定时 / 触发区 / 变量 |

### 5.8 UI

用一张共享的 `GKUiDesignTree`「恐怖游戏界面」，每章用
`界面_套用设计` 建出来；章节图只改变量和显隐：

- HUD：目标、纸条计数、电量、交互提示、字幕；
- 日志：已收集笔记列表 + 正文；
- 背包：关键道具（钥匙 / 保险丝 / 电池）；
- 暂停：继续 / 设置 / 保存 / 回标题；
- 设置：主音量 / 音乐 / 音效 / 鼠标灵敏度 / 反转 Y / 全屏；
- 章节卡：黑底 + 章节名 + 一行副标题（`界面_字幕` 或 `界面_文本`）。

**层级约定**（避免互相盖）：

| 层 | 内容 |
|---|---|
| 10 | HUD / 字幕 |
| 12 | 日志 / 背包 |
| 14 | 暂停 / 设置 |
| 16 | 章节卡 / 结局 |
| 20 | 黑屏转场 |

### 5.9 音频与灯光

- 总线：`Master` / `Music` / `SFX` / `Voice`（在 Godot 音频面板建；
  或在 `project.create_project` 里生成 `default_bus_layout.tres`）。
- 每章一套 BGM；追逐时切 `chase` 曲；紧张度驱动心跳；
- 灯光：教室暖色台灯、走廊冷白应急灯、音乐教室舞台灯、医务室闪烁灯、
  楼梯间单灯；每盏灯都能被『灯光_设置』开关；
- 断电 / 闪灯 / 手电低电闪烁是主要的"吓人"手段，不需要 jump scare 堆砌。

## 七、为了 1–2 小时，插件还缺什么

按优先级：

| 优先级 | 缺口 | 建议做法 |
|---|---|---|
| P0 | **音频总线布局** | `project.create_project` 生成 `default_bus_layout.tres`（Music / SFX / Voice），或文档写明手动建 |
| P0 | **检查点 / 出生标记** | 现有存档 + 空物体 + `对象_设置位置` 可做；做一个 `build_common_safe_room` 模板并写进示例 |
| P0 | **交互提示模板** | 现有射线/距离 + `界面_文本` 可做；抽成公共函数，避免每件道具重复 |
| P1 | **角色控制开关**（躲柜子 / 过场锁操作） | 现有 `显示_暂停节点` + `相机_切换` 可做"躲藏"；若要更干净，可加"输入_启用/禁用"节点 |
| P1 | **背包/日志 UI 模板** | 用现有 `界面_列表` + `界面_面板` 做；先做成一张 UI 设计图，别每个场景手画 |
| P1 | **章节卡 / 制作名单** | 现有文本/字幕节点足够；补一个标准模板 |
| P2 | **本地化 / 成就 / 云存档** | 不在 1–2 小时第一版范围；等玩法定型再做 |
| P2 | **动画系统资产** | 现有动画状态机够用；需要角色/怪物动画资产（Mixamo/MMD/自制） |

> 结论：**不需要新的大系统**。1–2 小时版本主要缺的是
> **内容生产、模板复用、检查点/日志/交互/UI 的工程化**，
> 而不是更多节点。

## 八、实施阶段（建议按纵切片推进）

### M0：20–30 分钟纵切片（第 1+2 章）

目标：先把"完整游戏骨架"跑通，再扩章节。

- 教室 + 走廊两章；
- 手电 / 蹲走 / K 噪音 / 保险丝盒 / 巡逻怪 / 安全屋 / 检查点 /
  失败重试 / 目标 HUD / 纸条日志；
- 章节卡、暂停、设置（音量/灵敏度/反转 Y）；
- 一条自动游玩探针：标题 → 教室 → 走廊 → 失败 → 重试 →
  安全屋 → 第 2 章出口。

**验收**：人工 20–30 分钟通关；自动探针全绿；无死局；失败回安全屋
不超过 5 秒。

### M1：第 3–4 章

- 音乐教室录音机谜题、磁带、密码门；
- 医务室躲藏点、手电电池、病历；
- 共享 UI 设计图接入日志/背包；
- 两条新 AI 行为（搜索 / 追逐音乐）。

**验收**：4 章连续通关 45–60 分钟；所有关键道具/门有锁-钥匙闭环；
每章至少 2 条笔记可读。

### M2：第 5 章 + 结局

- 楼梯间断电追逐、天台结局选择；
- 普通结局 / 真结局（集齐笔记）；
- 制作名单、回标题、二周目。

**验收**：主流程 60–90 分钟；两个结局都能到达；真结局条件可验证。

### M3：美术 / 音频 / 打磨

- 模块化教学楼替换占位方块；角色/怪物动画；
- 每章灯光/雾/音乐定稿；
- 性能：同屏怪物 ≤ 1、灯光阴影数量、纹理尺寸；
- 打包 Windows 可执行文件；写 README/控制说明。

## 九、自动验收（沿用现有门禁思路）

新增探针（每个一章 + 一条全流程）：

1. `check_horror_full_ch1.py`：教室纸条、手电、蹲走、第一张日志；
2. `check_horror_full_ch2.py`：保险丝盒、巡逻怪、听觉、安全屋存盘、
   失败回检查点；

### 本轮新踩的三个坑（都写进了代码注释）

1. **改速度别写同名变量**：角色预设速度是检查器参数 `@export move_speed`，图里用『变量_设置』写同名变量会被导出侧改名（`move_speed_param`），而移动代码读改名后那个 → **蹲跑静默失效、不报错**。正解是接到『移动_按方向』的速度引脚。
2. **相邻两个 Area3D 的离开事件会抹掉新目标**：`body_exited` / `body_entered` 落在**同一物理帧**且顺序不确定。规则改成「离开时，交互目标还是我才清」。
3. **`Input.is_key_pressed()` 按 keycode 匹配，自动化测不到**：蹲走脚本原本用 `Input.is_key_pressed(KEY_CTRL)`，而探针注入的是 `physical_keycode`（keycode=0）→ 真人键盘能蹲、探针量到 0。凡是「玩家能感知」的输入一律走**动作**（`Input.is_action_pressed("key_left_ctrl")`），真键盘 / 手柄 / 合成事件才一致。

## 十六、第 3 章「音乐教室」设计卡（M1a，2026-10-25）

> 用法：这一节是**规格书**。实现者照它做，验收照它验；第 4 章（医务室）照同样的格式写。

### 16.1 一句话

**「把心里的那首曲子按对，才能让怪物替你走开。」** 一间隔音的音乐教室：谱子被撕成三张，
录音机要按对四个音才会响，而响了会把它引过来——**声音既是钥匙，也是诱饵**。

### 16.2 流程与流程改动

```
标题 → 教室 → 走廊 → 【音乐教室】→ 楼梯间(结局) → 回标题 → 二周目
```

| 改动 | 原来 | 现在 |
|---|---|---|
| 走廊出口 | `去楼梯间` → 楼梯间 | **`去音乐教室` → 音乐教室** |
| 音乐教室出口 | — | `去楼梯间` → 楼梯间 |
| 楼梯间 | 「载入存档读回纸条数」 | **一行都不用改** |

### 16.3 玩法循环

```
进关(安全屋存档) → 找 3 张乐谱(E 读) → 凑出 4 音顺序 → 录音机按 1/2/3/4
        ↑                                        ↓
   被抓回安全屋(保留乐谱数)          对 → 放音 → 声音诱饵把怪物引到『舞台』
                                         ↓
                              上台取『磁带』 → 侧门(去楼梯间)放行
```

| 元素 | 规则 |
|---|---|
| 乐谱 | 3 张，各给一个音位；**集不齐也能试**（但只能靠猜，错两次就惊动怪物） |
| 录音机 | 靠近 E 打开，按 `1/2/3/4` 输入四音；`录音机错次` 每次错 +1 |
| 错 2 次 | **警报**：灯闪 + 噪音 + 字幕，怪物进本关查看（压力，不是必死） |
| 正确 | `录音机放音=true` → 在 `舞台` 位置发噪音 → 怪物被引走 → 舞台可上 |
| 磁带 | 只在诱饵生效后能取；拿到后侧门解锁 |
| 失败 | 被抓 → 冻世界 →『回到安全屋』→ 回本关入口，**保留乐谱数与磁带** |

### 16.4 时长预算（做的时候拿它当尺子）

| 段 | 目标 |
|---|---|
| 进关 + 摸清房间 | 2–3 min |
| 找 3 张乐谱 | 4–6 min |
| 试音（含错一次被吓） | 3–5 min |
| 诱饵 + 取磁带 + 出门 | 3–4 min |
| **合计** | **12–18 min** |

低于 10 分钟说明房间太小/线索太直白；高于 20 分钟说明在拖路。

### 16.5 验收断言（写死在门禁与探针里，不靠「看着差不多」）

| 层 | 断言 |
|---|---|
| 场景层 | `音乐教室.tscn` 存在；`乐谱1/2/3`、`录音机`、`磁带`、`舞台`、`安全屋区域`、`去楼梯间` 都在 |
| 代码层 | `game_logic_音乐教室.gd` 里有 `乐谱数` / `录音机输入` / `录音机错次` / `录音机放音` 的读写 |
| 行为层 | 读 3 张 → `乐谱数=3`；错顺序 → `录音机错次+1` 且画面有变化；正确顺序 → `录音机放音=true`；取磁带 → `磁带=1`；侧门 → 场景变 `楼梯间` |
| 失败层 | 被抓 → 回本关安全屋，**`乐谱数` 不丢** |
| 兼容层 | 旧档（没有磁带键）读进来当「没有磁带」，不崩 |

### 16.8 三个本轮踩出来的坑（别在别的章节复现）

1. **`逻辑_比较` 的 A/B 是文本框**：纯数字串会被转成数字字面量，`gk_b="3142"` 生成的是 `录音机输入 == 3142`（String 比 int，**恒假且不报错**）。要字符串比较必须自己带引号。已固化一条门禁断言盯着它。
2. **改物体名必须同时改 `write_physics(triggers=...)`**：漏了那一处，出口板会被导成 `StaticBody3D`（看得见的实体墙，Area3D 事件永不触发），而重建与门禁当时**都是绿的** —— 只有「它是 StaticBody3D 不是 Area3D」这一条能抓到。
3. **一层一只怪是本示例的约定**：走廊的怪不会跟到隔音教室；每关自己一只怪 + 自己一张 AI 图，关卡图开局就要『AI_启用』（别等"错满两次才出现"）。

## 十八、场景美术怎么借 `demo_story`（恐怖闯关示例）

> 用户 2026-10-25：「示例里还有一个恐怖闯关示例，可以根据它的游戏设计来进行场景等等的设计」。
> `examples/demo_story` 是**剧情**示例（大堂 / 走廊 / 结局），它的灯光与环境是被实机截图逐轮调过的，
> `scripts/make_story_demo.py` 里每个数值旁边都写着「为什么是这个数」。**直接搬，别自己重调。**

### 18.1 可复用的函数（同仓库、同插件，抄结构即可）

| 函数 | 位置 | 作用 |
|---|---|---|
| `make_wall_pieces` | `make_story_demo.py:464` | 墙分段 ＋ **踢脚线 ＋ 腰线**（墙和地面才"接得上"，否则像悬空） |

### 18.2 环境参数（`ENV_CORRIDOR`，`make_story_demo.py:1058` 起）

| 参数 | 值 | 为什么 |
|---|---|---|
| 环境光颜色 / 能量 | `(0.40,0.49,0.88)` / **0.30** | 环境光只负责"暗部还有冷紫色相"，明暗交给灯去画。环境光压过灯时画面是一层平蓝（实测关掉 7 盏壁灯整帧**一个像素都不变**） |
| 雾颜色 / 密度 | `(0.12,0.15,0.29)` / **0.0042** | 雾是"远处发白"，不是"整屏牛奶" |
| 雾亮度 `fog_light_energy` | **0.34** | 原样铺过去等于加一层牛奶（实测均值 0.2551 → 0.3547） |
| `fog_sky_affect` | **0** | 别让雾盖掉背景色 |
| 高度雾 高度 / 密度 | **0.5 m** / **0.12** | 雾贴地最浓、到天花板基本干净 = 纵向层次 |
| 体积雾 | **关** | 低浓度下有 froxel ＋ 时域重投影的"同心圆 / 流光"伪影，灯越多越明显 |

### 18.3 灯具的三条硬约束（都是踩出来的）

1. 吊灯主光用 **70° 聚光**：点光会把 1.5 米外的天花板照到过曝；118° 的锥边会在 8.4 米宽的走廊两面墙上切硬斜线。
2. 壁灯**离墙 ≥1.1 米**：贴墙 0.4 米时墙面照度约 18 倍，是白团 ＋ 大泛光。
3. 灯罩 / 灯泡：`render_no_shadow = True`（灯罩投在天花板上的环会被软阴影切成同心圆）；灯罩用**深色金属色**，灯泡挪到罩下 **≥0.3 米**（浅色罩贴点光会爆白团）；上照能量 **≤0.12 倍**。

### 18.4 不要借的三样（`demo_story` 也踩过）

- **体积雾**：示例里关着，要用就 ≥0.02；
- **长焦相机**：Blender 50mm 会被写成 Godot `fov=22.9°`，第三人称直接怼脸；
- **"显示值"直接写进线性属性**：会再被导出一层 sRGB，雾色变 0.51 中灰 —— `demo_story` 为此加了 `_display_color()`。

### 18.5 剧情层可以借的

`demo_story` 的『对话_选择』比 `demo_horror` 现在的「按 1 / 2」更能承载二次元的演出（选项带文本、可以分支）。
真要上剧情，**先解决对白数据化**（`docs/待办清单.md` 的 P0-1：一句对白 = 一个节点，5 分钟剧情 ≈ 80–150 个节点，改台词等于在图上找节点）。

## 十九、第 5 章落地记录（M2a，2026-10-28）

> 和第十二节一样：**已经做完的**，不是计划。验收：门禁 `CHECK_HORROR_DEMO=OK`
> ＋ 真窗口试玩 `PLAY_SUMMARY fail=0 shots=28` ＋ 人工看 `21_stairs` / `21b_blackout` / `22_choice` / `23_ending`。

### 19.1 一句话

**「灯灭的那一刻它开始上楼 —— 你要在天台门之前跑到顶。」**

这是全篇**唯一一段不能停的跑动**:前四章都可以蹲、可以躲、可以等,这一章只考
"断电之后你还剩多少胆量"。

### 19.2 流程

```
医务室侧门 → 楼梯间门厅(安全屋) → 6 秒后断电 → 追兵启动
     → 一层 → 二层(目标"还有 2 层")→ 三层(还有 1 层)→ 天台门
     → 天台:三选项 → 结局 1 / 2 / 3
```

| 段 | 目标时长 | 实际（自动试玩） |
|---|---|---|
| 门厅 → 断电 | 8 秒 | 7.2 秒（含读档/日志初始化） |
| 断电 → 天台门 | 25–40 秒 | 不适用（探针直接传送到天台） |
| 天台决策 | 10 秒 | 1 秒（按 2） |

### 19.3 为什么这么设计（拿前四章当对照）

| 维度 | 前四章 | 第 5 章 | 为什么改 |
|---|---|---|---|
| 怪的速度 | 4.08 m/s（CHASE_SPEED×0.85 < 走路 6.0） | **6.0 m/s**（= 走路速度） | 前几章怪是"压力",这一章它要**真的追得上**,否则跑不跑都一样 |
| 玩家对策 | 蹲 / 躲 / 慢慢摸 | **只能跑** | 一章换一个核心动词,玩家才不会腻 |
| 光源 | 手电 + 环境灯 | **断电**:3 盏应急灯一起灭,只剩门口红点 + 月光 | "光被拿走"比"光变暗"更恐怖,而且不用改手电逻辑(这一关不带手电) |
| 失败处理 | 回安全屋、保留进度 | **没有安全屋可用**(被抓就是被抓) | 楼梯间没有能关门的地方 —— 这一关的代价是"从头再跑" |
| 结局 | 门口两选一 | **天台三选一**,第 3 个要档案齐 | 真结局第一次有了**前置条件**,不再是纯选项 |

### 19.4 技术要点（三处非显然的实现）

1. **楼梯是斜坡不是台阶**：`CharacterBody3D` 在 Godot 4 里没有自动台阶攀爬，
   0.6 米一级的台阶必须跳着上（旧版楼梯间就是这样）。所以坡道是**绕 X 转 25° 的盒子**，
   踏面是贴在坡上的 `decor` 薄板（无碰撞）—— 看着是楼梯，走起来是坡。
2. **追兵只在断电那一刻 `AI_启用`**：AI 图的起始状态就是「追击」，如果跟其他关一样
   开局就启用，玩家一进门就会被追。断电链里放 `AI_启用` 一句，正好把
   "灯灭 = 它来了"这条叙事落到代码上。
3. **真结局判的是加法**：`纸条数 + 病历数 >= 6`。用『数学』的 ADD + 一个『比较』，
   省掉一个布尔节点；`存档_读取到变量` **没有值输出**（只往脚本变量里写），
   所以要先挂『变量_读取』才拿得到值（踩过一次 `KeyError: 值`）。

### 19.5 这一轮的三条教训

1. **"面板上看得见"≠"连着"**：`选项3 → 档案判断` 漏了一条线，选择框上第三个选项
   明明在、按下去什么都不发生 —— 生成的 `match` 里连第 3 个 `case` 都没有。
   门禁现在两侧都断（`options=3` **和** `ended=3.0`）。
2. **`--quit-after` 的单位是帧**：无头 Godot 一帧 2ms，`900` 帧 ≈ 2 秒游戏时间。
   第 5 章要等 6 秒断电 → 探针"跑到一半就没了"。给到 24000 帧。
3. **灯不要贴着表面"照亮"**：60W 贴在门楣上 0.3 米，平方反比把它照成一块发光板，
   第三人称相机被门口挡住时整屏洋红（`22_choice` 连踩三次）。灯离表面 ≥2 米，
   或者干脆用**小面积自发光**当指示。
