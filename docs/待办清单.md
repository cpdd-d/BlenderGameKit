## 零之前的之五:UPBGE 式整合 ✅(2026-10-03 第五轮)

用户第五轮(贴 UPBGE 截图):"①相机与动画的节点都可以整合成类似 upbge 一样;
②输入这里,这两个都可以整合到一起的,比如输入按键时有 x,y 的属性输出,
这样就可以调节向前向量和向右向量……这应该是自带的,不应该要再设置变量;
③弹簧臂的逻辑是**在场景中建模一条直线或是不规则曲线**,……设置为某一摄像机的
父级,这样弹簧臂发生缩放、变短变长时,摄像机改变其位置;④第一人称摄像机发生
旋转时,可以设计角色一部分模型跟随旋转吗"

| 要的 | 做出来的 |
|---|---|
| ① 动画/相机像 UPBGE 那样整合 | 『动画』分两级:**播放**(11 个) + **骨骼**(3 个,照 UPBGE 的 Get/Set Bone Data);『相机』补齐 11 个(新增 相机_路径) |
| ② 输入整合 + 自带 x/y | 新节点 **『输入_方向』**:四个键**各点各的『按一下键』捕获**,直接输出 方向 / 左右 / 前后 / 有输入;接『移动_按方向』就能走,**不用设变量**。旧的『输入_轴』『输入_方向向量』收进隐藏(功能保留) |
| ③ 曲线运镜 | 新节点 **『相机_路径』**:在 Blender 里画一条**曲线**,点『选曲线』挑它 —— 导出时把曲线**采样成点列**写进脚本,相机沿它移动(『位置』0~1 或『速度』自动前进),朝向可选"看前方/看某节点/不改"。glTF 不支持曲线,所以是导出时采样 |
| ④ 模型跟着视角转 | 新节点 **『骨骼_跟随视角』**:每物理帧让指定骨头(头/上半身)跟着相机偏,带**权重**(只跟一部分才像活人)、**限角**(脖子不能拧 180°)、平滑。配套『骨骼_取数据』『骨骼_设置』 |

第五轮抓到四个坑(**全是"离线测试全绿、真 Godot 才炸"**):

- ✅ **`matrix_world` 是求值后的属性** —— 曲线挪到 (1,2,0) 采到的点还在原点,
  相机走的是"没挪动过的那条轨道"。采样前要 `view_layer.update()`
- ✅ **`deg_to_rad()` 只收 float** —— `Quaternion.from_euler(deg_to_rad(Vector3))`
  解析期就报;向量要乘 `PI / 180.0`
- ✅ **`Vector2` 没有 `.z`** —— 『输入_方向』给二维向量、『移动_按方向』在 3D 里
  取 `.z`,整个脚本编译不过。3D 项目现在直接输出 `Vector3(x, 0, y)`
- ✅ **夹"斜着走"要夹分量** —— 只在向量上 limit_length,被夹的值根本没进 3D 输出,
  斜着走还是快 41%

**解析清单又扩了**:第 4 层现在解析 **7 个**生成脚本(状态机 / 输入鼠标 / 弹簧臂 /
曲线运镜 / 骨骼 / 输入方向 / 示例工程)。

## 零之前的之四:摄像机套件 + 按键捕获返修 ✅(2026-10-03 第四轮)

用户第四轮原话:"1,『输入_按键按住(旧)』……不需要显示;2,进行摄像机的设计:
摄像机的设置,切换,启用与禁用,视距,视野,分支的场景摄像机的设置,切换,
启用与禁用,弹簧臂的设计,摄像机的旋转,缩放,位置等向量,浮点,两变量的设计,
同样是按照虚幻蓝图进行。3 完成摄像机后进行之前的逻辑检验。4,如图所属输入
按键部分未正常工作"

| 要的 | 做出来的 |
|---|---|
| 旧输入节点不用显示 | 保持隐藏(功能仍在,老图照旧能加载导出) |
| 摄像机的**设置** | 新节点 **『相机_设置』**:一次设好 视野 + 视距(带平滑) |
| **启用与禁用** | 新节点 **『相机_启用』**:启用 = `make_current()`;禁用 = **只有它正开着才** `clear_current()`(否则把别人的画面弄黑) |
| **视距 / 视野** | 视距 = 沿相机朝向推远多少(用 `global_transform.basis.z`,父节点有旋转也对);视野 3D 改 `fov`、2D 改 `zoom`,按**相机真实类型**分派 |
| **弹簧臂** | 新节点 **『相机_弹簧臂』** —— 完整照虚幻的 SpringArm:臂长 / 高度偏移 / 侧向偏移 / 俯仰 / 偏航偏移 / 碰撞检测 / 碰撞半径 / 位置平滑 / 旋转平滑。每物理帧打射线,撞到就把杆子缩短 |
| **旋转 / 位置(向量 + 浮点)** | 新节点 **『相机_位置』『相机_旋转』**:两种给法 —— **向量**引脚,或 X/Y/Z(偏航/俯仰/翻滚)**浮点**;『保留』= 相对加、『直接设』= 绝对;旋转还带"限制俯仰 ±89°" |
| **分支的场景摄像机设置** | 每台相机各放一套『相机_设置』『相机_启用』,用『如果_否则』按条件挑一支(示例里就是这么演示的) |
| 读相机状态 | 新节点 **『相机_取状态』**:名字 / 位置 / 朝向 / 视野 / 开着吗 |
| **按键捕获未正常工作** | 真 bug,已修:见下 |

第四轮抓到的两个坑(**都是"离线测试全绿、真 Godot 才炸"那一类**):

- ✅ **Blender 里没有 `KEYDOWN` 这个事件类型** —— "按一下键就绑定"第一版写的是
  `event.type == "KEYDOWN"`,于是**按字母键毫无反应**,模态一直挂着
  (你截图里状态栏那句"按一下你要绑的键"不消失,就是这个)。
  正确判断是 `event.value == "PRESS"`,键名在 `event.type` 里。
  现在抽成 `key_from_event()`,冒烟测试直接喂 8 种假事件验证;
  另外捕获成功后主动 `tag_redraw()`,节点上那个框会**立刻**显示新键
- ✅ **`gd_number(8.0)` 后面又拼了个 `.0`** → 生成出 `clampf(8.0.0 * delta, ...)`,
  Godot 报 `Cannot use a decimal point twice in a number`,**整个脚本加载失败**。
  只在"弹簧臂平滑 > 0"时才出现,是**示例工程**那一层逼出来的

**验证面又加了一层**:第 5b 层把弹簧臂单独包一个最小 Godot 工程真跑 ——
杆子 5 米、身后 2 米一堵墙,断言相机停在 **1.20 米**(墙面 1.5 − 半径 0.3),
读到的要是 5.0 就说明碰撞检测没生效(会穿墙)。

## 零之前的之三:蓝图化卡片 + 开始·结束口 ✅(2026-10-03 第三轮)

用户第三轮(对着 UPBGE 的截图)原话:"①在设置变量属性时,卡片里可以设置多个
并且引脚可连接不同节点,如虚幻蓝图的变量节点可重复连接;②在判断属性时,
可由设置变量节点拉出连接,如虚幻蓝图设置变量后就直接连接判断节点;③在输入
按键时,按下键盘任意键即可设置哪个键盘控制输入等,如 upbge 的 keyboard key
设计逻辑;④优化这两个编辑器的右键排布,如 upbge 的输入里分类键盘、鼠标、
手柄;⑤游戏动画节点图中应有一个开始口和结束口……然后可以输出这一个游戏动画
的布尔情况,以便于在游戏逻辑里判断执行下一步逻辑;⑥游戏动画开始时的条件可
自定义,如发生什么,一个变量,一个动画结束,或者是自定义开始动画条件"

| 要的 | 做出来的 |
|---|---|
| ① 一张卡片设多个变量、引脚接不同节点 | 『变量_设置』加『数量』(1~6):值 / 值 2 / 值 3 …,每个引脚可接**不同**节点。第 1 个仍是老名字老引脚 —— 老图接好的线一个字不用改 |
| ② 设完变量直接接判断 | 『完成』执行流本来就能扇出到多个判断节点;现在配套把**类型推断**修对了(值接了线就从上游引脚种类推断,不再一律 Variant),否则会冒出"同时被当成 bool 和 Variant"的假告警 |
| ③ 按一下键就绑定(UPBGE Keyboard Key) | 新节点 **『输入_按键』**:『触发方式』= 按住 / 刚按下 / 松开(一个顶三个)+ **『按一下键』按钮**(模态算子抓 `KEYDOWN`)。捕获到的键导出时翻成 Godot keycode 写进 `project.godot`,**在 Blender 里按 C,Godot 里 C 就真的能用**(已验证 `physical_keycode":67`) |
| ④ 右键菜单分类(UPBGE 排布) | 『输入』下面分 **键盘 / 鼠标 / 手柄 / 触屏**(手柄、触屏从顶层收进来);**鼠标节点是新补的**:按键按住·按下、滚轮、位置、移动量、鼠标模式 |
| ⑤ 开始口 / 结束口 + 布尔输出 | 新节点 **『动画_开始』**(显式起点)和 **『动画_结束』**(收工)。走到结束口 → `_gk_anim_done = true`,玩法图用 **『动画_运行状态』** 读 `已结束 / 在跑 / 当前状态`,接着做下一步逻辑 |
| ⑥ 开始条件可自定义 | 『动画_开始』的『开始方式』:立刻 / **变量为真** / **刚按下某键** / 按住某键 / **上一个动画播完** / **自己写(接条件引脚)**。条件不成立时整张图不动;走到结束口后条件再次成立会重新开始 |

第三轮的坑(都写进 README 踩坑清单了):

- ✅ **多槽节点的引脚名算错**:第 2 槽去找不存在的『值 3』→ 永远读不到连线、
  悄悄退回数字框的值(示例生成出 `combo_ready = 1.0`,应该是 `true`)
- ✅ **布尔变量被填了数字** → `is_hurt = 0.0` 让整个脚本加载失败。现在转成
  `false/true` 并提示"该接『常量_布尔』"(以前只会说"请改用不同的变量名",
  用户会去改一个没问题的地方)
- ✅ **`bl_icon = "CURSOR_ARROW"` 不是合法图标** → 整个鼠标_位置节点注册失败
  (菜单里没有、老图里变未知节点)
- ✅ **Blender 算子不能直接 new** → 模态算子里的逻辑抽成
  `apply_captured_key()` 才测得到
- ✅ **同一个函数名被生成两份体** → `_input(event)` 回调表只记
  `(函数名, 是否清零)`、函数体写死成触屏那几行,鼠标滚轮复用后
  `_gk_mouse_wheel_event` 出现两份,Godot 报
  `Function ... has the same name as a previously declared function`
  **拒绝整个脚本**(是 `--check-only` 抓到的,离线测试全绿也发现不了)。
  现在函数体跟着登记一起带过去
- ✅ 示例里 `attack` 状态没接进来的边 → 解析器如实报"孤立状态"(测试写漏了)

**新增的验证面**:第 4 层现在解析**三个**脚本(状态机 / 输入鼠标 / 示例工程);
第 5 层的真跑探针会在 0.6 秒手动进"攻击",验证 **0.6 秒后走到结束口** ——

## 零之前的之二:条件动画 + 时间轴 / 相机 ✅(2026-10-03 第二轮)

用户第二轮的原话:"**设置上一个已经播放完成,设置布尔变量**,然后下面判断
是否输入、在地面且移动、新变量是否为真假,然后**就播放一个或多个动画**。
然后我想加入**时间轴**的功能实现如**摄像机视野变化**,**不同摄像机丝滑切换**
动画……还有**场景动画,不同动画的整体联动**"

| 要的 | 做出来的 |
|---|---|
| "上一个已经播放完成" | **『动画_播放完成』节点**(两张树都能用)。能和『逻辑_布尔运算』拼成"(播完了)**并且**(在地面)";玩法图里也能做"播完就清标志"。标志**粘住**到下一段动画开播(清的理由见下),所以复合条件等得到 |
| "设置布尔变量" | 状态节点新增『进入时』『离开时』两条**执行流**(照 UE5 的 State Entry/Exit)—— 『动画_设变量』**真的会被执行**了。用户之前是把状态的『转到』接到设变量上(那条线是"去下一个状态"),现在节点的报错会直接告诉他改用这两个出口 |
| "播放一个或多个动画" | 状态节点新增『同时播 2 / 3』:一个状态**同时播多段动画**。Godot 的 `play()` 一次只播一段,所以自动开"层播放器"(MMD 的骨骼动作 + 形态键动作就是这么一起播的);切走时自动停掉多播的层 |
| "摄像机视野变化" | 『定时_缓动属性』:目标 = 相机、属性 = `fov`、时长 = 1.2 秒,平滑推近。默认 0 秒 = 立刻变(**老图生成结果一字不变**) |
| "不同摄像机丝滑切换" | 『相机_切换』新增『过渡(秒)』。做法:让**新**相机先站到旧相机的位姿上再插值回自己 —— 两台相机都不用被挪走,来回切也不跑位。每帧推进挂在 `_physics_process`(和角色同一个时钟,不然画面会抖) |
| "场景动画 / 整体联动" | 『定时_缓动属性』能缓动**任意节点的任意属性**(`position:y` 开门、`modulate:a` 淡出、`light_energy` 变暗…)。用的是 Godot 的 Tween —— **异步**:调用完立刻返回,所以几条缓动 / 几段动画串在一起就是**同时**跑的,不需要额外的"时间轴编辑器" |

第二轮真跑出来的 bug(**都是"语法对、跑起来才炸"那一类**):

- ✅ **`_ready` 里"起始状态播一下"整行消失** —— `new_section()` 会把写入目标
  换成新段而且**不还回来**,状态钩子一生成,后面的语句全跑进那个函数里了。
  统一改成 `ctx.capture()` 上下文管理器
- ✅ **相机过渡的"目标相机"用了局部变量** → Godot
  `Identifier "_cam_to2" not declared in the current scope`;
  改成成员变量后又因为语句里多写了一个 `var` 而**遮蔽**它,过渡静默失效。
  跨函数引用一律 `declare_var` 且不写 `var`
- ✅ 信号连接从"表达式求值处"挪回 `_ready`(不然"每帧检查播完了没"会把
  `is_connected` 判断塞进 `_physics_process`)
- ✅ 验证加了一层**真 Godot 跑 1.5 秒**:`_dist/anim_probe` 最小工程,
