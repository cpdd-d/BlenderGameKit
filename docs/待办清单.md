## 零之前的之三十:移动平台 + 可驾驶载具 ✅(2026-10-05 第三十轮)

你选的"移动平台 / 载具",并且定了:平台**用现成的『定时_时间轴』**动,
载具这一轮做到**可驾驶(上/下车)**。物理测试场从 7 个工位扩到 **9 个**。

### ① 站上去被带走:平台必须是 AnimatableBody

Godot 里的讲究:被脚本/时间轴**每帧挪位置**的平台,只有做成
**AnimatableBody** 才会把速度传给站在上面的角色(CharacterBody 会跟着走);
StaticBody 是"瞬移",角色留在原地 —— 表现就是"平台从脚下溜走"。
所以『游戏物理』→ 物理类型加了两个新选项:
**3D 动画平台 AnimatableBody3D / 2D 动画平台 AnimatableBody2D**。

工位⑧就是这件事的现场:平台(4×4×0.4)由**时间轴 PINGPONG** 从
x=47 推到 51(和示例里"抬门"同一套路:轨道值 → 『移动_设置位置』的 X,
Y/Z 用平台当前坐标),角色站上去不按键,探针断言
**`carried ≈ plat_span`**(实测 `plat_span=3.99` / `carried=3.49`)。

### ② 可驾驶载具:三个新节点

| 节点 | 干什么 |
|---|---|
| **『载具_上车』** | 隐藏角色(可选)/关角色碰撞 / 摆到**座位**上;离车太远(『上车距离』)上不去 |
| **『载具_下车』** | 摆到**下车位置**(车本地空间的一个点)/恢复显示与碰撞 |
| **『载具_驾驶』**(挂物理帧) | 有人开时:W/S 沿**车头**前进后退、A/D 转车头;并**每帧把角色钉回座位** + 输出『驾驶中』(接分支用) |

几个设计决定:

* **状态放在载具自己身上**(`set_meta("gk_driving")`),不生成成员变量 ——
  同一辆车的三个节点自动一份,场景里摆两辆车也互不串;
* **每帧钉座位**是"镜头/距离判定/触发区跟着车走"的关键 —— 它们认的是
  角色节点,角色在座位上,整套就都跟着车;
* 载具做成 **CharacterBody**(和角色同款,撞墙会停、能走坡);
  要"在车上再站人"就用 AnimatableBody(那是平台);
* 载具/平台的网格都按**资产**导出(各自的 glb + `Model` 子节点)——
  碰撞体一挪,网格跟着挪。

### 探针抓出来的两个真 bug(都记档)

**① "否"分支每帧都在跑 → 刚下车就被塞回座位。**
这轮第一版接法是"E 且 驾驶中 → 如果_否则"(是=下车/否=上车)。
问题是那个『否』口**没按 E 的帧也会走**(条件假)→ 下一帧立刻又"上车"。
探针里 `ride_gap` 恒 0、怎么按都下不了车。修:**两层分支** ——
先判"按了 E 吗"(外层),再判"在开吗"(内层),否口只在按 E 的那一帧走。

**② `rotation.y` 是弧度,『转向速度』填的是度/秒。**
生成的是 `rotation.y -= dir.x * 120.0 * delta` —— 把 120°/秒 当成
120 弧度/秒,实测**每帧转 1.4 弧度**(肉眼就是疯狂打转)。修:
`deg_to_rad(...)`;探针的 `steer` 从 2.53 回到 **0.59**(= 0.4 秒 × 0.707
× 120°/秒,和手算一致)。

## 零之前的之二十九:上台阶 —— 角色能自己迈上矮台阶 ✅(2026-10-05 第二十九轮)

你选的方向。背景:Godot 的运动学角色(CharacterBody)**不会自动上台阶** ——
0.35 米的台阶在它眼里就是一堵墙(第二十八轮探针实测:三级台阶一级都上不去)。
这一轮给『移动_按方向』加了**『上台阶高度』**:默认 0 = 关闭(老图产物
一字不变);填个数(比如 0.5)就能迈上半米以下的台阶,比它高的仍然挡住。

### 怎么做的:四关探测(Godot 官方那套经典做法)

被挡住 + 站在地面上时,依次探(**全是 `test_move` 探测,不是"用力挤"** ——
挤出来的姿势会穿模/抖动),全过了才 `global_position` 平移过去:

1. **被竖着的东西挡住**(台阶前脸 / 墙)。坡面不算 —— 法线的竖直分量 ≥ 0.5
   当它是地面/斜坡,不然上坡会一蹦一蹦;
2. **抬到『上台阶高度』的那条斜路是通的**(台阶比它高就在这关撞上 ->
   原地不动 = 仍然挡住);
3. **抬起来之后还得走得动**(在这个高度再往前探一步 —— 就是这一关挡住
   了"假台阶",见下);
4. **落点有地,而且至少比现在高 5 厘米**(往下探 `高度 − 0.05`),而且落在
   **平面**上(法线朝上)。

往前迈的那一小步固定 0.35 米(半个身位):够把脚踩到台阶面上,又不至于
一步跨过窄台面。

### 探针抓出来的两个"假台阶"(都记档)

**① 顶着高台阶原地一蹦一蹦。** 胶囊碰撞体的下端是**尖的** —— 抬起来之后
那个尖能从 1.05 米高台阶的前脸旁边擦过去,于是"落点"探到的其实还是
**同一层**(站在 0.35 的低台阶上、顶着高台阶,却每次都能"抬腿成功" →
抬 0.5 掉 0.5)。探针里 `max_y=1.75`(比设计峰值多 0.5)抓出来的,
插桩逐帧轨迹定位到第二次抬腿发生在 `z=-1.15`。

**② 蹭到顶角也算"地"。** 修①时顺手给落点加了法线检查(得是平面),
结果发现蹭到台阶顶角时法线是 (0.8, 0.6) —— 也算"朝上",检查不出来。
最后按经典算法补上**第 3 关(抬起来还得走得动)**:假台阶在那一关就被挡 ——
`max_y` 从 1.75 回到 1.40。

### 台阶工位改成"两段断言"

低台阶 **0.35**(在 0.5 以内)→ 该**迈上去**;高台阶 **1.05**(差 0.7)→
该**仍然挡住**。实测:

    PHYS_stairs ok=true climb=0.50 max_y=1.40 min_z=-1.59 end_z=-1.59

(= 抬腿瞬间峰值 1.40;停在 z=-1.59 = 高台阶前脸 -2.1 + 角色半径 0.5)

### 验证

门禁:**563 离线单测**(+3:默认 0 老图不变 / 填 0.5 生成四关 / 2D 走 Vector2)+
构建 + 干净重装 + 冒烟 **128/128**(+3:默认不生成 / 填 0.5 生成 / 无告警)+
**五个** Godot 端到端(2D / 平台跳跃 / 曲线示例 / 小游戏示例 / 物理测试场)。

> 踩坑记档:GDScript **不支持 `a <= b <= c` 链式比较**(会按 `(a<=b)<=c`
> 解析,报 `Invalid operands "bool" and "float"`);写判据要拆成两个比较。

## 零之前的之二十八:物理加固 —— 七个工位的物理测试场 ✅(2026-10-05 第二十八轮)

你选的方向("碰撞/物理加固一轮")。做法:**专门建一个物理测试场**
(`examples/demo_physics`,七个工位排成一排),再写一个探针在 **Godot 里
驱动角色一个个走一遍** —— 有穿模 / 卡住 / 推不动就抓出来。

### 七个工位(探针全绿的数字)

| 工位 | 期望 | 实测 |
|---|---|---|
| **斜坡**(20°)| 爬上去 | `climb=2.05`(走到坡顶 y=2.95)✓ |
| **台阶**(0.35/0.7/1.05 三级)| **挡住**、不穿模、不骑上去 | 停在 `z=-0.02`(台阶前脸 0.5 + 角色半径 0.5)✓ |
| **对角方块**(转 45° 的角 + 另一个方块**斜对角重叠**)| 停在**角**外面 | 到中心 `min_dist=1.92`(= 角 1.41 + 半径 0.5)✓ |
| **推箱子**(RigidBody)| 推得动、不陷进去 | `moved=7.22` 米 ✓ |
| **多碰撞体**(头/身/腿三块)| 三块都在摆的位置 | 射线 0.4/1.6/2.45 命中、缝里 0.95 **漏掉** ✓ |
| **窄缝**(1.6 米宽)| 穿得过去 | 走到 `z=-9.60`(穿过去了)✓ |
| **薄墙**(0.25 米厚)| 全速撞不穿透 | 停在 `z=-2.36` ✓ |

### 挖出的两个真 bug(都在"看得见的 ≠ 判定的"这条线上)

**① 静态物体的碰撞代理丢旋转。** 导出时非角色物体只写位置、基**写死单位阵**
—— 于是"网格是斜的、碰撞是正的":20° 斜坡的碰撞体是一块**平砖**(角色
卡在坡脚)、45° 方块的碰撞体是**轴对齐盒子**(斜对角多出一圈)。
修:基改走 `_emitter_basis_text`(和粒子/相机同一套换轴换算)。

**② 碰撞形状用的是世界 AABB。** `object_bounds()` 一直返回**世界空间**包围盒,
而形状应该是"挂在物体**局部**坐标系的盒子、朝向由节点 transform 带":
转过 45° 的方块拿到 2.83 而不是 2 的形状(斜对角多出 0.8 米),
20° 斜坡拿到一块 2.7 米高的竖板。

> ⚠ 这两个 bug **必须一起修**才看得出效果:只修① → 形状是"旋转过的大 AABB",
> 挡得比模型还宽;只修② → 形状对了但没旋转。修完探针实测:
> 斜坡爬得上去、斜方块停在角外 1.92(球碰撞时只有 1.5)。

顺带(同一族):凸包点集以前乘了世界矩阵 —— 现在点集用**局部**坐标
(否则转过角度的物体凸包**转两次**);线框预览也跟着一起转(预览=导出还在);
尺寸诊断改用局部包围盒(不然把 45° 方块误报成"碰撞体比网格小")。

### 顺手补的一个"物理常识缺口":『推开刚体』

Godot 的 CharacterBody 是**运动学体**:撞到刚体只会贴着滑走、**不给它力** ——
推箱子推不动,用户会以为碰撞体没做对。『移动_按方向』新增勾选
**『推开刚体』**(默认关):`move_and_slide()` 之后遍历碰撞,对撞到的
RigidBody 施加 `推力 × 帧时长 × 质量` 的冲量(= 持续施加『推力』牛顿),
方向取碰撞法线的**水平**反向。**角色预设默认勾上** —— 新预设开箱即用,
老 .blend 里的节点不受影响。

### 探针(第 5 个端到端)

`scripts/check_physics_demo.py`:把角色依次传送到七个工位前,按住 W
往世界 -Z 走(测试场里把预设的『随相机朝向』关掉 —— 弹簧臂有跟随平滑,
传送过去时方向是斜的,实测偏航 -28°~-74°),边走边采样位置 + 射线。

`apply_central_impulse`)。

> ② 台阶/薄墙的判据要按"前脸 + 角色半径"算,不能凭感觉写死 z。

## 零之前的之二十七:"先放完再重复"一键化 ✅(2026-10-05 第二十七轮)

你最早那句原话是:

> "有个小问题,就是在**重复触发**时,它会重复开始动画,如果我想让它
> **先放完再重复**,这个设计了吧(节点图看着有点复杂)"

第二十五轮给的『流程_冷却』是"隔一段时间才放行一次"——能挡住重复触发,
但它按**秒**算,不知道动画放完没有。这一轮把"按动画本身"那条路做成一键。

### ① 『动画_播放』:『重复触发时』(原来藏在"混合模式"里)

| 选项 | 键(不变) | 生成出来是什么 |
|---|---|---|
| **从头重播**(默认) | `REPLACE` | 每次触发都 `play(name, …)` —— 老行为一个字不变 |
| **先放完再说(在播就跳过)** | `CONTINUE` | `if 播放器.current_animation != 名字 or not 播放器.is_playing():` 里面才 `play` |

* 这个能力**本来就存在**(以前叫『续播(同名不打断)』),但埋在一个叫
  "混合模式"的下拉里 —— 你完全看不出来它就是"先放完再重复"。现在:
  下拉的标题叫**『重复触发时』**,节点文档里正面写清楚它的用途;
* **只改了显示名**:选项的键还是 `REPLACE` / `CONTINUE`,老 `.blend`
  里的值原样对得上(单测 + 冒烟各钉一条);
* "想隔固定时间才放一次"(不是按动画长度)仍然用『流程_冷却』,文档里指了路。

### ② 修一个"一填就断链"的 bug:『动画播放器』填物体名

`animation_player()` 以前对"填了物体名"的情况**直接把那个物体当播放器用**:

    @onready var anim_敌1: Node = _gk_ref_typed(self, "敌1", "Node")
    var _ap := anim_敌1
    if _ap.has_animation(...)          # ← 运行时:Area3D 没有这个方法

glTF 把 AnimationPlayer 放在**模型实例内部**,用户能选到的只有场景物体
(碰撞代理 / 网格)。所以那句话运行时必炸
(`Invalid call. Nonexistent function 'has_animation' in base 'Area3D'`),
而且**整条链就此断掉**(后面的节点全不执行)—— 以前只验证过"留空 = 自动查找"
那条路,所以一直没暴露。**现在从那个物体开始查**(先它的子树,再退回全树)。

### ③ 示例里第一次有"真动画":敌1 的受击抖动

小游戏示例里**一个动画都没有**,所以"重复触发动画"这件事根本没有现场。
这一轮给敌1 用 Blender 的 Action 打了一条 **0.83 秒的"被拍扁再弹回来"**
(scale 5 个关键帧)→ 导出时进 `World.glb` → Godot 导入后模型实例内部
长出 `AnimationPlayer`。按 **E** 就播它。

> 这条链顺带把"**对象动作 → glb → Godot AnimationPlayer**"整条路第一次
> 验证了(以前只有角色/骨骼那条路)。

### ④ 探针(第 4 个端到端)新增的断言

重开之后单独测这一段(前一条时间线已经排满):

* `DEMO_ANIM_START player=true list=["敌1抖动"]` —— 播放器找得到、动画名对得上;
* **连按 E 约 23 次**(1.0~1.4 秒之间每帧一下,而动画有 0.83 秒)→
  `plays_during_spam=1`:只开播了**一次**,当前这一轮没被打断
  (从头重播的话会是 20 多次);
* 等它放完(1.83 秒)之后**再按一下** → `total_plays=2`:放完了能接着重复;
* `DEMO_ANIM ok=true`(三个数一起判);
* 生成物层面:`_gk_find_animation_player(节点_敌1)`(填物体名的那条路)、
  `current_animation != _anim`(在播就跳过);**反向**断言:
  不能再出现 `var _ap := 节点_敌1` 那种"把物体当播放器"的写法;
* `World.glb` 里真的有 `敌1抖动`(直接读 glb 的 JSON chunk 断言)。

## 零之前的之二十六:常用件再补一批(到达·加速 / 夹范围 / 每N次 / 闪红 / 飘字)✅(2026-10-05 第二十六轮)

你选的方向是"**再补一批常用件**"。这一批全是"小游戏示例里差点就要手拼"的东西:
3 处老节点加强 + 2 个新节点,**不新建分类**(特效 / 界面都是已有分类,
冒烟里"分类子菜单/节点数量"那批断言一个字没改)。

### 五处改动

| 改了什么 | 加了什么 | 生成出来是什么 |
|---|---|---|
| **移动_朝向目标** | 『到达』**输出** + 『加速』属性 | 到达:`((位置(目标) - 位置(自己)).length() <= 停在多远)`;加速:`velocity.move_toward(期望速度, 加速 * get_physics_process_delta_time())` |
| **变量_增减** | 『限制范围』+『最小』『最大』 | `血量 = clampf((血量 + -1.0), 0.0, 3.0)`;int 变量自动包成 `int(clampf(...))` |
| **流程_冷却** | 『每几次放行一次』(默认 1) | 只有 >1 才生成计数器:`_gk_cd_count += 1`,条件里加 `and _gk_cd_count % N == 0` |
| **特效_闪红**(新) | 执行 / 秒 → 完成 | `_gk_flash_3d(目标, Color(...), 秒)`:整棵 MeshInstance3D 盖上 unshaded 材质,时间到自动还原 |
| **界面_飘字**(新) | 执行 / 数值 → 完成 | `_gk_float_text_3d(目标, "+" + _gk_num_text(1.0), …, 0.8, 1.2)`:头顶冒 Label3D,上飘 + 淡出 + 自删 |

### 几个设计决定(都是"踩过才知道")

* **老图产物一个字不变**:『限制范围』不勾 = 生成的和以前逐字一样;
  『每几次放行一次』= 1 时不生成计数器行;『加速』= 0 时还是直接赋值。
  第二十五轮那批探针/冒烟断言(比如 `_gk_cd_ticks` 那行)今天原样通过。
* **『到达』必须是自包含表达式**:输出可以在图里任何地方被读,读的时候语句里
  那几个临时变量(`_to_goal` / `_goal_dist`)**不在作用域** —— 所以它用位置
  helper 重新算一遍(和语句里 `distance <= stop` 同款算法)。两处共用一份
  `_move_toward_goal`(引脚优先 / 属性兜底),免得以后改规则只改到一处。
* **闪红借 `material_override` 这一层**:卡通材质是**逐个表面**挂的
  (`set_surface_override_material`),整网格的 `material_override` 空着 ——
  设上 = 盖住所有槽,恢复原值 = 卡通材质原样回来。恢复前先比对"现在盖的是不是
  我们那个材质":连着闪两次时(受击 + 追击同时打中),先到期的那个**不会**把
  后一次的红提前抹掉。2D 没有材质覆写这一层,用 `modulate`(同样记原色 + 比对恢复)。
* **闪红 / 飘字走模块级 helper**(和 `_gk_num_text` 一样只生成一次):图里 5 枚
  金币各一个飘字节点,内联就是 5 份同样的十几行。
* **飘字挂在 `current_scene` 上**:金币这类锚点自己会被 `queue_free`,
  挂在锚点下面的话字会跟着一起消失(飘不出来)。
* **守卫用 `is_instance_valid` 而不是 `!= null`**:@onready 引用在锚点被销毁后
  还指着已释放的实例,`!= null` 拦不住(第二十四轮碰撞代理同步踩过同一个坑)。

### 小游戏示例用上它们(126 → 133 节点 / 138 → 146 连线)

## 零之前的之二十五:做游戏常用件(追人 / 加减 / 冷却 / 数字文字)✅(2026-10-05 第二十五轮)

上一轮的小游戏示例把"做游戏常用件"的缺口暴露出来了:

> 用户原话:"1. 有个小问题,就是在**重复触发**时,它会重复开始动画,
> 如果我想让它先放完再重复…… 2. 碰撞体系统的打磨吧,在与正方体模型对角上重叠会穿模。"

对角穿模那条**第二十四轮前的碰撞打磨已经修了**(正方体按圆度判成盒子,
不再给球 —— 冒烟里钉着)。这一轮补另外那类:**做游戏天天要用、但节点图里
得拼四五个节点才能凑出来的东西**。四个新节点,全部塞进**已有分类**
(移动 / 变量 / 流程 / 运算),不新建分类 —— 冒烟里"分类子菜单/节点数量"
那一批断言一个字都不用改。

### 四个新节点

| 节点 | 引脚 | 生成出来是什么 | 为什么需要 |
|---|---|---|---|
| **移动_朝向目标** | 执行 / 目标 / 速度 → 完成 | `方向 = (目标位置 - 自己位置).normalized()` → `velocity = 方向 * 速度` → `move_and_slide()`;离得比『停在多远』近就 `velocity = ZERO` | 追人 / 跟随 / 自动靠近。原来要"取值_位置 ×2 + 数学_运算 + 移动_按方向"四五个节点拼,而且中间那个"归一化"十个人里九个会漏 |
| **变量_增减** | 执行 / 增减 → 完成 + **新值** | `金币数 = int((金币数 + 1.0))` | 计数 / 扣血。原来"变量_读取 + 数学_运算 + 变量_设置"三个节点。『新值』输出 = **加完之后**的值(直接拿去比较/显示,不用再读一次变量);int 变量的 `int(...)` 兜底、setter 路径全部复用『变量_设置』那一套 |
| **流程_冷却** | 执行 / 秒数 → **可以** / **还在冷却** | `if Time.get_ticks_msec() - _gk_cd_ticks >= int((秒数) * 1000.0):` 然后 `_gk_cd_ticks = Time.get_ticks_msec()` | 无敌帧 / 防连发。**这条直接回答用户的第一句话**:触发区、子弹、按键会在窗口里连着触发几十次,扣血/闪白/音效跟着重来 —— 挂一个冷却门,"一波接触只发生一次" |
| **文本_数字** | 数值 → 文字 | 走一个 `_gk_num_text(value)` helper:整数 `str(int(roundf(value)))`,有小数 `str(snappedf(value, 0.01))` | HUD。**Godot 的 `str(3.0)` 是 `"3.0"`** —— 血量是 float,直接拼字符串就成了"血量 2.0"。这是实测出来的(探针打印的 HUD 文本) |

细节:

* 『移动_朝向目标』的『谁走』用 **CharacterBody 类型**取 `@onready`
  (`_gk_ref_typed(self, "敌2", "CharacterBody3D")`)—— 取成 `Node` 的话
  `.velocity` / `.move_and_slide()` 会被 Godot 静态检查拒绝,**整个脚本加载不了**;
* `validation.py` 的"基类必须是 CharacterBody"名单里加上了它(导出**之前**
  就能拦住"基类是 StaticBody 却用它"的图);
* 速度的维度坑同样处理(2D 像素/秒 vs 3D 米/秒,3D 超过 50 夹住并告警);
* 『面向目标』(可选):3D 用 `look_at`(**先压平 Y** —— 目标在头顶正上方时
  Godot 会报 "Up vector and direction are aligned"),2D 用 `rotation = atan2`;
* 『流程_冷却』的状态变量按节点分开(`ctx.node_tag`)—— 图里放两个冷却门
  互不打架;初值 `-999999` = 第一次一定放行;
* 『变量_增减』不能给 bool / String 变量用(告警 + 跳过,不生成非法算式);
* 顺手把『变量_设置』里那段"类型兜底 + setter"抽成了 `_assign_var_value`,
  两条写变量的路共用一份 —— 以后修类型转换不会漏一个。

### 又一个插件 bug:碰撞代理同步是**单向**的,追人敌人被每帧拽回原处

探针抓到的现象很有意思:`chaser_at=(0.0, 0.7, -2.5)` 一直不动,
而同一行的 `vel=(2.05, 0.06, -0.79)` 明明在动 —— **速度设上了、`move_and_slide()`
也调了,位置却纹丝不动**。

根因在导出的环境脚本 `gk_environment_<场景>.gd`:第十五轮为"门动得了网格、
动不了碰撞代理"加了**每物理帧把碰撞代理对齐到网格**,方向是单向的
(网格 → 代理)。**普通道具的网格在世界 glb 里、代理在 `Colliders/` 下**,
两者是分开的节点 —— 于是用 velocity 推着代理走的每一帧,都被"对齐回网格原处",
净位移恒为零。排查手法:探针把环境脚本的 `_gk_body_links` 打出来,
再把某一条从表里摘掉试一次 —— 摘掉之后立刻能追了(3.08 米 / 1.4 秒)。

修法:**谁动了谁说了算**。配对时记下两边各自的上一帧变换,这一帧:

    if mesh_now != pair[2]:        # 网格动了(Blender 场景动画 / 时间轴挪网格)
        body.global_transform = mesh_now
    elif body_now != pair[3]:      # 代理动了(游戏逻辑在推它 / 物理在滑)
        mesh.global_transform = body_now

两边都没动就什么都不做(地面、墙零开销)。老行为一个没丢:场景动画那一路照旧;
新行为修好了"逻辑推动的道具":**看得见的红方块真的跟着判定一起走了**
(以前只有判定在跑,网格钉在原地)。

### 挖出来的 4 件事(都修了)

**① 插件 bug:『@onready』引用只按"节点路径"去重、忽略类型**(真坑)

同一个物体先被『移动_设置位置』引用(它要 `Node`)、再被『进入区域』引用
(它要 `Area3D`)时,第二次**直接拿到那个 Node 类型的变量**。生成出来是

    if 节点_敌1 != null and 节点_敌1.body_entered...

而运行时 `节点_敌1` 是**网格**(MeshInstance3D)—— 探针报:

    Invalid access to property or key 'body_entered' on a base object
    of type 'MeshInstance3D'

**触发器整个失效**(敌人撞了不扣血)。修复:`add_onready` 的类型只往
**具体**方向升(Node → Area3D 可以,反过来不行)。

**② 插件 bug:碰撞代理同步在"道具被销毁后"每帧刷红**

环境脚本每物理帧把碰撞代理对齐到网格,里面写的是

    var mesh: Node3D = pair[0]
    if not is_instance_valid(mesh): continue

**第一句就先报错**:GDScript 往带类型的变量里赋"已释放的对象"直接抛
`Trying to assign invalid previously freed instance` —— 根本轮不到后面那句检查。
吃掉金币后(道具销毁了)就每帧刷一屏。修复:先对数组元素
`is_instance_valid(pair[0])`,通过了再落到带类型的局部变量上。

**③ 两条"虚惊告警"+ 一个静默 bug(静默那个更要紧)**

| 现象 | 真相 | 现在 |
|---|---|---|
| 『数学_运算』写回声明为 int 的变量 → 报"变量同时被当成 int 和 float,请改个名字" | 生成器**本来就**补 `int(...)`,产物没问题 | 静音(明确转换不再告警;名字也没问题) |
| 数字框给 bool 变量填 1 → 报"布尔变量被喂了数字,该接『常量_布尔』" | 数字框**只能填数字**,生成器也早就转成 `= true` | 静音(示例里 5 处这种写法 = 5 条噪音) |
| (顺手发现)给布尔变量**接一个数值表达式** → 生成 `= false` | 旧代码 `raw_value or 0`:接线时 raw_value 是 None,于是**表达式被丢掉、恒假** | 生成 `(表达式 != 0.0)` / `bool(表达式)` |

**④ 示例脚本自己的两个坑(写成注释 + 文档记档)**

* **同一个界面节点不能同时挂在两条执行链上**:执行流对"同一个节点"只认
  一条入口(按「节点+入口」记账),另一条会被当"抢"跳过 —— 结果开场链
  走到一半断了,HUD 和后面的巡逻时间轴**都不生成**。
* **节点图里的坐标是 Godot 坐标**:`移动_设置位置` 的 X/Y/Z 是运行时 Godot
  的坐标(Blender(x,y,z) → Godot(x, z, -y))。直接把 Blender 坐标填进去,
  "掉出地图复位"会把角色送到地板**下面**(y=-9),它每帧往下掉、每帧复位 ——
  探针看到的现象是"按 W 走不动"。

### 探针里也踩了两个小坑(记下来)

* 触发是"进入那一瞬间"的事:只在某个时间点读一次容易刚好错过 ——
  改成**每帧记最小值**(和"一次性粒子读 emitting"那个坑同一族);
* 角色要**贴着移动的敌人走**才可靠(直接传送一次,`body_entered` 来得偏晚);
* `:=` 推不出 `(bool and Variant)` 的类型,得写 `var near: bool = ...`。

## 零之前的之二十一:粒子 / 特效系统(需求 5)✅(2026-10-05 第二十一轮)

你从"下一步做哪块"里选了 **粒子系统(推荐)** —— 这是蓝图化总清单里
最后一个"完全没有"的大功能。四个分叉你定的方向都标在下面。

### 为什么 Blender 侧只是"标记 + 参数"

glTF 规范里**根本没有粒子**:Blender 的粒子系统一个字都传不过去,
硬塞 Godot 也不认。所以分工只能是:

    Blender 侧:标记"谁是发射器 + 参数多少"(面板『游戏物理』→『粒子特效』)
    导出时    :生成 Godot 的 GPUParticles3D / CPUParticles3D + 材质 / 贴图
    运行时    :『特效_播放』『特效_停止』『特效_爆发』三个节点控制它

**参数不是照印象抄的**:开发时先用 Godot 4.7 存了一份标准粒子场景当对照,
属性名 / 枚举值 / Curve 的 `_data` 序列化全部照它写。三个"凭印象写就会错"的点:

| 我原以为 | 实测 |
|---|---|
| `randomness` 写在粒子材质上 | 它在**节点**上,材质上没这个属性 |
| 缩放曲线给 `CurveTexture` 就行 | GPU 要 `CurveTexture`、**CPU 要 `Curve`**(直接给曲线) |
| 颜色渐变给 `Gradient` 就行 | CPU 要 `Gradient`、**GPU 要 `GradientTexture1D`** |

### ① 参数面板(你选的:物体面板)

『游戏物理』面板新增 **『粒子特效』** 框:数量 / 生命周期 / 一次性 / 自动播放 /
爆发度 / 初速 / 方向 / 扩散角 / 重力(负数=往上飘)/ 发射半径 / 起终颜色 /
起终大小 / 预发射 / 随机度 / 局部坐标 / 叠加发光。
方向按**物体自己的旋转**算 —— 把物体转 45°,斜着喷的火就是它。

### ② 两种引擎(你选的:面板可切,默认 GPU)

`粒子类型` 下拉:GPU(GPUParticles)/ CPU(CPUParticles),2D 项目对应
GPUParticles2D / CPUParticles2D —— 2D 的『方向』按**屏幕语义**来
(Blender 的"上" = 屏幕上的上;重力正数 = 往下)。

### ③ 三个节点(你选的:播放 + 停止 + 爆发)

| 节点 | 生成什么 | 语义 |
|---|---|---|
| **特效_播放** | `特效_x.emitting = true` | 开始喷;已经在喷就什么都不做 |
| **特效_停止** | `特效_x.emitting = false` | 停喷(已经在飞的粒子会自然消散完) |
| **特效_爆发** | `restart()` + `emitting = true` | **重新喷一轮**:一次性发射器=再放一轮,循环的=重开一段 |

* 目标用放大镜从场景里挑**发射器物体**(和静态资产的资产选择器同一个交互);
* 生成的引用带**具体类型**(`GPUParticles3D` / `CPUParticles3D`)—— 声明成
  `Node` 再调 `.emitting` 会被 GDScript 静态类型检查拒绝,整个脚本编译不过;
  所以导出侧把"这个发射器是 GPU 还是 CPU"算成一张表(和静态资产那张表一个套路),
  代码生成直接查。查不到(忘了勾『作为粒子发射器』)时给**明确告警 + 跳过**。

### ④ 本体网格(你选的:面板给开关)

勾『不显示本体网格』= 这个物体只当发射器标记:网格**不进世界 glb**
(和『子物体碰撞块』同一个套路),材质表里也不留它(免得刷"没找到网格节点")。
不勾就照常显示 —— 火盆模型上冒火一个物体搞定。
**空物体**也能当发射器(天然就是"只标位置和朝向")。

### 贴图:走现有链路 + 内置兜底

* 物体材质里有**基础色贴图** → 粒子就用它(走现有 `export_textures` 那份链路,
  文件名算法两边同源,不会出现"引用一个不存在的 png"让整个场景加载失败);
* 没有 → 导出时现写一张内置的 **圆形柔光** PNG(`art/fx_soft.png`,64×64,
  纯 Python zlib 手写的,离线单测能验);
* 有贴图但那张图**没导出来**(比如卡通材质总开关关掉)→ 自动退回内置那张,
  绝不生成悬空引用。

### 落位:挂在谁下面

* 这个物体在 `Colliders` 下有物理体 → 粒子挂在**它**下面:
  物体的游戏逻辑一移动,粒子跟着走(角色身上的火花要这个);
* 其余 → 统一挂在根下的 `Particles` 容器里(位置 = 物体世界坐标)。
朝向按 glTF 的 Y-up 换轴(**列优先**写进 .tscn —— 和相机那套同一个坑)。

## 零之前的之二十:碰撞系统打磨 —— 多碰撞体 + 凸包 + 预览=导出 ✅(2026-10-05 第二十轮)

你选的方向("下一步先做哪块" → **继续打磨碰撞体**)。这一轮不只做了新东西,
还顺手挖出**三个真 bug**(都在"预览和导出不一致"这条线上)。

### ① 子物体碰撞块(你选的方案:视口里直接摆)

『游戏物理』→『碰撞』框最后多了一个 **『作为父级的碰撞块』**:

* 勾上后这个物体**不出现在游戏画面里**(网格不进 glb),形状**合并进父物体**的碰撞体;
* 人形就是"摆三个胶囊/方块:头 / 身 / 腿",拖动摆位、配合线框预览所见即所得;
* 导出成宿主的 `Collision2 / Collision3…` 子节点,位置 = 相对宿主的偏移;
* 宿主面板会显示"含 N 个碰撞块:头、身、腿…";碰撞块顶在场景根上(找不到父物体)时给**红字**;
* 运行时『资产_创建实例』升级成**形状表**:本体一条 + 每个块一条 ——
  生成的实例和本体"长得一样"(以前只有本体那一个形状)。

### ② 凸包(你选的方案:手动选)

碰撞形状下拉多了 **『凸包 Convex』**:按网格真实外形(采样点求 bmesh 凸包)
生成 `ConvexPolygonShape3D` + 点集。自动模式**不会**用它(行为可预期);
算不出凸包(空网格)时**退回盒子**,不生成非法形状。2D 项目退回盒子。

### ③ 预览=导出(你清单里那句"预览没接进导出")

一查发现预览和导出**早就分家了**,三处不一致:

| 不一致 | 以前 | 现在 |

### ② 函数进阶:折叠时**自动**跨边界的数据线变成参数 / 返回值

上一轮"数据线跨边界"是**直接拒绝**的(要求手摆)。现在自动做掉:

```
外面 -> 里面(参数)          里面 -> 外面(返回值)
原来   外部.输出 ──► 选中里的输入        原来   选中里的输出 ──► 外部.输入
折叠后 外部.输出 ──► 调用节点的参数框     折叠后  选中里的输出 ──► 定义节点的『返回』
       函数体里插『变量_读取(参数名)』           调用节点的『结果』──► 外部.输入
       ──► 原来那个输入
```

* 参数名**取外面那个节点的名字**(一看就知道这个参数是什么);和已有变量重名会自动加序号;
* 同一个外部值喂给选中里**两个**节点 -> 只生成**一个**参数(不会多出一个框);
* 返回值只能有**一个** —— 多个不同来源要往外送会明确拒绝(提示"用字典/列表装起来"),比"悄悄只返回一个"安全。

实测(真 Blender,折叠前后等价):

```gdscript
func _ready() -> void:
    self.velocity = _dir1 * move_speed
    self.move_and_slide()
    带参数的折叠_0698c661(7.0)      # 外面那个常量,作为参数传进去
    print("你好，世界")              # 原来的下游照旧

func 带参数的折叠_0698c661(金额: float) -> void:
    print(金额)                      # 函数体里读参数
```

### 踩到的两个坑

1. **删线之后不能再读它的引脚**:`tree.links.remove(link)` 之后 `link.to_socket` 会报
   `ReferenceError: StructRNA of type NodeLink has been removed` —— 必须**先读引脚再删线**。
2. **参数必须在建『函数_调用』节点之前算好**:那个节点的参数引脚是按声明长出来的;
   建完再改声明就得重建引脚,而重建会把刚接好的线全冲掉。

### 三个关键决定(都记下来)

1. **函数签名只认"声明",节点不许各读各的**
   GDScript 的签名在两个地方用:定义处写形参、调用处传实参。两处各读各的就会对不上。所以两边都查**同一张声明表**(`properties.tree_functions`)。
2. **参数是函数局部的,不能生成成员变量**
   函数体里『变量_读取(参数名)』读到的必须是**形参**。第一版没处理,`_prepass` 会把它按成员变量声明到脚本顶部 —— 函数体里读到的就变成那个成员(而且 Godot 报 `SHADOWED_VARIABLE`)。现在 `_prepass` 和 `declare_var` 都跳过声明过的参数名;参数名和**真变量**重名时才告警提醒改名。
3. **中文函数名要映射成稳定且互不相同的名字**
   和变量名同一族的坑:`snake_case` 会把中文整个压掉,『治疗』『扣血』都会变成 `my_function` → Godot 报"函数已定义"、**整个脚本加载不了**。所以压完之后挂 8 位摘要(`治疗_c6b3f028`),不同名字不会撞。

### 折叠时**不能**自动做的情况(明确报出来,而不是折叠坏)

* 选中里有**多个入口**(函数只能有一个入口);
* **数据线穿过边界**(函数里的值给外面用 / 外面给里面用 —— 那需要参数和返回值,得手动摆);
* 出口不止一个,或出口是分支/循环的口(『是』『否』):折叠后它会变成**无条件执行**,行为会变;
* 选中的这段没有上游(没人驱动它)。

边缘处理)。BLEND 材质在 Godot 里走**透明队列:不写深度、按距离排序**,
所以后面的面片会画到前面去。

- [x] 确认没有顶点色(图元属性只有 POSITION/NORMAL/TEXCOORD_0/1/JOINTS_0/WEIGHTS_0)
- [x] 确认 .tres 正确引用 shader

      (`transparency = TRANSPARENCY_DISABLED` 在 ShaderMaterial 上不可设,
      可能要在 glb 的 .import 里改,或者导出时不让它变 BLEND)

### 3.5 头部(帽子区域)一块黑 ← ✅ **已修好(和 3.4 同一个根因)**

从正面看是一块黑;从侧面放大看帽子内沿有颜色。
**怀疑和 3.4 是同一个根因**(都是 BLEND/双面导致的深度与排序问题),
建议两件一起查。

**3.4 / 3.5 的最终解法**:`fragment()` 里**完全不写 `ALPHA`**。
Godot 只要看到写过 ALPHA 就归到透明管线(不写深度),值是多少不重要。
我们是抠图不是半透明,所以根本不需要写。见 gk_toon.gdshader 里的长注释。
