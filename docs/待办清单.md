## 第 217 轮:近景地形碰撞合批(减少静态物理体) ✅(2026-11-12)

第 216 轮的分区帧时结论:静止 / 走动平均 4~5ms,但各有 13 / 12 帧 >33ms,
而同一帧铺地形峰值只有 14.7ms —— 尖峰不在铺地形,在物理体数量。
本轮只做"减少静态碰撞体",不动地形外观与高度。

### ① 做法:一列一个物理体,碰撞按连续实心段合并

- `_build_column()`:整列一个 `StaticBody3D`(`地形_x_z`,原点在 y=0),
  视觉仍是一格一个 `MeshInstance3D`(名字 `方块_x_z_level`,位置 level+0.5)
  —— 外观和合批前逐像素一致;
- 新增 `_rebuild_column_shapes()`:读 `gk_kinds`(每格还在不在 / 是什么方块),
  把**连续实心段**合成一个盒子。高度 3 且都在 = 1 个 1×3×1 盒;
  挖掉中间那格 = 上下两个盒,洞的位置真的是空的;
- 新增 `_remove_block()`:挖一格只改 `gk_kinds`、收那一格的网格、重算碰撞段;
  整列挖空才 free 物理体(打 `gk_retire`,不重复记存档);
- 挖掘判定新增 `_aim_block()`:命中点沿法线退半格 = 方块中心,y 取整得层号,
  再查 `gk_kinds` 拿类型;同一列里换一格也会重置挖掘进度(`_mine_level`)。

### ② 三个依赖方是否等价

| 依赖方 | 合批前 | 合批后 | 是否等价 |
|---|---|---|---|
| `can_place_here()` | 0.9 立方 `intersect_shape`,mask 15 | 同一条查询,箱子体积 = 原逐块盒子的并集 | 是(占位拒绝逻辑不变) |
| 挖掘命中 | 射线命中方块节点,读 meta | 同一个盒子,按命中点算出层号再查表 | 是(类型 / 硬度 / 掉落一致) |
| 玩家 / 生物碰撞 | 每格 1×1×1 盒 | 1×h×1 合并盒(并集相同),挖中间会拆成两段 | 是 |

存档记录还是按"格"写 `_removed`(`x,z,level`),不受合批影响。

### ③ 前后对比(关 VSync / max_fps=0,各测两次取范围)

| 指标 | 合批前 | 合批后 |
|---|---|---|
| 近景 `地形_*` StaticBody3D | 4975 | **2304** |

结论:物理体与碰撞形状各降约一半;那 13 / 12 帧尖峰没有完全消失,
但 静止 13→5~6、走动 12→2(约 70~85% 消失),最大帧从 52~64ms 降到 38~42ms。
剩下的几帧与铺地形峰值(14.9ms)对不上,还在别处(首帧资源 / 物理步进),

## 第 207 轮:视距按原版(默认 16 区块)+ 先加载后进入 + 卸载迟滞 ✅(2026-11-10)

用户拿原版截图对标:渲染距离档位、默认值、视野内地形完整度都按原版来;

是**加载策略**不是档位数值,所以拆成三件事分别验收。

### ① 三件事

| 项 | 做法 |
|---|---|
| 先加载后进入 | 区块脚本暴露 `is_ready()` / `load_progress()`;点「开始游戏」「新建世界」「读档」后先盖一张「正在生成世界…」进度条,铺满再进世界(进度是真进度,不是定时动画) |
| 卸载迟滞 | `_region_in_range()` 加 `extra` 参数;`_replan()` 里走出范围的远景再留 2 个区块才拆 —— 在边界来回走不会一边拆一边建 |
| 档位与上限 | 8/12/16/24/32 区块 = 128/192/256/384/512 格;**默认 16 区块(256 格)**;帧率不够按 16→12→8 降档 |

`fog_depth_end = max(40, radius)`、`curve 1.4`、`density 0`,辉光与体积雾关闭。

### ② 卡顿真因:框架的"新节点进树就重挂材质"

`gk_environment` 监听 `SceneTree.node_added`,每有一个 Node3D 进树就排一次
`_gk_remat()`,把整张材质表(20 条 × 全树 `find_children`)重跑一遍。
地形一帧要进几十上百个节点 ——「新建世界→可玩」从 2.3 秒被拖到 **300 秒以上**,
玩家看到的就是进度条不动、走一步卡一下。

修法:区块脚本 `_ready()` 里 `_disable_remat.call_deferred()`,等一帧后扫全树
找到挂 `_gk_remat` 的节点(示例里是根下的 `Environment`,不是场景根),
把它的 `materials` 清空 —— `node_added` 的重挂直接走空表提前返回。
方块材质本来就由 `_block_material` / `_dress_placed` 指定,不需要框架再扫。
同时把每帧上限从 3 列提到 24 列、远景 2→4 区域(实测建一列 <0.1ms,
时间预算仍兜底),消掉"走一步刷一步"。

- **同类方块第二块识别不到**:Godot 对同名兄弟节点会改成

## 第 166 轮:射线『方向』未接线 = 零向量(修待办 ⑧)✅(2026-10-29)

待办清单里记了四天没修,因为它碰 codegen 默认路径。这轮按铁律单独做:
**先量影响面 → 再改 → 最后出零 diff 证据**。

### ① 根因(比清单里写的更大)

`input_vector` 未连线时**只**认 `gk_x / gk_y / gk_z`;而两个射线节点
(`GKNodeRaycast`、`GKNodeRaycastCheck`)只声明了 `gk_direction`。
于是拼出来是 `Vector3(0.0, 0.0, 0.0)`:射线长度为零、永远走『没打中』,
而且**不报错**。这不是"射线一个节点的问题",是"任何只声明向量属性的
节点都会中招"。

### ② 修法(为什么能零 diff)

`input_vector` 未连线时,先查 `gk_input_props` 的映射,**但只在节点
没有 gk_x / gk_y / gk_z 时才用**。绝大多数节点的向量引脚都是三件套,
所以它们的出码一位不变。

### ③ 影响面(量出来的,不是估的)

用脚本枚举全部节点类,满足"映射到 float_vector 且没有三件套"的**只有 2 个**,
就是两个射线节点;示例工程里也没有任何 `.gd` 出现过 `intersect_ray`,

## 第 163 轮:『角色_走路摆动』—— 没有骨骼也能"走起来像在走" ✅(2026-10-28)

用户:「继续下一步吧」。上一轮结尾列的第一条是"角色**没有骨骼动画**:走路是整体
平移、手臂不摆"。这一轮不动美术资产、不引入骨骼,用**程序化摆动**把它按下去 ——
而且做成**插件节点**,不是只改示例。

### ① 新节点『角色_走路摆动』(GKNodeHumanoidWalk)

| 参数 | 默认 | 说明 |
|---|---|---|
| 目标 | 自身 | 角色根节点(CharacterBody3D);零件在它下面(含 Model 里)都会被找 |
| 关节关键字 | `臂` | 零件名里包含这个字就当关节摆(示例:臂 / 腿 / 手) |
| 摆幅 | 34° | 最大摆角 |
| 浮沉 | 0.03 m | 每步上下浮几厘米(有 `Model` 节点才生效) |
| 参考速度 | 6 m/s | 到这个速度算"走满";摆幅与步频都按 速度/参考速度 缩放 |

生成的代码是 `_gk_walk_start(...)` + 注册在 `_physics_process` 里的
`_gk_walk_tick(delta)`,逐帧做三件事:按水平速度推进相位 → 两条手臂**反相**
摆 `rotation.x` → `Model.position.y` 加一个 `abs(sin)` 的浮沉。

### ② 为什么走物理帧 / 为什么按名字认零件

- **物理帧**:摆幅是按 `CharacterBody3D.velocity` 算的,velocity 只在物理帧更新;
  挂渲染帧会在两次物理帧之间重复读同一个速度,高刷屏上看着"一顿一顿"。
- **按名字认零件**:零件是 Blender 里的独立物体,导出成 glb 子节点后名字保留。
  没有骨骼的模型也能用 —— 这正是现在的处境。

### ③ 三个坑(每个都让功能"生成了但没效果")

1. **`input_string` 会对字符串再引一次**:第一版写
   `ctx.input_string(node, "关节", gd_string(text))` → 生成 `"\"臂\""`,
   一个**永远匹配不到任何零件**的关键字。代码照样生成、照样编译、照样跑,
   就是手臂不动。门禁因此改成读运行时的 `_gk_walks` 登记表
   (`entries=1 arms=2`),不再只 grep 生成代码。
2. **`_gk_walk_tick` 里变量重名**:生成时先写 `var body = state["target"]`
   又写 `var body = state["body"]`,GDScript 直接编不过;而 `elif` 分支里引用的
   `target` 根本没定义。
3. **探针把角色放到了地板外**:Blender 的 Y = Godot 的 **−Z**,出生点
   Blender y=−8.4 对应 Godot z=+8.4;探针按 Blender 坐标写 `z=-8`,
   角色一路掉到 −23 米。表现是 `speed=6.00` 但 `floor=false`,
   摆幅被"腾空只留三成"压到 10°。

### ④ 另一件必须记住的事:改插件代码要**先重装**

这一轮前两次重建都失败在 `尚未定义节点类型 'GKNodeHumanoidWalk'` ——
Blender 里装的是**副本**,`scripts\install.ps1` 不跑,新节点类在 Blender 里根本
不存在。顺序固定为:**改插件 → install.ps1 → 重建示例**。

- **逻辑**:开局『灯光_设置』把吊灯 2/3 灭掉(走廊只剩吊灯1+壁灯,后半截
  是黑的)→ 每捡一个保险丝:防重(标志)→ 计数+1 → **点亮一盏吊灯**
  (渐进反馈)→ 字幕;第三个亮起 = 供电恢复。
- **出口**:『去音乐教室』传送板加 **GetVar→Compare(GE 3)→Branch** ——
  0 个保险丝站上去只给字幕"配电箱还缺保险丝",集齐才切音乐教室。

### ② 探针踩的四个坑(每个都花了一轮才定位)

1. **判定体埋进立柱**:保险丝位置放在了立柱坐标 (±9,±6.5) —— 判定体
   被塞进 StaticBody 里,玩家一进去就被挤开,`body_entered` 永远不触发。
   挪开 ±1.5 米就好。**触发区别和实体几何重叠**。
2. **日志面板 = 隐形暂停**:走廊探针原有流程按 J 开了日志面板**没关**,
   后续阶段全程在"暂停菜单状态"下跑(世界物理停摆,body_entered 不触发,
   count 恒 0)。探针阶段要**先把面板关掉**。
   ⚠ 关面板别用 **Esc** —— Esc 是暂停菜单热键,合成 Esc 事件会把树
   暂停(又一个隐形暂停源);用 **J 再按一次**。
3. **迟到暂停**:被抓失败链的尾巴是 `await 1 秒 → _gk_apply_pause(true)`
   —— 探针点"回到安全屋"解除的暂停,**这条会在 ~10.1s 再把树暂停一次**
   (HORROR_PAUSE_CHANGE 三次二分全复现 elapsed=10.12)。探针强制
   `get_tree().paused = false` 再解一次,之后没有别的暂停源。
4. **探针活不过真切场景**:『场景_切换关卡』找不到 GkWorld autoload 时走
   `change_scene_to_file` —— 释放的是 current_scene = **探针根本身**,
   PASS 永远打不出来。修法:**root 下挂一个假 GkWorld**(类内定义
   `class GateSpy extends Node`,deferred add)拦下 `change_level(path)`
   调用 —— 打印目标路径 = 证明"放行分支真的走到了",真切场景的部分由
   音乐教室自己的探针覆盖。
