# 节点怎么连 —— 从零到一个能跑的角色

这篇是给"画完节点但不知道下一步该做什么"的人看的。
读完你应该能独立搭出一个会走会跳、有界面、能存档的角色。

---

## 一、先搞清三种线

Blender 节点编辑器里,引脚（socket）的颜色决定它是什么:

| 线的样子 | 名字 | 作用 | 能不能接错 |
|---|---|---|---|
| **金色 / 白色** | **执行流** | 决定**先做哪个、后做哪个** | 只能接执行流。接不进灰色引脚 |
| **灰色** | **任意值** | 传数据(可以接任何类型) | 能接任何数据引脚 |
| 其它颜色 | 数值 / 文本 / 布尔 / 向量 | 传具体类型的数据 | **颜色不同就连不上** |

**一句话记住**:

> **金线管顺序,灰线管数值。**

这和 UE5 蓝图**完全一样**。金线 = 蓝图的白色执行线，灰线 = 蓝图的数据线。

### 最容易犯的错

```
❌ 把「按键按下」的灰线接到「移动」的金线入口
   -> Blender 直接不让连(颜色不同)

✅ 金线:「每当_物理帧」──>「移动」
   灰线:「输入_按键按住」──>「移动」的某个数据引脚
```

## 二、最小的能跑图（4 个节点）

想做一个"能左右走"的角色，只要这些:

```
[每当_物理帧]  ──金──>  [移动_按方向]
                            ↑ 灰线
                    [输入_方向向量]
```

**就这么简单。** 三个节点(加事件)就能动起来。

再加跳跃，变成:

```
[每当_物理帧] ──金──> [移动_按方向] ──金──> [如果_否则]
                                                    ↑ 条件(灰线)
                                              [逻辑_布尔运算(与)]
                                                    ↑        ↑
                                          [取值_是否在地面]  [输入_按键按下]

                     [如果_否则] ──是──> [移动_跳跃]
```

## 三、四条必须记住的规则

### 规则 1:一个输入引脚只能接一条线

Blender 的限制。把两个事件的执行线接到同一个节点，**第二条会被静默拒绝**。

- 想两个地方都触发同一段逻辑 -> **把那几个节点复制一份**
- 生成器检测到这种情况会明确告警，不会默默丢逻辑

### 规则 2:有重力的游戏要勾「重力模式」

`移动_按方向` 上有个 **`重力模式`** 开关，**平台跳跃 / 有重力的游戏必须勾上**。

原因:Godot 4 的 `CharacterBody2D` **不会自动施加重力**，它只按你设的
`velocity` 移动。不勾的话角色 `velocity` 恒为 `(0,0)`、永远浮在原地，
看起来就像"脚本没生效"。

勾上之后生成器会做两件事:每帧累加 `get_gravity()`，并且**只改水平速度**，
纵向留给重力。

> 俯视角游戏(贪吃蛇、塔防)不需要重力，保持不勾。

### 规则 3:必须有相机

Godot 的 `Camera2D` / `Camera3D` **不会自己跟着角色**。它就是站在哪拍哪。

不放 `相机_跟随` 的话，角色一跑远就出画面 —— 这是"画面看起来空了"
最常见的原因。

```
[每当_每帧] ──金──> [相机_跟随]     ← 相机留空 = 自动找场景里的相机
```

### 规则 4:执行流必须有起点

一条链必须从**事件节点**开始(`每当_准备` / `每当_每帧` / `每当_物理帧` /
`每当_输入` / `自定义函数`)。

```
❌ [打印] (孤零零一个,没有事件)  -> 永远不会执行
✅ [每当_准备] ──金──> [打印]
```

侧栏会告诉你现在有几个事件、几个动作。**事件 = 0 就是不会跑。**

## 四、完整例子:一个能存最高分的角色

这是 `examples/demo_platformer` 的真实结构，可以直接打开看。

```
【1】初始化 —— 只在游戏开始时跑一次
────────────────────────────────────────────
[每当_准备]
   ──金──> [存档_载入(槽=best)]
   ──金──> [存档_读取到变量(键=best_score, 写入=best_score)]
   ──金──> [变量_设置(变量名=score, 值=0)]
   ──金──> [界面_文本(文字="A/D 移动  空格 跳", X=16, Y=16)]
   ──金──> [界面_文本(文字="分数: 0", X=16, Y=44)]
   ──金──> [界面_文本(文字="最高分: 0", X=16, Y=78)]
   ──金──> [界面_按钮(文字="重开 (R)")]
              └──金(点击)──> [调用_函数(重开函数)]

[自定义函数(函数名=restart_game)]
   ──金──> [实例_重载场景]


【2】移动 —— 每物理帧跑一次(和帧率无关,手感稳定)
────────────────────────────────────────────
[每当_物理帧]
   ──金──> [移动_按方向(速度=260, ✅重力模式)]
              ↑ 灰线:[输入_方向向量(左=move_left, 右=move_right)]
   ──金──> [移动_水平翻转(模式=自动)]
   ──金──> [如果_否则]
              ↑ 条件(灰线):[逻辑_布尔运算(运算=与)]
                               ↑A                ↑B
                    [取值_是否在地面]   [输入_按键按下(动作=jump)]
              └──是──> [移动_跳跃(强度=560)]


【3】相机 —— 每帧跑一次
────────────────────────────────────────────
[每当_每帧]
   ──金──> [相机_跟随(平滑=0.12)]     ← 相机留空 = 自动找
```

### 为什么这样分三段？

| 段 | 事件 | 为什么 |
|---|---|---|
| 1 | `每当_准备` | 初始化只该做一次。放 `每帧` 里会每帧重建 UI |
| 2 | `每当_物理帧` | **移动必须放物理帧**。放 `每帧` 里的话，帧率一变手感就变 |
| 3 | `每当_每帧` | 相机跟随是视觉，跟帧率走更顺滑 |

## 五、从零开始的推荐顺序

别一次画完。**每加一步就在 Godot 里按 F5 看一眼**，出问题好定位。

1. **只放 `每当_物理帧` + `打印_输出`** -> 跑起来,Godot 输出面板能看到字
   (这一步确认"脚本真的挂上了、真的在跑")
2. **加 `移动_按方向` + `输入_方向向量`** -> 角色能动
3. **勾上 `重力模式`** -> 角色会掉下去
4. 场景里加地面(`StaticBody2D` + `CollisionShape2D`) -> 站得住
5. **加跳跃分支** -> 能跳
6. **加 `相机_跟随`** -> 跑远也看得见
7. 最后再加 HUD、金币、存档

**每一步只加一个东西。** 一次加五个，出问题你不知道是哪个。

## 六、找不到节点怎么办

菜单最上面有两个入口:

- **`搜索节点…`** —— 打字找。中文标签、分类名、英文类型名都能搜
  (打「存档」列出存档类，打「ray」列出射线类)
- **`常用`** —— 起步最需要的 18 个，不用翻分类

菜单结构从 **87 个节点 / 23 个分类** 改成两级:

```
运算 ▸ 常量 / 数学 / 向量 / 逻辑 / 转换
```

小分类(只有三五个节点)保持一级 —— 再套一层是让你多点一次。

## 七、导出的代码长得什么样

点侧栏「导出为 Godot 脚本」后，你会拿到一个 `.gd` 文件。
它是**可读的标准 GDScript**，不是加密的中间产物:

```gdscript
func _physics_process(delta: float) -> void:
    var _dir1 := (Input.get_vector(ACTION_MOVE_LEFT, ..., 0.2)).normalized()
    self.velocity += self.get_gravity() * get_physics_process_delta_time()
    self.velocity.x = _dir1.x * move_speed
    self.move_and_slide()
```

生成的脚本**是给你读的**。看不懂节点图在做什么的时候，导出一份看看就知道了。

想手写补充？在导出目录里加，或者看 `examples/demo_platformer`
里 `HANDWRITTEN_TAIL` 的做法 —— 混合使用完全没问题。
