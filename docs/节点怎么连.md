# 节点怎么连 —— 从零到一个能跑的角色

这篇是给"画完节点但不知道下一步该做什么"的人看的。
读完你应该能独立搭出一个会走会跳、有界面、能存档的角色。

---

## 一、先搞清三种线

Blender 节点编辑器里,引脚（socket）的颜色决定它是什么:

| 线的样子 | 名字 | 作用 | 能不能接错 |
|---|---|---|---|
| **金色 / 白色** | **执行流** | 决定**先做哪个、后做哪个** | 只能接执行流。接不进灰色引脚 |
| **灰色** | **任意值** | 传数据(可以接任何类型) | 能接任何数据引脚 |
| 其它颜色 | 数值 / 文本 / 布尔 / 向量 | 传具体类型的数据 | **颜色不同就连不上** |

**一句话记住**:

> **金线管顺序,灰线管数值。**

这和 UE5 蓝图**完全一样**。金线 = 蓝图的白色执行线，灰线 = 蓝图的数据线。

### 最容易犯的错

```
❌ 把「按键按下」的灰线接到「移动」的金线入口
   -> Blender 直接不让连(颜色不同)

✅ 金线:「每当_物理帧」──>「移动」
   灰线:「输入_按键按住」──>「移动」的某个数据引脚
```

## 二、最小的能跑图（4 个节点）

想做一个"能左右走"的角色，只要这些:

```
[每当_物理帧]  ──金──>  [移动_按方向]
                            ↑ 灰线
                    [输入_方向向量]
```

**就这么简单。** 三个节点(加事件)就能动起来。

再加跳跃，变成:

```
[每当_物理帧] ──金──> [移动_按方向] ──金──> [如果_否则]
                                                    ↑ 条件(灰线)
                                              [逻辑_布尔运算(与)]
                                                    ↑        ↑
                                          [取值_是否在地面]  [输入_按键按下]

                     [如果_否则] ──是──> [移动_跳跃]
```

## 三、四条必须记住的规则

### 规则 1:一个输入引脚只能接一条线

Blender 的限制。把两个事件的执行线接到同一个节点，**第二条会被静默拒绝**。

- 想两个地方都触发同一段逻辑 -> **把那几个节点复制一份**
- 生成器检测到这种情况会明确告警，不会默默丢逻辑

### 规则 2:有重力的游戏要勾「重力模式」

`移动_按方向` 上有个 **`重力模式`** 开关，**平台跳跃 / 有重力的游戏必须勾上**。

原因:Godot 4 的 `CharacterBody2D` **不会自动施加重力**，它只按你设的
`velocity` 移动。不勾的话角色 `velocity` 恒为 `(0,0)`、永远浮在原地，
看起来就像"脚本没生效"。

勾上之后生成器会做两件事:每帧累加 `get_gravity()`，并且**只改水平速度**，
纵向留给重力。

> 俯视角游戏(贪吃蛇、塔防)不需要重力，保持不勾。

### 规则 3:必须有相机

Godot 的 `Camera2D` / `Camera3D` **不会自己跟着角色**。它就是站在哪拍哪。

不放 `相机_跟随` 的话，角色一跑远就出画面 —— 这是"画面看起来空了"
最常见的原因。

```
[每当_每帧] ──金──> [相机_跟随]     ← 相机留空 = 自动找场景里的相机
```

### 规则 4:执行流必须有起点

一条链必须从**事件节点**开始(`每当_准备` / `每当_每帧` / `每当_物理帧` /
`每当_输入` / `自定义函数`)。

```
❌ [打印] (孤零零一个,没有事件)  -> 永远不会执行
✅ [每当_准备] ──金──> [打印]
```

侧栏会告诉你现在有几个事件、几个动作。**事件 = 0 就是不会跑。**

## 四、完整例子:一个能存最高分的角色

这是 `examples/demo_platformer` 的真实结构，可以直接打开看。

```
【1】初始化 —— 只在游戏开始时跑一次
────────────────────────────────────────────
[每当_准备]
   ──金──> [存档_载入(槽=best)]
   ──金──> [存档_读取到变量(键=best_score, 写入=best_score)]
   ──金──> [变量_设置(变量名=score, 值=0)]
   ──金──> [界面_文本(文字="A/D 移动  空格 跳", X=16, Y=16)]
   ──金──> [界面_文本(文字="分数: 0", X=16, Y=44)]
   ──金──> [界面_文本(文字="最高分: 0", X=16, Y=78)]
   ──金──> [界面_按钮(文字="重开 (R)")]
              └──金(点击)──> [调用_函数(重开函数)]

[自定义函数(函数名=restart_game)]
   ──金──> [实例_重载场景]


【2】移动 —— 每物理帧跑一次(和帧率无关,手感稳定)
────────────────────────────────────────────
[每当_物理帧]
   ──金──> [移动_按方向(速度=260, ✅重力模式)]
              ↑ 灰线:[输入_方向向量(左=move_left, 右=move_right)]
   ──金──> [移动_水平翻转(模式=自动)]
   ──金──> [如果_否则]
              ↑ 条件(灰线):[逻辑_布尔运算(运算=与)]
                               ↑A                ↑B
                    [取值_是否在地面]   [输入_按键按下(动作=jump)]
              └──是──> [移动_跳跃(强度=560)]


【3】相机 —— 每帧跑一次
────────────────────────────────────────────
[每当_每帧]
   ──金──> [相机_跟随(平滑=0.12)]     ← 相机留空 = 自动找
```

### 为什么这样分三段？

| 段 | 事件 | 为什么 |
|---|---|---|
| 1 | `每当_准备` | 初始化只该做一次。放 `每帧` 里会每帧重建 UI |
| 2 | `每当_物理帧` | **移动必须放物理帧**。放 `每帧` 里的话，帧率一变手感就变 |
| 3 | `每当_每帧` | 相机跟随是视觉，跟帧率走更顺滑 |

## 五、动画状态机怎么连

动画状态机在**另一张图**里(节点编辑器左上角把类型切成「游戏动画」,
或者侧栏『游戏逻辑』面板 -> 『打开/新建动画树』)。玩法图里只放**一个**
『动画_状态机』节点驱动它。

### 形状 A:播完就切(最简单)

```
[动画_状态 idle] ● 转到 ──────> [动画_状态 run] ● 进入
```

**状态之间直接连线 = 「前一个动画播完就切到后一个」。**
不需要任何条件,也不用放转场节点。
(和 Godot 自己的 `AnimationNodeStateMachine` 的 auto-advance 一样。
动画要是设成循环的,它永远播不完,也就永远不切。)

### 形状 B:按条件切

```
[动画_状态 idle] ● 转到 ──> [动画_转场] ● 转到 ──> [动画_状态 run] ● 进入
                                 ● 上游              (『上游』= 这个引脚)
                                 ● 条件 <── [动画判断_移动状态] ● 在移动
```

转场节点要接**三样**东西,少一样都会在导出时被告警点名:

| 引脚 | 接什么 | 忘了会怎样 |
|---|---|---|
| **上游** | 上一个状态的『转到』 | 不知道从哪切过来 —— **这条转场整条失效** |
| **条件** | 判断节点的输出 | 不知道什么时候切,规则不生效 |
| **转到** | 下一个状态的『进入』 | 不知道切到哪去 |

> **忘了接上游怎么办?** 转场节点上有『从』『到』两个下拉(右边放大镜),
> 直接选状态名也行 —— 连线优先,下拉兜底。**但推荐连线**,箭头看得见。

『条件来源』可以直接选按键,不用拉节点:

- `自己写(接引脚)` —— 想多复杂都行
- `上游动画播完` —— 这个动画播完就切
- `选输入:按住 / 刚按下 / 松开` —— 挑一个输入动作,比如 `jump`

### 一个状态可以接**多条**转场

```
[动画_状态 idle] ● 转到 ──> [转场:刚按下 jump] ──> [动画_状态 jump]
                        └──> [转场:在移动]      ──> [动画_状态 run]
```

**判定顺序 = 节点在画布上的上下位置**,上面的先判,第一个成立的赢,
而且一帧只走一步(和虚幻 5 一样)。所以想让"跳跃"优先于"跑步",
就把跳跃那条转场往上摆。

### 起始状态 / 开始口 / 结束口

**没放开始口时**:没有任何转场指向它的那个状态 = 起始状态,进游戏就播它。
(不用勾任何东西 —— 勾选框那个方案早就删了。)

**放了『动画_开始』**:它连的那个状态就是起始状态 —— **写明的事,不用猜**
(图一大,"谁没被指到"经常猜不准)。它的『开始方式』就是**自定义的开始条件**:

| 开始方式 | 什么时候开始 |
|---|---|
| 立刻开始 | 游戏一开始(或上一段演完之后)就跑 |
| 变量为真 | 侧栏那个布尔变量为真时开始 |
| 刚按下 / 按住某键 | 按键触发(填输入动作名) |
| 上一个动画播完 | 某段动画播完之后才开始这张图 |
| 自己写(接条件引脚) | 怎么判都行 —— 接一个判断节点上去 |

条件不成立时整张图**不动**;『动画_结束』之后条件再次成立会重新开始。

**『动画_结束』**表示"这段动画演完了":状态节点的『转到』直接连到它的『进入』
即可。走到它的时候状态机收工(`_gk_anim_done = true`)并且**不再判转场**,
所以玩法图有稳定的时机去读它:

```
[动画_运行状态] ─ 已结束 ──> [如果_否则] ─是─> 扣血 / 回待机 / 播下一段
                ─ 在跑
                ─ 当前状态
```

### 一个状态能被几条转场指着?调『入口数量』

> **Blender 的硬限制:一个输入引脚只允许一条连线。**

所以「待机」被 走/跑/跳/受击/攻击 五条转场指着时,只有**最后接的那一条**
留在引脚上,前面几条的线会被**顶掉**(画布上你会看到箭头跳走)。

修法:状态节点上有 **『入口 [N]』** —— 要被几条转场指着就调到几,
引脚长成 `进入 / 进入 2 / 进入 3 …`(第一个永远叫『进入』,
老文件里接好的线不会断)。调数量时**已经接好的连线会保住**。

### 用自定义变量当条件

```
侧栏『变量』加一个 is_hurt(布尔)
        ↓
动画树里拉『动画_取变量』选 is_hurt → 它的『值』接到转场『条件』
        ↓
变量谁来改?两条路:
   (1) 状态的『进入时』/『离开时』接『动画_设变量』(进状态就置真、离开就置假)
   (2) 游戏逻辑图里用『变量_设置』(真假值接『常量_布尔』)
```

**『变量_设置』一张卡片能设好几个变量**(照蓝图的 Set 节点):把『数量』调到
2~6,引脚长成 `值 / 值 2 / 值 3 …`,**每个值引脚可以接不同的节点**。
第 1 个变量仍然叫『值』/填在老位置 —— 老图接好的线不会断。

> 布尔变量别用数字框填 `0/1`(那个框只能填数字):导出时会转成 `false/true`
> 并提醒你接『常量_布尔』—— 因为 `is_hurt = 0.0` 会让整个脚本加载失败。

### 输入按键:按一下键就绑好(照 UPBGE 的 Keyboard Key)

```
[输入_按键]   触发方式: [刚按下 ▾]    按键: [C]  [🔑按一下键]
```

* **一个节点顶三个**:按住 / 刚按下(这一帧)/ 松开
* 点 **『按一下键』** 然后按键盘上任意键 —— 绑好了,不用记动作名
  (『输入动作』留空会按按键名自动生成,比如 `key_w`)
* 导出时这个键会写进 `project.godot` 的输入映射:
  **Blender 里按 C,Godot 里 C 就真的能用**
* 鼠标 / 手柄 / 触屏在右键菜单的『输入』下面分栏(照 UPBGE 的排布)

两张图编译成**同一个脚本**,变量就是同一个 —— 玩法图设、动画图读,
这是蓝图里最常见的那种联动。

> 『动画_设变量』放在**动画树**里不会被执行(动画树只算条件,没有执行流)。
> 导出时会明确告警 —— 要改变量就去游戏逻辑图。

**"这个标志谁来清"**:让动画自己负责最省事,比如

```
每当_物理帧 → 如果( is_hurt 且 非(动画_是否在播("受击")) ) → 变量_设置(is_hurt = false)
```

不要用『等待_秒』去清:`等待_秒` 生成的是 `await`,而这段代码在
`_physics_process` 里 —— 一 await,后面的移动逻辑就一起被挂起
(按一下键角色卡住不动)。

### 出问题了看哪里

- **节点上**:『动画_状态机』节点会直接把状态清单和问题画出来
- **侧栏**:『游戏动画』面板里有完整的图(状态 / 每条转场 / 问题清单)
- **导出报告**:上面那些问题会**原样**变成告警,一条不漏

最常见的三条:

| 现象 | 原因 |
|---|---|
| 角色进游戏一动不动 | 状态没选『动画』(状态名 = 动画名),或者动画名和模型里对不上 |
| 状态不切换 | 转场的『上游』空着 / 条件没接 / 动画设成了循环 |
| 某个状态永远进不去 | 它和起始状态之间没连起来(面板会标成"孤立") |

> **想直接照抄一份能跑的?** 打开
> `examples/demo_anim_tree/动画状态机示例.blend` —— 6 个状态
> (待机/走/跑/跳/受击/攻击)、一个状态 4 条出线、自定义布尔变量当条件、
> 状态直连"播完就切",全都接好了。配套说明见同目录的 README。

## 六、从零开始的推荐顺序

别一次画完。**每加一步就在 Godot 里按 F5 看一眼**，出问题好定位。

1. **只放 `每当_物理帧` + `打印_输出`** -> 跑起来,Godot 输出面板能看到字
   (这一步确认"脚本真的挂上了、真的在跑")
2. **加 `移动_按方向` + `输入_方向向量`** -> 角色能动
3. **勾上 `重力模式`** -> 角色会掉下去
4. 场景里加地面(`StaticBody2D` + `CollisionShape2D`) -> 站得住
5. **加跳跃分支** -> 能跳
6. **加 `相机_跟随`** -> 跑远也看得见
7. 最后再加 HUD、金币、存档

**每一步只加一个东西。** 一次加五个，出问题你不知道是哪个。

## 七、找不到节点怎么办

菜单最上面有两个入口:

- **`搜索节点…`** —— 打字找。中文标签、分类名、英文类型名都能搜
  (打「存档」列出存档类，打「ray」列出射线类)
- **`常用`** —— 起步最需要的 18 个，不用翻分类

菜单结构从 **87 个节点 / 23 个分类** 改成两级:

```
运算 ▸ 常量 / 数学 / 向量 / 逻辑 / 转换
```

小分类(只有三五个节点)保持一级 —— 再套一层是让你多点一次。

## 八、导出的代码长得什么样

点侧栏「导出为 Godot 脚本」后，你会拿到一个 `.gd` 文件。
它是**可读的标准 GDScript**，不是加密的中间产物:

```gdscript
func _physics_process(delta: float) -> void:
    var _dir1 := (Input.get_vector(ACTION_MOVE_LEFT, ..., 0.2)).normalized()
    self.velocity += self.get_gravity() * get_physics_process_delta_time()
    self.velocity.x = _dir1.x * move_speed
    self.move_and_slide()
```

生成的脚本**是给你读的**。看不懂节点图在做什么的时候，导出一份看看就知道了。

想手写补充？在导出目录里加，或者看 `examples/demo_platformer`
里 `HANDWRITTEN_TAIL` 的做法 —— 混合使用完全没问题。
