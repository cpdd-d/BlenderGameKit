# 界面（UI）右键菜单与连线式层级 优化方案

## Context（为什么做这件事）

用户要求"优化游戏界面的右键菜单逻辑"，具体三块诉求：

1. **加节点**：`变量_设置/读取`、`获取物体`、`获取物体名称`、`当鼠标点击时`、`当键盘某键被按下时`。
2. **改流程**：把界面逻辑改成 UMG 式的层级链（画布 → 限定框/容器 → 按钮 → 文本/背景 …），并且**父子层级改成连线**而不是填名字。
3. **界面引用值**：一个"可连线的界面引用"（类似 UMG 控件变量），让玩法图能拿到界面/控件去显示、隐藏、改属性。

经四轮确认，用户选定：**两张图都改**、**层级改成连线（贴近 UMG）**、结构节点要**画布 + 限定框 + 背景 + 文本限定框**、鼠标点击事件**两种都做**（填控件名=只认那个控件，留空=全屏）、引用节点**两个都做**（`界面_取控件` + `界面_取界面`）。

现状（已核实）：

* 控件全部由节点在运行时 `new()` 出来，没有场景真节点（[services.py](file:///d:/BlenderGameKit/BlenderGameKit/codegen/services.py#L788-L802)）。

* 父子层级靠 `gk_parent_widget` 字符串 + 运行时 `_gk_find_widget(父名)`，生成前用 `_ui_design_order` 按名字做拓扑排序（[services.py](file:///d:/BlenderGameKit/BlenderGameKit/codegen/services.py#L2694-L2723)）。

* `变量_设置/读取`、鼠标/键盘节点是**故意没开**到界面图的（[nodes.py](file:///d:/BlenderGameKit/BlenderGameKit/nodes/nodes.py#L168-L181)）。

* **关键约束**：事件节点（`GKEventNode`）目前**只在玩法图里被执行** —— `_collect_events` 只扫 `self.tree`，设计图里的语句只要不在 `STMT_HANDLERS` 就被跳过（[generator.py](file:///d:/BlenderGameKit/BlenderGameKit/codegen/generator.py#L2730-L2736)、[services.py](file:///d:/BlenderGameKit/BlenderGameKit/codegen/services.py#L2760-L2770)）。所以新事件**不能**做成 `GKEventNode`，否则放进设计图等于摆设。

预期结果：界面节点族按 UMG 习惯扩充，父子可以连线，界面能被当作"值"在玩法图里传递，新事件在两张图（含主界面）里都能真正触发。

## 设计要点（先定调，再落地）

### 1. 连线式父子：**连线只是写法，落地仍是"按名字挂"**

不重写运行期。做法：给每个控件节点加一个 `父` 输入引脚（`OBJECT`）+ `自己` 输出引脚，供连线；代码生成时**从连线反推父节点名**，走原有 `_gk_find_widget(父名)` 那条路。好处是运行期零改动、生成物可预期。

`gk_parent_widget` 字符串**保留**（既是老图的既有写法，也是"不想连线时手填名字"的快捷键），resolver 里**连线优先、没连才读字符串**。已保存的 `.blend` 靠**开机迁移**补上 `父`/`自己` 引脚（见阶段 A0）—— 用户已确认"老 .blend 不必兼容"，所以可以放心用重建引脚那条路。

### 2. 新事件：做成**语句节点 +** **`register_input_handler`**，不做 `GKEventNode`

因为设计图/主界面里的事件节点走不到 `_collect_events`。而 `界面_暂停游戏`、`界面_对话框` 已经证明了另一条路可用：语句节点在生成期调 `ctx.register_input_handler(...)` 注册一个 `_input` 回调，派发与函数体由生成器统一发射（[context.py](file:///d:/BlenderGameKit/BlenderGameKit/codegen/context.py#L795-L826)、[generator.py](file:///d:/BlenderGameKit/BlenderGameKit/codegen/generator.py#L478-L513)、[generator.py](file:///d:/BlenderGameKit/BlenderGameKit/codegen/generator.py#L2412-L2431)）。这条路：

* 两张图 + 主界面 autoload 都生效（`_input_handlers` 派发与 `ui_main` 分支无关）；

* `during_pause` 可控制"暂停里也响应"（UI 热键正是要这个）；

* **绕开** `generator.py:131` 写死 `GKNodeOnInput` 的签名陷阱。

链式逻辑放进 `ctx.extra_sections`（照 `界面_按钮` 的写法），`_input` 回调只放一小段守卫 + 调它。

### 3. "引用一整套界面"靠新的 `界面_画布` 节点

当前没有"设计级根容器"，控件直接挂在 `_gk_ui_root` 下（[services.py](file:///d:/BlenderGameKit/BlenderGameKit/codegen/services.py#L978-L983)）。所以 `界面_取界面` 的落地方式：找该设计图里的 `界面_画布` 节点 → 返回 `_gk_find_widget(画布节点名)`；没有画布就回退 `_gk_ui_root` 并告警。

## 实施步骤（按可独立验证的批次推进）

### 阶段 A0 — 开机迁移：给老节点补 `父` / `自己` 引脚

已保存的 `.blend` 里，节点的引脚是当**数据**存着的 —— 新声明的 `父`/`自己` 不会自己长出来。用现成的加载迁移补上：

1. 扩 `migrate_pin_names()`（[nodes/\_containers.py](file:///d:/BlenderGameKit/BlenderGameKit/nodes/_containers.py#L479-L518)）：

   * **扩大扫描范围**：现在只扫 `GKGameLogicTree` / `GKAnimationTree`（[L486-489](file:///d:/BlenderGameKit/BlenderGameKit/nodes/_containers.py#L486-L489)），要加上 `GKUiDesignTree` 等 GK 树（建议按 `current_tree_type` 那份 8 类名单统一）。

   * **新增"缺声明引脚"判据**：`wanted = gk_inputs + gk_outputs` 的引脚名里，有哪个在实例的 `inputs`/`outputs` 里找不到 → 触发 `rebuild_sockets()`。现在只看 input 的"陈旧引脚"（[L492-509](file:///d:/BlenderGameKit/BlenderGameKit/nodes/_containers.py#L492-L509)），不够。
2. **安全性已核实**：基类 `rebuild_sockets()` 会先把连线按引脚名记下来，重建完再照原名接回去（[node\_base.py](file:///d:/BlenderGameKit/BlenderGameKit/nodes/node_base.py#L669-L714)），所以迁移**不会丢掉旧连线**。
3. **幂等性**：迁移后缺失引脚已存在，下次加载不再触发 → 必须写一条冒烟断言"连跑两次，第二次返回 0"，防止某类节点的 `build_sockets` 产不出某个声明引脚而每次加载都重建。
4. 落点不用改：`_on_load_post` 已经在 `load_post` 里调它（[operator\_io.py](file:///d:/BlenderGameKit/BlenderGameKit/operator_io.py#L210-L221)）。

### 阶段 A — 连线式父子层级（基础，先做）

   ⚠ 必须"新建 tuple 赋给子类"。`GKNodeUiText` 等**没声明** **`gk_outputs`**，是从 `GKStatementNode.gk_outputs`（[node\_base.py](file:///d:/BlenderGameKit/BlenderGameKit/nodes/node_base.py#L916) 的共享 tuple）继承的，原地 mutate 会污染所有语句节点。
   ⚠ 已核实这 12 个 builder 类**都没有覆写** **`build_sockets`**，集中追加安全。

2. **新增 resolver（纯逻辑，便于离线测试）**：在 [nodes/node\_base.py](file:///d:/BlenderGameKit/BlenderGameKit/nodes/node_base.py) 加 `ui_parent_name(node)`：

   * 引脚不存在（阶段 A0 迁移还没跑到的文件）→ 同样回退字符串，不报错。

   ⚠ 不放 `codegen/services.py`（那里模块级 import 了 `nodes.node_base`，反向会循环导入）；需要环检测时在函数体内 lazy import `codegen.graph.upstream`。

### 阶段 B — 新结构节点（画布 / 限定框 / 背景 / 文本限定框）

新增 4 个 `GKStatementNode`（`gk_category="界面"`），加进 `UI_DESIGN_BUILDER_NODES`（[nodes/\_display.py](file:///d:/BlenderGameKit/BlenderGameKit/nodes/_display.py#L2940-L2945)），各写一个 `@stmt_node` 处理器：

| 节点        | bl\_idname         | 生成物                                                                                    |
| --------- | ------------------ | -------------------------------------------------------------------------------------- |
| 界面\_画布    | `GKNodeUiCanvas`   | 一个具名 `Control`（铺满/自定义尺寸），作为该设计图的根；子控件挂它下面                                              |

| 界面\_文本限定框 | `GKNodeUiTextBox`  | `PanelContainer` + `Label`（带边框/背景/字号）                                                  |

### 阶段 E — 新事件节点（鼠标点击 / 按键按下）

按要点 2，做成语句节点：

| 节点       | bl\_idname             | 触发                                                                                                                                    |
| -------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 界面\_鼠标点击 | `GKNodeUiOnMouseClick` | `_input` 里 `event is InputEventMouseButton and event.pressed`（左右键可选）；填了控件名则加"点在那个控件上"的判定；输出 FLOW `执行`                                 |
| 界面\_按键按下 | `GKNodeUiOnKeyPress`   | `_input` 里 `event.is_action_pressed(<ACTION>)`（捕获键，复用 `gk.capture_key` + `resolved_action()`，导出时自动写进 project.godot 输入映射）；输出 FLOW `执行` |

实现细节：

* 节点处理器：`ctx.new_section()` 收集守卫 + `_chain(ctx, node, …)`（照 [services.py](file:///d:/BlenderGameKit/BlenderGameKit/codegen/services.py#L1150-L1172) 的 `界面_按钮` 写法，注意手动存还 `ctx.sink`），结果放进 `ctx.extra_sections`；再 `ctx.register_input_handler(<唯一名>, during_pause=<选…>, body=[守卫行, 调那个函数])`。

* `during_pause=True`（UI 热键默认暂停里也要响应；给一个卡上开关）。

## 风险与注意

* **开机迁移的幂等性**：`migrate_pin_names` 的判据改成"声明了但实例上没有"之后，只要某类节点的 `build_sockets` 产不出某个声明引脚，就会**每次加载都重建**。必须靠"第二次返回 0"的冒烟断言兜住。

* **迁移会重建引脚**：`rebuild_sockets()` 已按引脚名保存/还原连线，但只认**引脚名**——迁移时若同时有改名，连线要按旧名找回（现有 `PIN_RENAMES` 机制保留）。

* **`_ui_design_order`** **必须一起换 resolver**，否则连线式父子会出现"子先建、父找不到"（[services.py](file:///d:/BlenderGameKit/BlenderGameKit/codegen/services.py#L2695-L2701) 的注释讲的就是这个坑）。

* 追加引脚必须用"新建 tuple"写法，避免污染 `GKStatementNode` 的共享 `gk_outputs`。

* 新节点进菜单后**分类不用动**（"界面"已在 `CATEGORY_ORDER` 与 `MENU_GROUPS`），但节点手册必须重生成。

* 阶段 E 不碰 `EVENT_KINDS` / `_emit_event_body` / 签名判定，从而规避 `generator.py:131` 陷阱；若日后确要用 `GKEventNode` 承载设计图事件，需另开一条发射路径。
