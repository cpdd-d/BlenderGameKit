# 恐怖闯关示例 —— 3D 恐怖剧情闯关(第一 / 三人称可切换)

一个 `.blend`、三个 Blender 场景,`asset_export.export_all_scenes()`
一关导一张 `.tscn`;关底用『场景_切换关卡』切过去 —— 一段能反复跑的闭环短篇。

## 三关

| 关 | 场景 | 内容 | 用到的 |
|---|---|---|---|
| 1 | **大堂** | 门厅(地面 + 四壁 + 柱子)、章节卡 + HUD、**拾取钥匙**、**手电(可用 F 开关 / 电量会掉)**、会**升起**的大门、自动存档 | 角色预设 / 触发区 / 灯光_设置 / 时间轴 / 存档 |
| 2 | **走廊** | 长走廊、开场**对话 + 剧情选择**、巡逻 AI(3 个巡逻点)+ 看见追击 / 丢失去查看、近身**惊吓三连** + 心跳紧张度、**2 个柜子躲藏**、尽头门 | AI_状态 / AI_转场 / 惊吓 / 心跳 / 暗角 / 对话_选择 |
| 3 | **结局** | 小房间、**结局选择**(回头救她 / 独自逃出去)、存档(结局键 + 槽位 `story_end`)、结局大字、**BGM 淡出**、回大堂**闭环** | 对话_选择 / 存档 / 总线音量 / 切关卡 |

### 章节 / 目标骨架(一处定义、三关复用)

`make_story_demo.py` 里只写**一个** `build_hud(logic, chapter, goal, ...)`:
目标文本 + 钥匙数 + 手电电量 + 提示 + 章节卡(3 秒淡出)。三关各自只传不同的
章节名和目标文字。

## 怎么玩

用 Godot 打开 `恐怖闯关示例_godot` 文件夹,按 **F5**(主场景 = 大堂)。

| 按键 | 作用 |
|---|---|
| WASD / 空格 | 走 / 跳 |
| 鼠标 / 滚轮 | 转视角 / 缩放 |
| **C** | 切到**第一人称**(相机贴头平视) |
| **V** | 切到**第三人称**(越肩弹簧臂) |
| **F** | 手电开关(开局关着,电量每秒 -1.5,没电自动关) |
| 走钥匙 / 走大门 | 大堂:拾钥匙 → 钥匙数 +1 → 走到大门(够 1 把才升起开门) |
| 走进柜子 | 走廊:躲藏(暗角加深 + 提示"屏住呼吸…") |
| **1 / 2** | 结局选择 |

> **第一 / 第三人称的事实**:预设角色建**两根弹簧臂 + 两台相机**,**C → 第一人称机位**
> (`第一人称相机`，随玩家跨关卡保留)、
> **V → 第三人称机位**。第一人称是"把俯瞰那根杆子的臂长收到 0.25、高度抬到 1.55、
> 俯仰 0"做出来的(见 `codegen/camera.py`:"臂长 0 = 相机贴枢轴")。

## 节点图与躲藏

三关共用一张 **玩家角色逻辑**，移动、跳跃、鼠标转向、滚轮、C/V 切换、
Alt 鼠标捕获、视角偏好、手电开关和电量都在这里维护。图中用 `@第一人称相机` 和
`@第三人称相机` 引用玩家的子相机；整份文件只有一个“玩家”对象，在大堂中编辑。
走廊和结局只放出生点，不再复制玩家或相机。
角色图按六个职责分组，通过编号“序列”固定执行顺序，整理图的位置不会重排这些分支。

每关各有一张关卡逻辑图，走廊另有怪物 AI 状态图。关卡图的
『每当_准备』通过『序列』依次完成状态初始化、存档、界面建立；章节卡的
等待链在最后。角色图的手电物理帧用『序列』明确按键、灯光、电量显示的顺序。
同一执行出口扇出多条线且其中有等待/对话/选择时，导出会报
`SUSPENDING_FLOW_FANOUT`，提示改用『序列』。

柜子是躲藏区。玩家进入后，『AI_看得见』判定会忽略处于躲藏区的玩家；
AI 仍在巡逻。暗角和 HUD 提示由进出区域事件控制，走出柜子后恢复正常视野判定。

## 用到了什么

多场景导出 + 切关卡 / 角色预设(WASD·跳跃·鼠标视角·滚轮·C·V)/ 触发区 /
`灯光_设置`(手电开关 + 亮度)/ `定时_时间轴`(门板升起)/ `存档_*` /
`AI_状态`·`AI_转场`·`AI_开始`(巡逻 / 追击 / 去查看)/ `惊吓_事件` /
`氛围_紧张度` + `氛围_心跳` / `屏幕_暗角` / `对话_选择` / `界面_对话框` /
`音效_总线音量`(结局 BGM 淡出)/ 场景设置里的**开局 BGM**(每关一首)。

> ⚠ **美术是占位方盒**:墙 / 柱 / 柜 / 怪物都是程序生成的长方体,先把玩法与
> 氛围跑通用的。真要发作品,请自行替换成美术模型。

## 怎么重新生成

```
blender -b --gpu-backend vulkan --python scripts\make_story_demo.py
```

会重建 `恐怖闯关示例.blend`(三个场景、一张共享角色图)和 `恐怖闯关示例_godot/`,
并在工程的 `audio/` 里**现生成四个小 wav**(心跳 / 惊吓 / 拾取 / 开门)+
三首开局 BGM 源 —— 示例不依赖任何外部素材。

导出包含三张关卡场景和一张 `GKDefaultPlayer.tscn`。世界设置的“默认角色”选择
角色对象，启动时生成一次，切关时保留同一实例及全部子对象。每关的“玩家出生点”
决定到达位置与朝向，切关会清零速度、重置弹簧臂缓存；电量、物品和视角状态保留。
未指定默认角色的旧项目沿用原有场景导出方式。目前默认角色支持 3D 角色体。

## 灯光与预览

**这一版按"卡通二次元"配的**(第 123 轮,用户实测反馈:"现在的环境渲染成了
『中世纪』的风格了,但我想要的是卡通二次元"):

- **卡通材质开着 + 全局卡通风格开着**,三段明暗(`three_tone` 0.45~0.55),
  暗部是**冷紫**;
- **色调映射 LINEAR**(不用 ACES —— ACES 会把颜色压灰,是"写实奇幻感"的一半来源);
- **环境光强度 0.78~0.95**(以前只有 0.09,暗部直接死黑),
  背景色 / 雾色都改成有颜色的冷调,不再往暖棕走;
- **饱和度 1.16~1.20、亮度 1.04~1.06**;
- 墙 / 地 / 柱的 albedo 整体**抬亮去棕**(0.13~0.17 -> 0.30~0.62),
  暖色灯保留(暖光 + 冷影是动画的经典对比)。

> ⚠ "中世纪感"的两个历史来源,别再改回去:`scripts/story_upgrade.py` 的
> `upgrade_visuals()` 曾经在环境设好**之后**又把 `toon_materials = False`、
> 环境光 0.09、背景近纯黑写了一遍(那段已删,理由写在函数头);
> 以及 `ACES` 色调映射。

雾 / 泛光 / 背景 / 环境光都在『游戏显示』图的 **`游戏环境设置`** 卡上
(第 123 轮从『显示_环境氛围』改名);**环境预设**下拉里现在有
**★ 卡通日间 / 卡通黄昏 / 卡通夜晚**三档二次元配方,示例自己也存了
「示例·卡通门厅 / 示例·卡通走廊 / 示例·卡通结局」三套,可以一键套到别的关卡。
"启动画质"设为高画质(原生分辨率、4x MSAA、4096 阴影图);接触阴影 SSAO 与
间接补光 SSIL 需要 Forward+。手电只照亮光锥内的局部表面。

Blender 的"Godot 观感"预览按各关背景、环境光、雾和色调设置对齐。
两套引擎的光照单位、阴影滤波和后处理仍有差异，不能保证逐像素一致。
测试：`tests/blender_blueprint.py`、`tests/blender_persistent_player.py`、`scripts/check_story_demo.py`、
`scripts/check_persistent_player.py`（真实往返切关，检查实例、子对象、相机、电量和出生点）、
`scripts/check_scene_light_render.py`（最后一项需要真实显卡）。
