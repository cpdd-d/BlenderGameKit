# 恐怖闯关示例 —— 3D 恐怖剧情闯关(第一 / 三人称可切换)

一个 `.blend`、三个 Blender 场景,`asset_export.export_all_scenes()`
一关导一张 `.tscn`;关底用『场景_切换关卡』切过去 —— 一段能反复跑的闭环短篇。

## 三关

| 关 | 场景 | 内容 | 用到的 |
|---|---|---|---|
| 1 | **大堂** | 门厅(地面 + 四壁 + 柱子)、章节卡 + HUD、**拾取钥匙**、**手电(可用 F 开关 / 电量会掉)**、会**升起**的大门、自动存档 | 角色预设 / 触发区 / 灯光_设置 / 时间轴 / 存档 |
| 2 | **走廊** | 长走廊、开场**对话 + 剧情选择**、巡逻 AI(3 个巡逻点)+ 看见追击 / 丢失去查看、近身**惊吓三连** + 心跳紧张度、**2 个柜子躲藏**、尽头门 | AI_状态 / AI_转场 / 惊吓 / 心跳 / 暗角 / 对话_选择 |
| 3 | **结局** | 小房间、**结局选择**(回头救她 / 独自逃出去)、存档(结局键 + 槽位 `story_end`)、结局大字、**BGM 淡出**、回大堂**闭环** | 对话_选择 / 存档 / 总线音量 / 切关卡 |

### 章节 / 目标骨架(一处定义、三关复用)

`make_story_demo.py` 里只写**一个** `build_hud(logic, chapter, goal, ...)`:
目标文本 + 钥匙数 + 手电电量 + 提示 + 章节卡(3 秒淡出)。三关各自只传不同的
章节名和目标文字。

## 怎么玩

用 Godot 打开 `恐怖闯关示例_godot` 文件夹,按 **F5**(主场景 = 大堂)。

| 按键 | 作用 |
|---|---|
| WASD / 空格 | 走 / 跳 |
| 鼠标 / 滚轮 | 转视角 / 缩放 |
| **C** | 切到**第一人称**(相机贴头平视) |
| **V** | 切到**第三人称**(越肩弹簧臂) |
| **F** | 手电开关(开局关着,电量每秒 -1.5,没电自动关) |
| 走钥匙 / 走大门 | 大堂:拾钥匙 → 钥匙数 +1 → 走到大门(够 1 把才升起开门) |
| 走进柜子 | 走廊:躲藏(暗角加深 + 提示"屏住呼吸…") |
| **1 / 2** | 结局选择 |

> **第一 / 第三人称的事实**:预设角色建**两根弹簧臂 + 两台相机**,**C → 第一人称机位**
> (`第一人称相机`，随玩家跨关卡保留)、
> **V → 第三人称机位**。第一人称是"把俯瞰那根杆子的臂长收到 0.25、高度抬到 1.55、
> 俯仰 0"做出来的(见 `codegen/camera.py`:"臂长 0 = 相机贴枢轴")。

## 节点图与躲藏

三关共用一张 **玩家角色逻辑**，移动、跳跃、鼠标转向、滚轮、C/V 切换、
Alt 鼠标捕获、视角偏好、手电开关和电量都在这里维护。图中用 `@第一人称相机` 和
`@第三人称相机` 引用玩家的子相机；整份文件只有一个“玩家”对象，在大堂中编辑。
走廊和结局只放出生点，不再复制玩家或相机。
角色图按六个职责分组，通过编号“序列”固定执行顺序，整理图的位置不会重排这些分支。

每关各有一张关卡逻辑图，走廊另有怪物 AI 状态图。关卡图的
『每当_准备』通过『序列』依次完成状态初始化、存档、界面建立；章节卡的
等待链在最后。角色图的手电物理帧用『序列』明确按键、灯光、电量显示的顺序。
同一执行出口扇出多条线且其中有等待/对话/选择时，导出会报
`SUSPENDING_FLOW_FANOUT`，提示改用『序列』。

柜子是躲藏区。玩家进入后，『AI_看得见』判定会忽略处于躲藏区的玩家；
AI 仍在巡逻。暗角和 HUD 提示由进出区域事件控制，走出柜子后恢复正常视野判定。

## 用到了什么

多场景导出 + 切关卡 / 角色预设(WASD·跳跃·鼠标视角·滚轮·C·V)/ 触发区 /
`灯光_设置`(手电开关 + 亮度)/ `定时_时间轴`(门板升起)/ `存档_*` /
`AI_状态`·`AI_转场`·`AI_开始`(巡逻 / 追击 / 去查看)/ `惊吓_事件` /
`氛围_紧张度` + `氛围_心跳` / `屏幕_暗角` / `对话_选择` / `界面_对话框` /
`音效_总线音量`(结局 BGM 淡出)/ 场景设置里的**开局 BGM**(每关一首)。

> ⚠ **美术是占位方盒**:墙 / 柱 / 柜 / 怪物都是程序生成的长方体,先把玩法与
> 氛围跑通用的。真要发作品,请自行替换成美术模型。

## 怎么重新生成

```
blender -b --gpu-backend vulkan --python scripts\make_story_demo.py
```

会重建 `恐怖闯关示例.blend`(三个场景、一张共享角色图)和 `恐怖闯关示例_godot/`,
并在工程的 `audio/` 里**现生成四个小 wav**(心跳 / 惊吓 / 拾取 / 开门)+
三首开局 BGM 源 —— 示例不依赖任何外部素材。

导出包含三张关卡场景和一张 `GKDefaultPlayer.tscn`。世界设置的“默认角色”选择
角色对象，启动时生成一次，切关时保留同一实例及全部子对象。每关的“玩家出生点”
决定到达位置与朝向，切关会清零速度、重置弹簧臂缓存；电量、物品和视角状态保留。
未指定默认角色的旧项目沿用原有场景导出方式。目前默认角色支持 3D 角色体。

## 灯光与预览

**这一版按"卡通二次元 + 明暗交给灯"配的**(第 123 轮配色改成二次元,
**第 124 轮按真机实测重配了光比** —— 用户:"优化运行画面的显示"):

- **卡通材质开着 + 全局卡通风格开着**,三段明暗(`three_tone` 0.45~0.55),
  暗部是**冷紫**;
- **色调映射 LINEAR**(不用 ACES —— ACES 会把颜色压灰,是"写实奇幻感"的一半来源);
- **环境光强度 0.28~0.34**(第 124 轮从 0.78~0.95 降下来;第 123 轮以前只有 0.09,
  暗部直接死黑);
- **饱和度 1.18~1.20、亮度 1.04~1.06**;
- 墙 / 地 / 柱的 albedo 整体**抬亮去棕**(0.13~0.17 -> 0.30~0.62),
  暖色灯保留(暖光 + 冷影是动画的经典对比)。

### 第 124 轮:为什么把环境光降下来(实测数据)

用真 Godot 4.7.2 在走廊关卡的**第一人称实际游玩机位**上逐项开关,量帧均值亮度
与标准差(标准差 ≈ 画面明暗层次):

| 状态 | 均值 | 标准差 | 灯对整帧的贡献 |
|---|---|---|---|
| 第 123 轮配方(环境光 0.78) | 0.2593 | 0.0922 | **0.0000** |
| 环境光 0.28 + 灯 9.0 + 射程 28 | 0.4084 | **0.1634** | **0.1638** |

第一行那个 **0.0000** 是这一轮的病灶:关掉全部 7 盏壁灯,**整帧一个像素都不变** ——
环境光 0.78 把灯完全压没了,画面是一层平的蓝,所以"运行画面看着很闷、很平"。
灯本身是好的(把相机对准灯附近的墙面/天花板,关灯 0.0123 → 开灯 0.138~0.184)。

所以这一轮做了三件事,把**明暗还给灯**:

1. **环境光 0.78~0.85 → 0.28~0.34**。它现在只负责"暗部有冷紫色相"这一件事
   (第 123 轮用户的诉求"暗部是有颜色的暗,不是黑"仍然成立),明暗段落交给灯。
   ⚠ 不要再往下压:再低墙裙和角落会糊成一团黑。
2. **壁灯射程 11 米 → 28 米、能量 4200W → 9000W**。射程就是 Godot 点光的
   `omni_range`:一条 48 米的走廊、每隔 14.4 米一盏灯,射程只有 11 米时
   灯与灯之间永远有一段照不到。实测射程 11 → 30 米让灯的贡献从 0.0507 涨到
   0.1349(2.7 倍)。**走廊尽头仍然照不到** —— 那里该黑下去。
3. **泛光门槛 `glow_threshold` 1.0 → 0.85、力度 `glow_strength` → 1.6**。
   泛光的真扳机是这两个值,不是 `glow_intensity`:门槛停在 Godot 出厂值 1.0 时,
   开/关泛光整帧只差 0.0044(等于没有)。

雾也一起调了:密度 0.022 → 0.014、**雾亮度 0.55**。雾色本身是亮的蓝灰,
原样铺过去等于给整条走廊加一层牛奶(实测关雾 0.2551 vs 开雾 0.3547)。

另外这一关**显式**把『雾盖背景』(`env_fog_sky_affect`)设成 **0**:
Godot 出厂值是 1.0,意思是"雾色把背景整个换掉" —— 于是取色器上挑的背景色
在游戏里根本看不见,而 Blender 预览(雾是独立体积盒子、不盖世界底色)是看得见的,
这正是"预览和运行对不上"的一半。实测那一步让整帧从 0.3803 掉到 0.3460。

> ⚠ 这个字段的**默认值仍是 1.0**(= Godot 出厂行为),这是有意的:实测把它
> 一刀切成 0 会把**恐怖示例**整帧压暗 70%(0.1422 → 0.0434,那个示例的背景
> 本来就是近黑、靠雾色垫亮的)。本仓库的规矩是"新功能不改老工程/老示例的观感",
> 所以这里是**示例自己显式点明**要 0,而不是插件替所有项目做决定。
> 你自己想要这个效果,就在『游戏环境设置』卡上把『雾盖背景』拉到 0。

> ⚠ "中世纪感"的两个历史来源,别再改回去:`scripts/story_upgrade.py` 的
> `upgrade_visuals()` 曾经在环境设好**之后**又把 `toon_materials = False`、
> 环境光 0.09、背景近纯黑写了一遍(那段已删,理由写在函数头);
> 以及 `ACES` 色调映射。
>
> ⚠ 第 124 轮这条"把环境光降下来"**只改数值、不改结构**:第 123 轮定下的
> "LINEAR + 冷色暗部 + 三段明暗 + 抬亮去棕"一条都没动。降环境光是为了让
> **已有的明暗设计真的显示出来**,不是换风格。

雾 / 泛光 / 背景 / 环境光都在『游戏显示』图的 **`游戏环境设置`** 卡上
(第 123 轮从『显示_环境氛围』改名);**环境预设**下拉里现在有
**★ 卡通日间 / 卡通黄昏 / 卡通夜晚**三档二次元配方,示例自己也存了
「示例·卡通门厅 / 示例·卡通走廊 / 示例·卡通结局」三套,可以一键套到别的关卡。
"启动画质"设为高画质(原生分辨率、4x MSAA、4096 阴影图);接触阴影 SSAO 与
间接补光 SSIL 需要 Forward+。手电只照亮光锥内的局部表面。

Blender 的"Godot 观感"预览按各关背景、环境光、雾和色调设置对齐,
**并在第 124 轮改成用场景里的真实灯光画明暗**(第 123 轮以前视口用的是
Blender 默认那盏"跟着视角转的棚拍灯",所以预览里的光比和运行时对不上)。
两套引擎的光照单位、阴影滤波和后处理仍有差异，不能保证逐像素一致。

### 第 124 轮:三个实机 bug 的修法(都带实测数字)

用户实测报了三条,根因和修法都记在这里,免得以后有人"顺手改回去"。

**① 附身时相机穿墙。** 原来是把相机**纯位置赋值**到角色身后 5 米,完全没查
碰撞 —— 贴墙时那 5 米就落到墙外。真机(走廊南墙,墙内表面 z=-6.75)量到:
旧写法相机落在 **z=-10.59(墙外)**,新写法 **z=-2.55(屋内)**。
修法照角色弹簧臂那一套:从枢轴往"想要的位置"打射线,撞到就把相机拉到撞点
前面 0.35 米,再从**身体**(不是枢轴)竖直向上打一条做天花板兜底。
⚠ 别把相机也加进排除列表:`Camera3D is CollisionObject3D` 是 GDScript
**静态错误**,整份脚本会加载不了(踩过,`Parse Error`)。

**② 被 AI 攻击的瞬间"传送 / 变成肩部视角"。** 根因不在 AI,在**相机震动**:
`Camera2D.offset` 是**像素**,而 `Camera3D.h_offset / v_offset` 是
**视锥偏移(世界单位)** —— 生成器把同一个"强度"直接填给了两者。惊吓_事件
给的强度是 20,于是 3D 那边等于把视口横移二十个世界单位。真机量到:
强度 20 在旧写法下让画面横移 **577 像素(目标直接飞出屏幕)**,新写法
**20.0 像素**(正是那个"强度"想表达的像素当量)。换算公式是实测标定的:
`px_per_unit ≈ 23.0 × (视口高度/360) ÷ tan(fov/2)`,在 640×360 / 1280×720
配 fov 50/70/90 六组里都吻合(23/33/49 与 23/64/97,误差 < 3%)。

**③ 预览的灯比运行时亮一倍多。** 真机同一机位(1152×648)量帧均值:
运行时 **0.3953**,预览 **0.9130**;而且亮的**几乎全是灯** —— 把世界强度
调到 0 只让 0.9130 动到 0.9123(环境光项在预览里不起作用)。
根因是两套引擎的光**根本不是同一种单位**:Blender 点光按物理瓦数 1/r² 衰减,
Godot 的 `light_energy` 按 `omni_range` 做距离衰减,而导出侧的换算约定是
**1000W ≈ 1.0** —— 解 `1000 = 4πr²·衰减` 得 **r ≈ 9.4 米**,也就是说这个
约定只在离灯 9.4 米那一个距离上成立,灯离墙 2~3 米的房间里预览自然亮十几倍。
修法是按实测标定把预览的灯乘 **0.06**(扫 0.04~0.2 取误差最小的一档):
预览 **0.9130 → 0.4070**,对上运行时的 0.3953。
⚠ 这个系数**只存在于内存**:无头构建(`-b`)不调暗,Ctrl+S 之前也会先还原
(save_pre 钩子)—— 否则 0.06 倍会被写进 .blend,下一次导出灯就暗 16 倍。
(这条路径实测踩过:`save_pre` 钩子签名漏了 `*args`,Blender 调用时
`TypeError`,钩子静默失败,540W 真的被写进了文件。现在有测试钉着。)
