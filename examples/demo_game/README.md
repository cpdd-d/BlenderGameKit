# 小游戏示例(吃金币 + 躲敌人 + 胜负 + 重开)

这一关是**用来验证整条链路**的(第二十四轮),第二十五 / 二十六 / 二十七轮又拿它当
"做游戏常用件"的试验场:从 Blender 里摆场景、连节点图,到 Godot 里真的能玩、能赢、能输、能重开。

| 文件 | 说明 |
|---|---|
| `小游戏示例.blend` | Blender 工程(打开它,节点编辑器里是整棵逻辑图,136 个节点)|
| `小游戏示例_godot/` | 导出的 Godot 工程(用 Godot 打开这个目录,按 F5)|

## 一、怎么玩(按 F5 之后)

| 操作 | 会发生什么 |
|---|---|
| **WASD / 空格 / 鼠标 / 滚轮 / C·V** | 移动 / 跳 / 转视角 / 缩放 / 切机位(角色逻辑**预设**生成的)|
| 走进**金色方块**(金币) | 金币数 +1、金币消失、原地爆一簇火花、**金币位置飘一个 "+1"**,HUD 跟着变 |
| 碰到**敌1**(红方块) | 血量 -1 + **玩家模型闪红** + 头顶飘 **"-1"** + 屏幕闪一下红 + 相机震动;它在左右来回巡逻 |
| 被**敌2**(另一个红方块)**追上** | 血量 -1(它一路追着你跑,不会穿墙;起步/刹车是平滑的,不会瞬起瞬停)|
| **E** | **拍一下敌1**:它抖一下(真动画)。连着按 E 时**不会打断当前这一轮** —— 先放完再重复 |
| 受伤之后 | **1.5 / 2 秒无敌帧**:同一波接触里只会掉一次血 |
| 集齐 **5 枚金币** | 屏幕中间出现「全部收齐!按 R 再来一次」 |
| 血量掉到 **0** | 出现「被抓到了……按 R 重来」 |
| **R** | 重开这一关(重载场景:金币、血量、位置全部复位)|
| **Tab** | 上帝摄像机(WASD 飞 / 空格升降 / 鼠标转视角)|
| **F1 / F2** | 调试面板:看金币数 / 血量实时值 + 最近打印;F2 复制全部内容 |
| **Esc** | 退出游戏 |
| 掉出地图 | 自动送回出生点 |

左上角三行是 HUD(操作提示 / 目标 / 金币·血量)。血量是**小数(float)**,
显示成"血量 2"而不是"血量 2.0" —— 靠的是『文本_数字』;血量和金币还**夹了范围**
(0~3 / 0~5):扣血不会扣成负数,计数也不会溢出。

## 二、这一关演示了什么(每一块都用到了)

| 用到的功能 | 在哪看 |
|---|---|
| 角色逻辑预设 | WASD / 跳 / 鼠标视角 / 弹簧臂 / 滚轮缩放 / C·V 切机位 |
| 触发区拾取(『进入区域』) | 每枚金币一条独立链:走进 → 金币数 +1 |
| **『变量_增减』**(第二十五轮) | 一个节点顶掉"读取 + 数学 + 设置"三件套:金币 +1、血量 -1 |
| **『移动_朝向目标』**(第二十五轮) | 敌2 追着玩家跑(velocity + move_and_slide,撞墙会滑不会穿) |
| **『流程_冷却』**(第二十五轮) | 两条受伤链前面:一波接触只掉一次血(无敌帧) |
| **『文本_数字』**(第二十五轮) | HUD 显示"血量 2"而不是"血量 2.0" |
| **『到达』/『加速』**(第二十六轮) | 敌2 的"贴上了吗"直接用『到达』输出(少了距离+比较两个节点);起步/刹车平滑 |
| **『限制范围』**(第二十六轮) | 血量夹 0~3、金币夹 0~5 —— 探针里再也不会出现 `hp=-2` |
| **『特效_闪红』**(第二十六轮) | 挨打时玩家整个模型红 0.25 秒,自动还原 |
| **『界面_飘字』**(第二十六轮) | 吃金币飘 "+1"、受伤飘 "-1"(一次性 Label3D,不占 HUD) |
| **『动画_播放』+『先放完再说』**(第二十七轮) | 按 E 播敌1 的抖动动画(真 Blender Action → glb → Godot AnimationPlayer);连按不打断当前这一轮 |
| 粒子特效(第二十一轮) | 『金币火花』(空物体发射器):吃到时把它挪到金币位置再『特效_爆发』 |
| 时间轴(往返) | 敌1 左右来回巡逻(一条时间轴、一条轨道)|
| 变量 + HUD | 『界面_文本』每物理帧刷"金币 N / 血量 N" |
| 受伤反馈 | 『屏幕_闪白』+『相机_震动』+ 打印 |
| 胜负判定 | 每物理帧查『金币数 ≥ 5』/『血量 ≤ 0』,用变量『结束』挡住重复触发 |
| 重开 | 『实例_重载场景』(存档槽留空 = 重载当前场景)|
| 掉出地图复位 | 每物理帧查自己 Y < -6 就送回出生点 |
| 上帝机 / 调试面板 | Tab / F1(F2 复制)—— 这两块也在导出的环境脚本里 |

> **两个敌人长得一样,机制不一样**:
> * 敌1 是**触发区**(Area3D,不挡人),巡逻靠时间轴把位置左右挪,
>   受伤靠 `body_entered`(走进去就触发);
> * 敌2 是**角色体**(CharacterBody3D,挡人),靠『移动_朝向目标』每帧
>   设速度 + `move_and_slide` 追玩家,受伤靠它的『到达』输出
>   (= 距离进了『停在多远』1.2 米)。
>
> 两者都靠环境脚本把**碰撞代理**和**网格**对齐 —— 第二十五轮把它改成了
> "谁动了谁说了算"(见下面第五节)。

## 三、自动检查(不用 Blender,要 Godot)

```
python scripts\check_game_demo.py
```

它会把示例拷到 `_dist/game_probe`,加一个探针场景,用真 Godot **把这一关玩一遍**,
断言这些现象(**不是**看代码长什么样):

* `DEMO_GAME … coins=5 enemies=1 chaser=true spark=true` —— 开场东西都在;
* `DEMO_MOVE ok=true` —— 按住 W 一秒,角色真的走了(约 5.9 米);
* `DEMO_PATROL ok=true` —— 敌1 在巡逻;
* `DEMO_COINS picked=5 left=0 hud=金币 5 clean_text=true` —— 5 枚金币收完、场上清零、
  HUD 跟上、且**没有 .0**;
* `DEMO_WIN ok=true` —— 集齐后出现胜利提示;
* `DEMO_CHASE ok=true` —— 敌2 从 14.9 米外追到 12.1 米(它真的在靠近);
* `DEMO_COOLDOWN ok=true hits=2` —— 贴着敌2 走 2.5 秒,扣血只触发 2 次
  (冷却 2 秒;没有冷却门的话是每帧一次,血量当场清零);
* `DEMO_HURT ok=true hits=1` —— 贴着敌1 走 2 秒,触发区只扣 1 次血;
* `DEMO_FX flash=true restored=true float_coin=true float_hurt=true` ——
  挨打时玩家模型**闪过红**(`material_override` 一度是 unshaded 材质)且**过后恢复**;
  吃金币 / 受伤时 "+1" / "-1" 的 **Label3D 飘字**都出现过(每帧采样才抓得到);
* `DEMO_ANIM ok=true triggers=23 plays_during_spam=1 total_plays=2` ——
  **先放完再重复**:重开之后连按 E 约 23 次(1.0~1.4 秒里每帧一下,
  而敌1 的抖动动画有 0.83 秒),动画**只开播一次**、当前这一轮没被打断;
  等它放完(1.83 秒)再按一下,才接着播下一轮。播放次数是探针监听
  `AnimationPlayer.animation_started` 数出来的;
* `DEMO_RELOAD ok=true` —— 按 R 之后:金币数回 0、血量回 3、金币回到场上、角色在出生点;
* 生成物层面:脚本里有 `int(clampf((金币数 + 1.0), 0.0, 5.0))`(计数 + 夹范围)、
  `金币火花.restart()`(粒子)、
  `reload_current_scene`(重开)、`Time.get_ticks_msec() - _gk_cd_ticks`(无敌帧)、
  `_gk_num_text(血量)`(数字转文字)、`节点_敌2.move_and_slide()`(追击)、
  `velocity.move_toward(`(加速)、`.length() <= 1.2`(到达)、
  `func _gk_flash_3d(…)`(闪红)、`Label3D.new()`(飘字)、
  `_gk_find_animation_player(节点_敌1)`(从物体找播放器)、
  `current_animation != _anim`(在播就跳过)、
  HUD、闪白、时间轴轨道;`.tscn` 里有粒子节点、`Colliders` 容器、环境脚本、
  以及 `敌2` 的 `CharacterBody3D`;`art/World.glb` 里有动画 `敌1抖动`。

`scripts/build_and_test.ps1` 里它也是**第 4 个端到端**关卡(会先用真 Blender
重建示例再跑探针 —— 只查仓库里那份旧产物等于没测)。

## 四、第二十四轮(做这个示例时)挖出来的问题

写在 `docs/待办清单.md` 的"第二十四轮"里,简单说:

1. **插件 bug**:`@onready` 引用只按"节点路径"去重、**忽略类型** ——
   同一个物体先被『移动_设置位置』(Node)引用、再被『进入区域』(Area3D)引用时,
   触发器拿到的是 Node 类型的变量,运行时对着**网格**调 `body_entered`,
   触发器整个失效(探针抓到的 `Invalid access … 'MeshInstance3D'`)。
2. **插件 bug**:环境脚本的"碰撞代理同步"在道具被**销毁之后**每帧报
   `Trying to assign invalid previously freed instance`(吃掉金币就刷屏)。
3. **两条虚惊告警**(『数学_运算』写回 int 变量 / 数字写 bool 变量)现在安静了;
   顺手修掉一个**静默 bug**:给布尔变量接数值表达式时,旧代码会把表达式
   丢掉、生成恒 `false`。
4. **示例脚本自己的两个坑**(都写成注释记档了):同一个界面节点不能同时挂在
   两条执行链上(执行流只认一条入口);节点图里的坐标是 **Godot 坐标**
   (Blender(x,y,z) → Godot(x, z, -y)),直接把 Blender 坐标填进
   『移动_设置位置』会把角色送到地板**下面**。

## 五、第二十五轮:拿它当"常用件"的试验场

用户看完这一关说"做游戏常用的东西还不够",于是补了四个节点,并全部在这关里用上:

| 新节点 | 解决的问题 | 在这关里的位置 |
|---|---|---|
| 『移动_朝向目标』 | 追人/跟随。原来要自己拼"方向向量 + 速度 + 滑动"三四个节点 | 敌2 追玩家 |
| 『变量_增减』 | 计数/扣血。原来"读取 + 数学 + 设置"三个节点 | 金币 +1、血量 -1 |
| 『流程_冷却』 | 重复触发。触发区/子弹会在窗口里连着触发,动画、扣血、音效跟着重来 | 两条受伤链的无敌帧 |
| 『文本_数字』 | HUD 显示。Godot 的 `str(3.0)` 是 `"3.0"`,直接拼会显示"血量 2.0" | 两行 HUD |

**又挖出一个插件 bug(这次是探针硬抓到的)**:

追击敌人**根本不动** —— 探针打出 `chaser_at=(0.0, 0.7, -2.5)`,而速度明明是 2.2。
根因在导出的环境脚本:它每物理帧把**碰撞代理对齐到网格**(第十五轮为了
"门动得了网格、动不了碰撞代理"加的),方向是**单向**的。用 velocity +
`move_and_slide` 推着走的道具,每帧被拽回原处,净位移为零。

修法:**谁动了谁说了算** —— 配对时记下上一帧两边各自的变换,这一帧谁变了
就让另一边跟过去(网格动了 = 场景动画,代理跟;代理动了 = 游戏逻辑在推,网格跟)。
修完探针实测:敌2 从 14.92 米追到 12.09 米,而且**看得见的红方块也跟着在动**
(以前网格根本不动,只有判定在跑)。

## 六、第二十六轮:常用件再补一批(126 → 133 个节点)

你选的方向是"再补一批常用件"。这一轮五处改动,四处在关卡里直接用上了:

| 改了什么 | 在这关里的位置 |
|---|---|
| 『移动_朝向目标』加『**到达**』输出 | 敌2 的"贴上了吗"不再挂『取值_距离』+『逻辑_比较』,直接读『到达』(= 距离进了『停在多远』1.2 米)|
| 『移动_朝向目标』加『**加速**』 | 敌2 的起步/刹车变成平滑的(6 米/秒²),不再瞬起瞬停 |
| 『变量_增减』加『**限制范围**』 | 血量夹 0~3、金币夹 0~5 —— 扣血扣到底就停在 0(`clampf`)|
| **『特效_闪红』**(新节点) | 挨打时玩家整个模型红 0.25 秒,时间到自动还原 |
| **『界面_飘字』**(新节点) | 金币处飘 "+1"、玩家头顶飘 "-1";一次性 Label3D,飘完自删 |

几个"踩过才知道"的设计(详见 `docs/待办清单.md` 第二十六轮):

* **老图产物一个字不变** —— 『限制范围』不勾、『每几次放行一次』=1、『加速』=0 时,
  生成的和以前逐字一样(第二十五轮那批断言原样通过);
* 『到达』是**自包含表达式**:在别处被读时用位置 helper 重算一遍,不依赖语句里的临时变量;
* 闪红借的是 `material_override`(**整网格**这一层):卡通材质走的是逐槽
  `set_surface_override_material`,整网格那层空着,正好拿来"整体染色"再还原;
  连着闪两次时先到期的不会把后一次的红提前抹掉(还原前先比对材质);
* 飘字挂在 `current_scene` 上 —— 金币自己会被 `queue_free`,挂在它下面会跟着消失。

## 七、第二十七轮:"先放完再重复"一键化(133 → 136 个节点)

用户最早那句"重复触发时会重复开始动画,想让它先放完再重复",这一轮做成一键:

| 改了什么 | 在这关里的位置 |
|---|---|
| 『动画_播放』的『混合模式』改名 **『重复触发时』**,选项改成『从头重播』/『**先放完再说(在播就跳过)**』 | 按 E 那条链用的是『先放完再说』 |
| 修 bug:『动画播放器』填**物体名**时,以前直接把物体当播放器用 → 运行时对 `Area3D` 调 `has_animation` 报错、**整条链断掉** | 这条链填的就是"敌1",走新路(从敌1 开始找它的 AnimationPlayer) |
| 敌1 多了一条真动画(Blender Action:0.83 秒的"被拍扁再弹回来") | 按 **E** 拍一下敌1 就能看到 |

> **为什么这条链要"填物体名"**:glTF 里 AnimationPlayer 藏在**模型实例内部**,
> 场景里根本选不到它 —— 能选的只有物体(敌1)。所以正确做法是
> "从那个物体开始找播放器",而不是把物体当播放器。

**这也是这关第一次有"真动画"**:以前示例里一个动画都没有,现在
"Blender 里打关键帧 → glb → Godot AnimationPlayer → 『动画_播放』"这条路
被探针整条验证了(连命名都对得上:`list=["敌1抖动"]`)。
