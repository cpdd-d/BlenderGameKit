# 网络联机示例(房间 + 自定义消息)

打开 `联机示例.blend` 就能改这两张图;用 Godot 打开 `联机示例_godot` 按 **F5** 就能看
(建议同时开两份工程、或者干脆开两个进程,一个开房一个加入)。

## 这一关在看什么

用 Godot 自带的 **ENetMultiplayerPeer**(局域网 / 直连:一个 IP + 一个端口)
做最小的"房间 + 自定义消息",**不引任何第三方服务**。两个 Blender 场景
各导出一张 `.tscn`:

| 场景 | 节点图 | 干什么 |
|---|---|---|
| `联机房间.tscn` | 房间逻辑 | 『联机_开房』;有人进来就单发欢迎语;收到消息就打印 + 回一条;有人走了记一行日志 |
| `联机客户端.tscn` | 客户端逻辑 | 『联机_加入』;收到消息就打印 + 回一条(只回一次);3 秒后『联机_断开』 |

七个节点(分类『网络』):

| 节点 | 类型 | 引脚 |
|---|---|---|
| 联机_开房 | 动作 | 属性:端口 / 最多几个人 |
| 联机_加入 | 动作 | 属性:主机地址 / 端口 |
| 联机_断开 | 动作 | —— |
| 联机_发消息 | 动作 | 输入:执行 / 内容 / 发给谁;属性:频道 / 发给(所有人 或 某个玩家) |
| 有人进来 | 事件 | 输出:执行 / **谁**(玩家编号) |
| 有人走了 | 事件 | 输出:执行 / **谁** |
| 联机_收到消息 | 事件 | 输出:执行 / **谁发的** / **内容**;属性:频道 / 任何频道都接 |

## ⚠ 一条必须记住的硬规矩:RPC 靠"节点路径"找对端

Godot 的 `@rpc` 是按**节点在场景树里的路径**把调用送到对端的。所以主机和
客户端必须跑**同一张场景**(同一个 `.tscn`、同样的节点结构)—— 换的只是节点图
里的『联机_开房』/『联机_加入』。两张场景结构不一样时,连得上,但**消息收不到**:

```
ERROR: Node not found: "CLI" (relative to "/root").
ERROR: Failed to get path from RPC: CLI.
```

(真机实测过。本示例的两张场景根节点名不同,所以**不要**拿它们互相连 ——
想自己玩,复制一份场景、把『联机_开房』换成『联机_加入』,或者按下面
"想自己玩"的第 3 条做。)

## 自定义消息的对外约定

『联机_发消息』发出去的东西走**一个固定通道** `_gk_net_msg`,参数是
`(频道, 发送者编号, 文本)`。想用别的脚本(甚至别的语言写的服务端)跟它通信,
照着这个签名实现就行:

```gdscript
@rpc("any_peer", "call_remote", "reliable")
func _gk_net_msg(channel: String, sender: int, text: String) -> void:
    ...   # 你的处理
```

* **频道**:两边填一样的名字才能对上(本示例用 `聊天`);
* **发送者编号**:发送方自己填进来的(不靠 `get_remote_sender_id()`),所以
  "谁发的"永远可控;
* **发给所有人**:`rpc(...)` = 房间里**除自己以外**的每个人(和 Godot 语义一致,
  **发的人自己不会收到**);**发给某个玩家**:`rpc_id(...)` —— 把『有人进来』的
  『谁』接到『发给谁』上即可。

## 生成出来的代码长什么样

整棵图照旧导出成一个 `game_logic_<场景>.gd`,里面多出这几样:

```gdscript
var _gk_net: ENetMultiplayerPeer = null
func _gk_net_start(server, ip, port, max_clients)   # 开房 / 加入
func _gk_net_stop()                                  # 断开
func _gk_net_send(channel, to_peer, text)            # 发消息
@rpc("any_peer", "call_remote", "reliable")
func _gk_net_msg(channel, sender, text)              # 收消息(固定通道)
```

各事件节点(有人进来 / 有人走了 / 收到消息)各是一条独立的执行流函数,
信号 / RPC 分发在 `_ready` **最前面**接上(排在用户的『等待_秒』前面)。

## 想自己玩

1. **同一台电脑**:开两个 Godot 实例,`project.godot` 的 `run/main_scene` 指到
   `res://scenes/联机房间.tscn` 跑一个(开房),再复制一份工程、把它指到
   `res://scenes/联机客户端.tscn` 跑一个(加入 127.0.0.1);
2. **两台电脑**:客户端那张图里把『主机地址』改成主机的 LAN IP,端口两边
   填一样(本示例是 47777);
3. **同一张场景既能开房又能加入**(正规做法):复制场景、只把『联机_开房』
   换成『联机_加入』—— 节点结构完全一样,RPC 路径就对得上。

## 不在这一版里

位置 / 状态同步、房间列表、匹配、鉴权、断线重连 —— 都没有。
"谁在哪儿"这类同步要靠『联机_发消息』自己按帧发。协议是可靠的
(`reliable`),适合聊天 / 指令 / 事件,不适合每帧刷位置。

## 自动检查 / 重建

```powershell
python scripts\check_net_demo.py        # 探针(要 Godot):同机两个进程真连一次
blender -b --python scripts\make_net_demo.py   # 重建 .blend + 工程
```

> 门禁(`scripts\build_and_test.ps1`)的 5t 层跑的就是上面两条,探针标记
> `CHECK_NET_DEMO=OK`。
> 探针怎么做的:把示例场景**复制一份、只把游戏脚本换成 `peer.gd`**当"对端"
> —— 节点结构逐字节一致,`@rpc` 的路径才对得上;然后**真起两个 Godot 进程**
> (一个开房一个加入),按控制台日志断言"连上 / 收到事件 / 收发消息 / 断开"。
