# 集合层级示例(第一百零二轮)

Blender 里把物体分进**集合**,导出后 Godot 的场景树里就是**同名节点分组** ——
东西一多,不用在一个大平铺列表里找。

Godot 里打开 `集合层级示例_godot`,场景树是:

```
World (glb 实例)
  房间A                 ← 集合『房间A』
    A_墙 / A_桌子
  房间B
    架子                 ← 集合里还能套集合
      架子_板1 / 架子_板2
  地面 / 侧视机位 …      ← 直接放在场景根集合里的物体:直接在 World 下
  Scene Collection       ← 只有"和分组撞名"时才保留这一层
    Colliders            ← 你建的集合就叫 Colliders(和碰撞分组重名)
      重名方块
  Colliders              ← 导出生成的碰撞代理(物理体,不是集合)
    ...
```

## 怎么看

用 Godot 打开 `集合层级示例_godot` 文件夹,按 **F5**。

| 按键 | 作用 |
|---|---|
| WASD | 走动(按 D 会撞上『房间A』的墙) |
| 空格 | 跳 |
| 鼠标 | 转视角 |
| C / V | 俯瞰 / 侧视机位 |
| Tab | 上帝机 |

## 这一关用到了什么

| 能力 | 在游戏里怎么看 |
|---|---|
| **Blender 集合** | Godot 场景树里的同名分组节点(`房间A/...`) |
| **嵌套集合** | 分组里再分组(`房间B/架子/...`) |
| **根集合里的物体** | 直接在 World 根下(地面 / 相机) |
| **空集合** | **不会**出现在 Godot 里(Blender 导出时丢掉) |
| **撞名集合** | 保留一层 `Scene Collection/` 前缀,免得和碰撞分组打架 |

三条容易被问到的行为(Blender 原生语义,导出时不做加工):

* 一个物体**同时在多个集合**里时,它归到**第一个**集合;
* 物体和它的父物体**不在同一个集合**里时,导出后父子关系会被拉平
  (位置、大小不变,只是不再"跟着父动");同一个集合内的父子关系完整保留;
* 集合是**纯分组**,在 Godot 里没有自己的变换,不会挪动物体位置。

## 怎么重新生成

```
blender -b --python scripts\make_groups_demo.py
```

## 自动检查

```
python scripts\check_groups_demo.py
python scripts\check_groups_demo.py --godot "D:\godot\Godot_v4.7.2-stable_win64_console.exe"
```

探针真跑 Godot,断言:`房间A/A_墙`、嵌套的 `房间B/架子/架子_板1` 都能用
**路径**取到(验的是层级,不只是"找得到");直接放根集合的物体在 World 根下;
撞名集合保留前缀、碰撞分组照常在根下;空集合不存在;角色按 D 走到墙边
**被挡住**(分组没把碰撞弄坏)、卡通材质照样挂上(8 个材质覆盖)。
结论行 `CHECK_GROUPS_DEMO=OK`,这一层接进门禁 **5u**。
