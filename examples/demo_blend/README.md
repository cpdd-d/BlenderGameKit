# 动画混合树示例(第六十一轮)

一个会"走↔跑"**连续过渡**的方块。

两块动画:**『走』晃 0.2 米**、**『跑』晃 2 米**。按 **1** 切到走、
按 **2** 切到跑 —— 注意它不是"啪"地换过去,而是**连续混过去**
(参数从 0 滑到 1,姿势是两段动画按比例叠的)。这就是混合树相对
状态机(硬切)的意义。

## 怎么看

用 Godot 打开 `混合示例_godot` 文件夹,按 **F5**。

| 按键 | 作用 |
|---|---|
| **1** | 混合位置 = 0(完全『走』,小晃) |
| **2** | 混合位置 = 1(完全『跑』,大晃) |
| Tab | 上帝机 |

## 这一关用到了什么

| 能力 | 在游戏里怎么看 |
|---|---|
| **动画_混合树** | 建一个 **AnimationTree + AnimationNodeBlendSpace1D**,混合点 `走:0\|跑:1` |
| **参数** | 『参数』引脚接了 `混合位置` 变量;每物理帧推给 `parameters/blend_position` |
| **变量_设置 + 常量_数值** | 按 1 / 2 把混合位置设成 0 / 1 |
| **循环播放** | 建树时把两段动作设成循环(glTF 导进来的动画默认不循环,播一遍就停) |
| **平滑秒数** | 本关为 0(立刻到);想"慢慢混过去"就填 > 0(比如 0.15) |

## 怎么重新生成

```
blender -b --python scripts\make_blend_demo.py
```

## 自动检查

```
python scripts\check_blend_demo.py
python scripts\check_blend_demo.py --godot "D:\godot\Godot_v4.7.2-stable_win64_console.exe"
```

探针真跑 Godot,断言:方块上真的建出了 AnimationTree;混合位置 0 时
最高只抬到 ~1 米、1 时能抬到 ~3 米(两段动画都进了 glb,且参数真的
起作用);**0.5 时高度落在两者之间**(是"混"不是"二选一");
按 1 / 2 能把混合位置改成 0 / 1。结论行 `CHECK_BLEND_DEMO=OK`,
这一层接进门禁 **5p**。
