# 动画状态机示例(可直接照抄)

打开 `动画状态机示例.blend` → 节点编辑器左上角把类型切成 **游戏动画**,
看到的就是这张树「**角色动作**」。

> 这个 `.blend` 用 `scripts\make_anim_example.py` 生成,可以随时重新生成:
> ```powershell
> blender -b --python scripts\make_anim_example.py
> blender -b --python scripts\check_anim_example.py     # 自查(13 项)
> ```
> 整条链路(含真 Godot 跑 1.5 秒)一键验证:
> `powershell -File scripts\verify_anim_system.ps1`

**这张示例演示了十三件事**(每件都能直接照抄):

1. 一个状态**多条出线**,按画布上下顺序判定
2. **状态直连 = 播完就切**(不用放转场节点)
3. **状态的『进入时』/『离开时』**执行流(设布尔变量)
4. 一个状态**同时播多段动画**(骨骼 + 形态键)
5. **自定义变量**当转场条件(动画树声明、玩法图/状态自己改)
6. **『动画_播放完成』**拼复合条件("播完了 并且 在地面")
7. **时间轴**:『定时_缓动属性』动任意属性(视野 fov 变化)
8. **丝滑切相机**:『相机_切换』的过渡秒数
9. **『动画_开始』开始口**:显式指明起始状态 + 开始条件可自定义
10. **『动画_结束』结束口**:演完就收工,玩法图用『动画_运行状态』读到"已结束"
11. **按一下键就绑定**:『输入_按键』(按住/刚按下/松开一个顶三个)
12. **一张卡片设多个变量**:每个『值』引脚接不同的节点
13. **摄像机套件**:弹簧臂跟随(不穿墙)、相机_设置(视野+视距)、启用/禁用

### ⑬ 摄像机套件(照虚幻的 Camera + SpringArm)

```
[每当_准备] ──> [动画_状态机] ──> [相机_弹簧臂] ──> [特写机位设置(相机_设置)]

[每当_物理帧]
  ├─ 如果(刚按下 C) ─是─> [相机_切换 特写机位 过渡0.6] ──> [缓动 fov→34]
  └─ 如果(刚按下 V) ─是─> [相机_启用 特写机位=禁用] ──> [相机_切换 主相机 过渡0.5]
```

| 节点 | 一句话 |
|---|---|
| **相机_弹簧臂** | 相机挂在一根"会缩的杆子"上:平时退到『臂长』,**撞到墙就缩短** —— 第三人称/越肩视角不穿墙的关键。参数对照虚幻:`臂长`=TargetArmLength、`高度/侧向偏移`=SocketOffset、`俯仰`=杆子下压角度、`碰撞检测`=bDoCollisionTest、`平滑`=CameraLag |
| **相机_设置** | 一次设好 **视野**(fov / 2D 的 zoom)+ **视距**(沿相机朝向推远多少),带平滑就是渐变过去 |
| **相机_启用** | 启用 = 切到它;禁用 = **只有它正开着才摘下来**(不然会把别人的画面弄黑) |
| **相机_切换** | 换当前相机;『过渡(秒)』= 丝滑推镜 |
| **相机_位置 / 相机_旋转** | 两种给法:**向量**引脚,或 X/Y/Z(偏航/俯仰/翻滚)**浮点**;『保留』= 相对加,『直接设』= 绝对。旋转还带"限制俯仰 ±89°"(第一人称转视角必备,不然会翻过头) |
| **相机_取状态** | 读当前相机:名字 / 位置 / 朝向 / 视野 / 开着吗 —— 给逻辑判断用 |

**多台相机 / 分支场景**:每台相机各放一个『相机_设置』『相机_启用』,
用『如果_否则』按条件挑一支走 —— 想按关卡切机位就这么写。

> 弹簧臂的"不穿墙"是真跑验证过的:杆子 5 米、身后 2 米一堵 1 米厚的墙,
> 相机停在 **1.20 米**(墙面 1.5 − 碰撞半径 0.3)。

### ⑨⑩ 开始口 / 结束口 —— "从哪开始、到哪算完"

```
[动画_开始]  ● 开始 ─────> [动画_状态 待机] ● 进入      ← 显式起点
  开始方式: 立刻开始 / 变量为真 / 刚按下某键 / 上一个动画播完 / 自己接条件引脚

[动画_状态 攻击] ● 转到 ──> [动画_结束] ● 进入           ← 演完了就收工
```

* **开始口**让"起始状态"变成**写明的事**,不再靠"谁没被转场指到"去猜
  (图一大就猜不准)。『开始方式』就是**自定义的开始条件**:
  一个变量为真、刚按下某个键、上一个动画播完,或者自己拉个判断节点接上去。
  条件不成立时整张图**不动**;成立才开始播第一个状态。
* **结束口**表示"这段动画演完了"。走到它的时候状态机收工
  (`_gk_anim_done = true`),并且**不再判转场** —— 所以玩法图有稳定的时机
  去读它。开始条件再次成立时会重新开始。

### ⑪ 按一下键就绑定(照 UPBGE 的 Keyboard Key)

```
[输入_按键]  触发方式: [刚按下 ▾]   按键: [C]  [🔑按一下键]   输入动作: switch_camera
```

* **一个节点顶三个**:按住 / 刚按下 / 松开(UPBGE 的 `Tap` 下拉)
* 点 **『按一下键』**,按哪个键就绑哪个 —— 不用记"jump 绑空格"这套约定
  (动作名留空会按按键名自动生成,比如 `key_w`)
* 捕获到的键导出时会写进 `project.godot` 的输入映射:
  **你在 Blender 里按 C,Godot 里 C 就真的能用**(示例已验证 `physical_keycode: 67`)

### ⑫ 一张卡片设多个变量(照蓝图 Set 节点)

```
[变量_设置]  变量数 = 2
   1. is_attacking  ← [常量_布尔 假]
   2. combo_ready   ← [常量_布尔 真]      ← 每个值引脚接**不同**的节点
   ● 完成 ──> 后面的判断节点
```

布尔变量如果不小心用数字框填了 `0/1`(那个框只能填数字),导出时会转成
`false/true` 并提醒你接『常量_布尔』—— 不会生成 `is_hurt = 0.0` 那种
让整个脚本加载失败的代码。

## 一、这张树长什么样

```
动画判断_移动状态 ──┬─ 在地面 ──┐
                    ├─ 在移动 ──┼──────────┐
                    ├─ 速度快 ──┼────────┐ │
                    └─ 速度慢 ──┼──────┐ │ │
                               │      │ │ │
动画_取变量(is_hurt) ───────────┼──────┼─┼─┼──┐
输入_按键刚按下(jump) ─┐        │      │ │ │  │
                      ├─ 与 ───┼──────┼─┼─┼──┼──┐
动画判断(在地面) ──────┘        │      │ │ │  │  │
                               ↓      ↓ ↓ ↓  ↓  ↓
                            ┌──────────────────────┐
                            │ [动画_状态 待机]      │  ← 起始状态(没有转场指向它)
                            │   ● 转到             │
                            └──────────────────────┘
```

状态一共 6 个:**待机 / 走 / 跑 / 跳 / 受击 / 攻击**,
名字就是**动画名**(导出后 Godot 的 `AnimationPlayer` 里就是这些)。

### 一个状态多条出线(这张树最重要的地方)

「待机」有 **4 条**出线,画布上从上到下依次判定:

| 顺序 | 条件 | 切到 |
|---|---|---|
| 1 | `is_hurt`(自定义布尔变量) | 受击 |
| 2 | 刚按下 `attack`(节点上直接选输入) | 攻击 |
| 3 | 刚按下 `jump` **与** 在地面 | 跳 |
| 4 | 在移动 | 走 |

「走」有 3 条出线(速度快→跑 / 速度慢→待机 / is_hurt→受击),
「跑」有 2 条。**一帧只走一步**,第一个成立的条件赢 —— 和虚幻 5 一样。

### 状态直连 = 播完就切

```
[动画_状态 受击] ● 转到 ──────> [动画_状态 待机] ● 进入
[动画_状态 攻击] ● 转到 ──────> [动画_状态 待机] ● 进入
```

中间**不放转场节点**:意思是"这个动作播完就切回待机"。
(和 Godot 自己的 `AnimationNodeStateMachine` 的 auto-advance 一个意思。
动画设成循环的话它永远播不完,也就永远不切。)

### 自定义变量当条件

树的『变量』面板里声明了三个:

| 变量 | 类型 | 谁改它 | 谁读它 |
|---|---|---|---|
| `is_hurt` | 布尔 | **状态的『进入时』/『离开时』**(自己维护) | 「待机/走/跑 → 受击」的『条件』引脚 |
| `is_attacking` | 布尔 | 同上(攻击状态) | — |
| `walk_speed` | 浮点 | — | — |

**要点**:变量在动画树里声明,在两张图里都能改 ——
两张图编译成**同一个脚本**,变量是同一个:

* **动画树里**:接在状态的『进入时』/『离开时』后面(见下面"设置布尔变量")
* **游戏逻辑图里**:用『变量_设置』(接『常量_布尔』给真假值)

动画树里的『动画_取变量』把它拉出来接到转场的『条件』引脚上,就成了转场条件。

### 状态的『进入时』/『离开时』——"设置布尔变量"就写在这里

每个状态都有**两个做事的出口**(照虚幻 5 的 State Entry / State Exit):

```
[动画_状态 受击] ● 进入时 ──> [动画_设变量 is_hurt = 真]
                 ● 离开时 ──> [动画_设变量 is_hurt = 假]
```

这张示例里「受击」「攻击」都这么接。好处是**标志位由状态自己维护** ——
进这个状态就置真、离开就置假,不用在玩法图里算计时器
(用『等待_秒』去清标志会 `await`,把同一帧后面的移动逻辑一起挂起)。

> ⚠ **不要**把『动画_设变量』接在状态的『转到』上 ——
> 『转到』是"去下一个状态"的意思。导出时会明确告警,告诉你去用这两个出口。

### 一个状态**同时播多段动画**

状态节点上有『同时播 2』『同时播 3』两个动作槽。填了就额外开一个播放器
把那段动画**一起播**:

```
[动画_状态 攻击]
   动画: 攻击             ← 主播放器
   同时播 2: 形态键动作    ← 自动开第二个播放器
```

**为什么需要它**:Godot 的 `AnimationPlayer` 一次只能播一段(`play()` 会把
上一段顶掉)。MMD 这类模型把**骨骼动作**和**形态键动作**分成两段,要看完整
动作必须同时播 —— 两层播放器各播各的,互不干扰;切走时自动把多播的停掉。

### 『动画_播放完成』——"上一个播完了吗"是个节点

```
[动画_播放完成 攻击] ──┐
                       ├─ 与 ──> 转场『条件』
[动画判断_移动状态 在地面] ┘
```

- 在**动画树**里:和『逻辑_布尔运算』拼成复合条件(播完了**并且**在地面)
- 在**玩法图**里:`如果(动画_播放完成) -> 变量_设置`,做"播完就清标志/发奖励"

标志会**一直保留到下一段动画开始播**(进新状态、或者任何 `play()` 都会清),
所以不用担心"只在那一帧有效"而错过。

> 别自己写 `current_animation == "X" and not is_playing()`:Godot 在一次性
> 动画播完时会把 `current_animation` **清成空串**,那个条件永远不成立
> (实测,见主 README 第 22 条)。

### 时间轴 / 相机(示例里也有)

| 玩法 | 怎么接 |
|---|---|
| **视野变化** | 『定时_缓动属性』:目标 = 相机、属性 = `fov`、到 = 45、时长 = 1.2 |
| **丝滑切相机** | 『相机_切换』:相机 = 特写机位、过渡 = 0.6(秒) |
| **场景动画** | 『定时_缓动属性』动任意属性:`position:y`(门升起)、`modulate:a`(淡出)、`light_energy`(灯变暗)… |
| **整体联动** | 几条缓动 / 几段动画**串在一起就行** —— Tween 和 `play()` 都是异步的,调用完立刻返回,所以天生同时进行 |

示例里 `每当_准备` 会把视野推到 45 度、再把机位丝滑推到「特写机位」;
按 **C** 也能切(过渡 0.6 秒 + 视野再推一次)。

### 一个状态能被几条转场指着?调『入口数量』

**Blender 一个输入引脚只允许一条连线**,所以多个转场指向同一个状态时,
后接的那条会把前一条顶掉。状态节点上的『入口 [N]』就是想接几条调到几,
引脚会变成 `进入 / 进入 2 / 进入 3 …`(调数量时已接的线会保住)。

### 玩法图这边读动画状态

```
每当_物理帧
  └─ 如果(动画_运行状态.已结束) ──是──> [变量_设置] 一次设两个变量
                                              ● 完成 ──> 后续逻辑
```

『动画_运行状态』给三个输出:**已结束 / 在跑 / 当前状态**(状态名,做分支和
调试都方便)。这就是"输出这一个游戏动画的布尔情况,以便于在游戏逻辑里判断
执行下一步逻辑"。

## 二、导出的脚本长什么样

```gdscript
func _physics_process(delta: float) -> void:
    ...
    if anim_state == "待机":
        if is_hurt:
            _gk_anim_enter("受击")
        elif Input.is_action_just_pressed(ACTION_ATTACK):
            _gk_anim_enter("攻击")
        elif (Input.is_action_just_pressed(ACTION_JUMP) and (self.is_on_floor())):
            _gk_anim_enter("跳")
        elif ((Vector2(self.velocity.x, self.velocity.z).length() > move_threshold)):
            _gk_anim_enter("走")
    elif anim_state == "走":
        ...
    elif anim_state == "受击":
        if (_gk_anim_finished == "受击"):     # ← 播完就切
            _gk_anim_enter("待机")
    _gk_anim_finished = ""
```

- **`_gk_anim_enter()`** 是"进入状态"的唯一入口:记状态 → 播动画 →
  找不到动画就打一条带**可用清单**的警告
- **`_gk_anim_finished`** 由 `animation_finished` 信号写入,只活一帧。
  (不能用 `current_animation == "X" and not is_playing()`:真 Godot 4.7 实测,
  一次性动画播完时 `current_animation` 会被清成**空字符串**,
  那个条件永远不成立 —— 状态机会卡在第一个状态)

## 三、照抄到你自己角色上的步骤

1. 把状态节点的『动画』换成你自己的动作(状态名自动跟着动作名走)
2. 状态的**入口数量**:一个状态要被几条转场指着,就把『入口 [N]』调到几
   —— Blender **一个输入引脚只允许一条线**,满了的话新线会顶掉旧的
3. 转场三件套:**上游**(从哪来)、**条件**(什么时候切)、**转到**(去哪)
   - 忘了接上游/转到?节点上有『从』『到』下拉兜底(连线优先)
4. 想要"播完就切":状态之间**直接连线**,不用放转场节点
5. 想用自定义变量当条件:侧栏『变量』加一个 → 动画树里拉『动画_取变量』
   → 接到转场『条件』;变量本身在**游戏逻辑图**里用『变量_设置』改
6. 出问题看三处:节点上、侧栏『游戏动画』面板、导出报告

示例角色是个方块(6 个动作是它的位移/缩放关键帧),所以"换动作"一眼能看见。
换成你自己的模型时,把方块换掉、动作名对齐即可。
