# 关卡示例(打开就能玩)

一条命令出 .blend **和**能玩的工程:

```
blender -b --python scripts/make_demo_level.py     # 存 .blend + 导出 game_godot/
```

然后用 Godot 打开 `game_godot/` → F5(主场景 = `scenes/关卡1.tscn`)。

也可以在 Blender 里:打开 `关卡示例.blend` → 侧栏『游戏逻辑』→
**导出为 Godot 脚本(勾选同时生成示例场景)**,或直接在节点编辑器里按 **F5**。

## 关卡长什么样

```
┌──────────────────────────────────────────┐
│ 北墙                                     │
│      ▓▓▓                                 │  ▓ = 高台
│   ▓▓ ▓▓▓ ▓▓      (中央高台上有一枚金币)   │  ● = 金币
│      ▨ ←电梯                             │  ▲ = 出生点
│  ●              ▓▓▓▓            ●        │  ═ = 终点门
│                                          │  ▨ = 电梯(会动的平台)
│   ▣ ←车          ▲               ═══     │  ▣ = 载具(能开)
│ 南墙                                     │
└──────────────────────────────────────────┘
   30 x 30 米,四面有墙(跑不出去)
```

- **5 枚金币**:走近(1.3 米内)就吃掉,分数 +1,金币消失
- **HUD**:左上角"金币 N/5" + 一行操作提示
- **电梯**(第三十一轮):贴着中央高台东面的会动平台,站上去**被抬到 2.4 米**,
  直接走到高台上拿那枚金币(以前只能跳上去)
- **载具**(第三十一轮):西南空地一辆能开的车 —— 走到旁边按 **E** 上车,
  `W/S` 沿车头开、`A/D` 打方向,再按 **E** 下车
- **集满 5 枚** → 屏幕中间"通关!按 Esc 退出",同时对外端口 `通关` 变真
- **通关演出** → 相机丝滑推镜(1.4 秒转场)→ 等运镜播完(1.6 秒)→
  **切换到第二关**(`res://scenes/关卡2.tscn` —— 它是 .blend 里的另一个
  **Blender 场景**,导出时由插件各出一张 .tscn,不是手写补的文件)
- **掉出地图**(掉到 -6 米以下)→ 送回出生点,不惩罚、不卡死
- **Esc** → 退出游戏

操作:`WASD` 移动 · `空格` 跳 · `鼠标` 转视角 · `C/V` 切俯瞰/侧视 · `E` 上/下车

## 节点图怎么连(『玩家逻辑』)

```
[每当_准备] ─> [鼠标_模式(锁定)] ─> [相机_设置(侧视机位,60°)]
                                     └─> [界面_文本(HUD标题)] ─> [界面_文本(HUD提示)]

[每当_物理帧] ─┬─> [移动_按方向(6m/s)]        ← [输入_方向](WASD 各按一下捕获)
               ├─> [如果(在地面 且 刚按下空格)] ─是─> [移动_跳跃]
               ├─> [相机_跟随]                 ← 跟随侧视机位
               ├─> [相机_旋转(保留)]            ← 鼠标位移 × 帧间隔 × 0.12
               ├─> [如果(刚按下 C)] ─是─> [相机_切换(俯瞰)]
               ├─> [如果(刚按下 V)] ─是─> [相机_切换(侧视)]
               ├─> [如果(自己的 Y < -6)] ─是─> [移动_设置位置(出生点)]
               ├─> [如果(刚按下 Esc)] ─是─> [流程_退出游戏]
               └─> 金币拾取 ×5:
                     [取值_距离(甲=自己 乙=金币N)] ─> [逻辑_比较(<1.3)] ─> [如果_否则]
                        └─是─> [实例_销毁(金币N)] ─> [变量_读取(金币数)]
                                                      └─> [数学_运算(+1)] ─> [变量_设置(金币数)]
                                                            └─> [文本_拼接]×2 ─> [界面_文本(刷新HUD)]
                                                            └─> [如果(金币数 >= 5)] ─是─> [逻辑_输出结果(通关)]
                                                                                          └─> [界面_文本(通关提示)]
                                                                                          └─> [相机_切换(转场机位,过渡1.4s)]
                                                                                                └─> [等待_秒(1.6)]
                                                                                                      └─> [场景_切换关卡(关卡2.tscn)]
```

**对外端口**(侧栏『对外端口』):

| 端口 | 类型 | 含义 |
|---|---|---|
| `金币数` | 浮点 | 收集到的金币数(HUD 和别的图都读它) |
| `通关` | 布尔 | 集满 5 枚 |

别的逻辑图用『变量_读取』填 `输出_金币数` / `输出_通关` 就能读到 —— 这就是跨图联动。

## 这一轮顺手修掉的真 bug

做关卡的过程把几个"平时看不出来"的问题全暴露了,都修了:

1. **中文变量名会撞车** —— `snake_case` 把中文压成下划线,于是『金币数』和
   『通关』**都变成 `v`**,生成 `var v: float = false`(类型和值都对不上),
   Godot 直接解析失败。
   实测 Godot 4.7.2 **接受 Unicode 标识符**,现在中文原样保留 ✓
2. **端口变量和用户变量是两份** —— 声明端口生成 `输出_金币数`,而
   『变量_设置(金币数)』生成另一个 `金币数`,端口永远停在初值。
   现在端口**先声明**并登记别名,两者是同一个变量 ✓
3. **浮点写进整数变量** —— `var x: int` + `x = (x + 1.0)` 会让 Godot 拒绝加载。
   现在自动补 `int(...)` 转换(蓝图里本来就是隐式的)✓
4. **节点图存盘丢失** —— 忘了 `use_fake_user`,重新打开 .blend 发现
   "节点图数量 = 0"(踩过的坑,README 里有,这次又忘了)
5. `bl_icon = "TRANSFORM_MOVE"` 不是合法图标 → 整个节点注册失败
6. 脚本里 `read_factory_settings` 会把插件一起卸载 → 之后建不了 GK 节点图

## 第二十三轮:默认观察相机(你要的"虚幻那种")

场景里**一台相机都没有**时,以前画面全黑 —— 看起来就是"游戏没跑起来",完全不知道角色在动没动。
现在 `_gk_current_camera()` 会在这种情况下**当场造一台**:

```gdscript
func _gk_make_fallback_camera(host: Node) -> void:
    var cam := Camera3D.new()
    cam.name = "GK默认观察相机"
    host.get_tree().root.add_child(cam)
    # 挂在角色后上方 4 米、略微俯视 —— 够看清发生了什么
    ...
    cam.make_current()
    push_warning("[GK] 场景里没有相机 —— 临时造了一台 GK默认观察相机")
```

这样"没指定相机"不再等于"什么都看不见",控制台也会说清这是兜底的。

## 第二十四轮:你报的六条

| 你反馈的 | 处理 |
|---|---|
| **侧边栏东西太多** | ① 逻辑图面板里的 **『动作分类』盒子删了**(它只对动画树有意义) ② **『添加节点』按钮删了**(Shift+A / 右键都在) ③ **『导出设置』折起来了**(3D/2D、基类、类名这些开一次就不用动) |
| **默认相机应该能到处飞、不受碰撞** | 改成**自由飞行观察机**(照虚幻的 Spectator):`WASD` 平移、`空格` 上升、`Shift` 下降、鼠标转视角;直接改坐标**不走物理**,想穿墙就穿墙 |
| **第三人称应该绕角色 360 度、穿模时缩短** | 关卡换成 **『弹簧臂』** 节点:杆子挂在角色身上,鼠标转的是杆子朝向 -> 相机在杆子末端,**360 度想转哪转哪**;射线撞到墙/地面就自动缩短 ✓ |
| **相机旋转灵敏度太低** | **真 bug**:『鼠标_移动量』给的已经是"这一帧多少像素",我却**又乘了一次帧间隔** -> 数值被除以 60,慢得离谱。现在就是 `像素 × 0.25`(鼠标移 100 像素转 25 度) |
| **卡通渲染应该有开关** | 导出盒子加了 **『卡通材质』勾选**。关掉 = 按 Blender 原样导出 PBR 材质,运行画面和预览就一致了,可以核对细节 |
| 现在就开始改 | ✓ 都在这一轮里 |

### 灵敏度这条的教训

`鼠标_移动量` 的语义变过一次(速度 -> 每帧位移),但**乘 delta 的老写法留在了示例里** ——
"每帧位移"再乘"每帧秒数",等于把它当成"每秒位移"处理,数值被除以 60。
**改语义时要回头检查所有使用者**(这次两处示例都中招)。

## 第三十一轮:电梯 + 载具(能玩的版本)

把第三十轮的"移动平台 / 可驾驶载具"接进这一关,顺手抓出两个**只有整关跑起来
才看得见**的 bug:

| 坑 | 表现 | 修法 |
|---|---|---|
| **多场景导出的输入映射被最后一个场景覆盖** | 关卡1 新加的 `E 上车` 完全没反应(工程里 `[input]` 只有关卡2 的动作 —— 每个场景各重写一次标记块,后写的赢) | `export_all_scenes` 把各场景的动作**并起来**最后写一遍(见 `asset_export` 第三十一轮注释) |
| **电梯甲板 0.4 米高,角色上不去** | Godot 的运动学角色不会自己上台阶 —— 电梯在旁边,走上去却被"一堵墙"挡住 | 关卡的角色移动节点填上『上台阶高度』= 0.5(第二十九轮那个能力) |

自查脚本这一轮也升级了:不只看生成物,还**在真 Godot 里跑一段** ——
把角色放到电梯上、等它升到顶(断言角色升高 ≈ 电梯升高),再走到车旁按 E
上车开 1 秒、按 E 下车走两步(断言角色全程钉在座位上、下车后能走)。
这两行 `LEVEL_LIFT / LEVEL_CAR` 就是它跑出来的实数。
