# AI 绕墙追击示例(第六十三轮)

> 一句话:**敌人是纯 AI 驱动的,它自己会绕开墙追你** —— 图里**一个
> 『移动_寻路』节点都没有**。

## 场景长什么样

一堵 **5 米宽的墙**把『敌人』和『玩家』隔开(两者在 Godot 里 z 差 4 米,
直线距离只有 4 米),中间是墙。敌人每帧朝玩家走 —— 如果**直线走**,它
会一头顶在墙上贴住,永远追不上。

场景设置里勾了『寻路』(侧栏 →『导出脚本』→『寻路』),于是在启动时按
静态碰撞体烤了一块导航网格。**敌人的追击行为会自动改走导航网格算出来的
方向**,从墙端绕过去追到人。

## 按键

| 键 | 作用 |
|---|---|
| **Tab** | 在玩家相机和上帝摄像机之间切(飞着看它怎么绕) |
| **WASD / 空格 / Shift / 鼠标** | 上帝机自由飞(切到上帝机时) |

## 这张图用了什么

| 节点 / 设置 | 说明 |
|---|---|
| **『AI_状态』(追击)** | AI 图『敌人AI』里唯一一个状态,目标 = 玩家 |
| **『AI_启用』** | 玩法图『AI寻路逻辑』里把它挂到**敌人自己**身上 |
| **场景设置『寻路』** | 总开关:它决定"有没有导航网格可走" |

## 怎么跑

```powershell
# 重建示例(.blend + Godot 工程)
& "D:\blender-4.5.5-windows-x64\blender.exe" -b --python scripts\make_ai_nav_demo.py

# 自动检查(不用 Blender,要 Godot):真跑一遍,量"它到底绕过没有"
python scripts\check_ai_nav_demo.py
```

探针断言四件事:

| 断言 | 意思 |
|---|---|
| `polys > 0` | 导航网格真烤出来了 |
| `around >= 2.8` | 敌人横着走出 2.8 米以上 = **从墙端绕过去**了 |
| `arrived` | 最后贴到玩家 1.5 米以内 |
| `state = 追击` | AI 状态机真的在跑 |

想自己看"直线走会怎样":把场景设置里的『寻路』取消勾选、重新导出 ——
敌人就会顶着墙原地推。

## 和『移动_寻路』的关系

『移动_寻路』是**手动**节点:要哪段逻辑绕墙,自己往那儿放一个。
这个示例说的是另一件事:**AI 的移动行为本来就走导航网格** ——
玩家用的是「AI_状态」的追击 / 跟随 / 去查看 / 巡逻 / 返回,不用额外拼。

⚠ 两个已知边界:

* **『逃跑』不接导航**(它是"背对威胁跑",没有固定目标点);
* 场景**没勾『寻路』**时,AI 的移动退回直线(和以前逐字一样)。
