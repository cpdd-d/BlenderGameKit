# 2D 寻路示例(俯视 2D:真绕障碍追人)

打开 `2D寻路示例.blend` 就能改这张图;用 Godot 打开 `2D寻路示例_godot` 按 **F5** 就能看。

## 这一关在看什么

俯视 2D 场景(不是横版平台):中间一堵 10 米宽的障碍把『追踪者』和『小玩家』隔开
—— 直线只有 12 米,但**走不通**。追踪者挂着『移动_寻路』:

* 场景设置里勾了『寻路』→ 启动时按**静态碰撞体**烤一块 NavigationPolygon;
* 追踪者每帧查 NavigationServer2D 的绕行路径 → **从障碍两端绕过去**追到玩家
  (直线追只会一头顶在障碍上)。

## 避障(第八十二轮:两对对撞的人)

场地里还有四个人分成**两对**,从 x=±5 对走(终点是对方那头的小绿标记):

| 车道 | 谁 | 勾了『避障』吗 | 现象 |
|---|---|---|---|
| y=+3 | 避障甲 / 避障乙 | **勾了** | 快撞上时各自侧移让开(最小间距 1.2 米 = 2×避障半径),**两个都到达** |
| y=-3 | 对照丙 / 对照丁 | **没勾** | 正对撞上就**顶死在中点**(间距 1.0 = 两个方块贴住),谁也没到 |

> 两对是同一张图、同一个脚本驱动的(『移动_寻路』的『目标』按名字选到谁就动谁);
> 『避障』= NavigationAgent2D 的 RVO —— 勾上后每帧把"期望速度"交给引擎,
> 由它算一个**不会撞上邻居**的安全速度再移动。
> ⚠ 终点标记故意用 **Area2D**:2D 烘焙只认 StaticBody2D,标记要是 StaticBody2D
> 就会被挖成障碍(终点变不可达)。

## 动态障碍(第八十三轮:不重烤导航网格就能绕)

两条车道正中各摆一个**幽灵障碍**(`幽灵甲` / `幽灵乙`):

* 物体是 **Area2D**(没有物理碰撞,谁也撞不到它);
* 在『游戏物理』面板里勾了 **『动态障碍』**(半径 0.8)-> 导出时给它挂一个
  `NavigationObstacle2D` 子节点;
* **勾了『避障』的人会绕开它**(避障对最近只贴到 1.32 米),
  **不勾的直接穿过去**(对照对最近 0.00 米)—— 两个数一比,
  就知道"绕开"是避障干的,而不是被物理挡住的;
* 探针还会**每帧把它沿 x 来回挪 ±1 米**(模拟会动的柱子 / 车):
  导航网格是启动时烤好的,**没有重烤**,避障照样跟得上 ——
  这就是 `NavigationObstacle` 的用处。

> 为什么不用"重烤导航"来躲会动的东西:重烤是**整张网重算**,
> 一根每帧挪一点的柱子扛不住;`NavigationObstacle` 只进**避障**那一层,
> 便宜得多(代价:它不改路径,只改"这一小段怎么走")。

## ⚠ 2D 寻路的唯一注意事项

**2D 里碰撞体 = 障碍物**。所以:

* 给"墙 / 箱子 / 障碍"加碰撞体 ✓
* 给"地面 / 地板"**不要**加(整块地板会被当成一个巨大的障碍挖掉)——
  俯视 2D 游戏本来也不需要给地板加碰撞。

## 自动检查 / 重建

```powershell
python scripts\check_nav2d_demo.py      # 探针(要 Godot):绕障碍追人 + 避障两对对照 + 动态障碍
blender -b --gpu-backend vulkan --python scripts\make_nav2d_demo.py   # 重建 .blend + 工程
```

> 门禁(`scripts\build_and_test.ps1`)里这一层跑的就是上面两条命令,
> 探针标记 `CHECK_NAV2D_DEMO=OK`。
> **镜头不用管**:场景里没有相机时,插件会给 2D 场景自动补一台
> "框住全部物体"的 Camera2D(第四十六轮;不然 Godot 停在原点视图,
> 负坐标区的内容全在屏外 = "运行后一片空")。
> 想自己控镜头:在 Blender 里放一台相机并设为视口当前相机(小键盘 0)。
>
> 3D 寻路的现场在 `examples\demo_physics`(『绕墙追击』『群追避障』『门升起重烤』工位);
> 多层导航 / `NavigationObstacle` / 区域代价还是待办(见 docs\待办清单.md)。
