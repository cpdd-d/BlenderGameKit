# 恐怖示例 —— 熄灯的教学楼(第五十九 / 六十 / 七十 / 一百五十八轮)

阶段④⑤的收尾示例:把恐怖游戏要的那几样一次串起来,并做成一段
**可循环的短篇**。第一百五十八轮按"系统分工"重排了节点图,也补上了
原版会卡死 / 没有失败状态等缺口。

## 六幕

一个 `.blend`、五个 Blender 场景,`asset_export.export_all_scenes()`
一幕导一张 `.tscn`;幕间用『场景_切换关卡』切过去。

| 幕 | 场景 | 内容 |
|---|---|---|
| 0 | **标题** | 标题 + 『开始游戏』(清掉旧档) / 『退出游戏』 |
| 1 | **教室** | 开场俯冲曲线运镜、月光 + 台灯、**3 张纸条(靠近按 E 才拿)**、`[E]` 交互提示、纸条 HUD、**按 J 看笔记日志**、门口门禁(按 E 推门) |
| 2 | **走廊** | **手电 + 电量(HUD 每秒 −1.5)**、雾、**巡逻怪物(会听动静)**、**蹲走不出声 / 跑动脚步声 6 米**、**安全屋存档检查点**、一次性惊吓、**被抓 → 回到安全屋(保留纸条数)**;出口通向 **音乐教室** |
| 3 | **音乐教室** | **录音机顺序谜题**、3 张乐谱、**错顺序触发警报**、**声音诱饵把怪引到舞台**、磁带、本关安全屋;出口通向 **医务室** |
| 4 | **医务室**(第 159 轮新增) | **手电进关只有 60 电量**、两块电池各 +40、**没电就摸黑**、**病床帘躲藏(E 进出)**、3 页病历、本关怪(视线 6 米)、本关安全屋 |
| 5 | **楼梯间**(第 161 轮重做) | **三折楼梯 + 天台**、进门 6 秒**断电**(三盏应急灯灭)、**追兵启动**(6 m/s,走路甩不掉)、三层进度提示、**天台三结局**(真结局要 纸条+病历 ≥ 6)、存档、解冻后回标题 / 退出 |

### 第 3 章 · 音乐教室(2026-10-27)

**一句话**:「把心里的那首曲子按对,才能让怪物替你走开。」

```
进关(安全屋静默存盘) → 找 3 张乐谱(E 读) → 凑出 4 音 → 录音机按 1/2/3/4
        ↑                                        ↓
   被抓回安全屋(乐谱数保留)        对 → 练习曲响起 → 舞台发噪音把怪引走 → 舞台灯灭
                                         ↓
                              上台取『磁带』 → 侧门(去楼梯间)放行
```

| 元素 | 规则 |
|---|---|
| 乐谱 | `乐谱1/2/3` 各给一个音位;集不齐也能试(但只能猜) |
| 录音机 | 靠近 E 打开,按 `1/2/3/4` 输入四音;`录音机错次` 每次 +1 |
| 错一次 | 灯闪 + 警报音 + 字幕「刺耳的警报响了起来」 |
| 错满两次 | **它盯上你**:在你身上发一个响度 40 的噪音 → 怪物转去查看你 |
| 正确 | 放练习曲 → 在 `舞台` 位置发噪音(响度 34)→ 怪物被拉过去(实测近了 4.33 米)+ 舞台灯灭 |
| 磁带 | 只有灯灭了才拿得走;拿到后侧门解锁 |
| 失败 | 被抓 → 冻世界 →『回到安全屋』→ 回本关入口,**乐谱数/磁带保留** |

**这一关的怪**:`音乐教室怪物` + 独立 AI 图 `音乐教室AI`(巡逻 `音乐室巡逻点甲`=舞台前 / `音乐室巡逻点乙`=南门洞外;看见→追击;听见→去查看)。
走廊那只怪不会跟到隔音教室 —— **一层一只怪,是这套示例的约定**。

**本轮抓到的三个真 bug**(都会在别的章节复现,记在这里):

| 现象 | 根因 | 修法 |
|---|---|---|
| 谜题永远判错 | `逻辑_比较` 的 B 是**文本框**时,`"3142"` 被生成成 `== 3142`(字符串比 int,永远不等) | 比较前先统一类型,或用字符串比较节点 |
| 走廊出口走不过去 | `write_physics` 的 triggers 里还是旧名字,漏改那一处 ⇒ 出口板被导成 **StaticBody3D**(一块挡路实体) | 改名时把 triggers 一起改;判据是 tscn 里它是 `Area3D` 不是 `StaticBody3D` |
| 进关头 0.8 秒挂着「安全屋:进度已保存」 | **不是跨关残留**(UI 每关自己的 CanvasLayer),是出生点就在安全屋区域里,首帧就触发存盘提示 | 首次进安全屋**静默存盘**,第二次起才提示 |

### 第 4 章 · 医务室(2026-10-28)

**一句话**:「灯只剩一点电,而它就在帘子外面走。」这一章是**潜行 + 资源课**:手电电量第一次真的会见底,躲藏点第一次成为解法。

```
进关(电量 60) → 摸黑找 3 页病历 + 2 块电池(各 +40)
      ↑                        ↓
 被抓回安全屋(病历/电池/电量都保留)   电量告急 → 躲进病床帘避开巡逻 → 侧门(去楼梯间)
```

| 元素 | 规则 |
|---|---|
| 手电 | 进关 **60**(不是 100);`电池1/2` 各 **+40**;耗电 1.5/秒;**归零灯灭**,画面压到只剩窗光 |
| 躲藏 | `躲藏1/2`(病床帘)按 **E** 进 → 相机切 `医务室躲藏机位`、玩家隐藏、身体移出视距;再按 E 出来 |
| 病历 | `病历1/2/3`,E 读;集齐 3 页侧门才放行 |
| 怪 | `医务室怪物`,视线 **6 米**(走廊 9 / 音乐教室 8),听见→去查看 |
| 安全屋 | `医务室安全屋区域`;**物体名全局唯一**,所以走廊/音乐教室的安全屋各叫 `走廊安全屋区域` / `安全屋区域` |
| 失败 | 被抓 → 回本关安全屋,**病历数 / 电池数 / 手电电量全保留** |

**这一轮修掉的一个隐蔽洞**:手电链的两处『界面_设定』**只接了『文字』没接『执行』** —— 节点根本没生成执行入口,`手电电量` HUD 从头到尾停在初值(走廊那关同病)。

**技术债(已记 `docs/待办清单.md`)**:

| 债 | 为什么现在是这样 | 该怎么还 |
|---|---|---|
| 手电链是两关各一份**内联复制** | 没有共享工厂 | 抽 `_torch_chain(logic, ...)`,否则第 5 章再复制一份,同一个洞第三次出现 |
| 「躲藏」用**传送出视距**实现 | 现有卡片里 `变量_设置` 写不到角色脚本的 `move_speed`,`移动_设置速度` 每帧被角色图覆盖 | 插件补一张『输入_启用/禁用』(待办 P1);观感没问题(躲藏机位是独立相机,画面不跟人跑) |
| 怪的视线是**纯距离判定**,没有遮挡射线 | AI 的 `看得见` 只有距离+视野角 | 真做掩体要插件支持"视线遮挡",当前"躲在桌后"只是视觉掩体 |

### 第 5 章 · 楼梯间(2026-10-28)

**一句话**:「灯灭的那一刻它开始上楼,而你要在天台门之前跑到顶。」

以前这一"章"只有一块 5×5 判定板:从医务室推门进来走 8 米,按 1 或 2 选结局。
现在它是一段**真的爬楼**。

```
进关(门厅) → 6 秒后断电(三盏应急灯灭 + 警报 + 字幕) → 追兵启动
      ↑                                    ↓
   天台门(在三楼尽头) ← 二层 / 三层各改一次目标 ← 一路往上跑
      ↓
   天台:三选项 → 结局 1 / 2 / 3(真结局)
```

| 元素 | 规则 |
|---|---|
| 场地 | 门厅 + **3 段坡道**(每段 6m 水平 / 升 2.8m)+ 3 个平台 + 顶层 + **露天天台**(y 28..38) |
| 楼梯 | 走的是**斜坡**(25°),踏面是贴在坡上的装饰薄板 —— `CharacterBody3D` 没有自动上台阶,真做 0.6m 一级就得**跳**着爬(旧版就是这样) |
| 断电 | 进门 **6 秒**:三盏应急灯一起关(0.35s 渐变)→ 警报(降调)→ 字幕"灯全灭了" → 目标改"往上跑" |
| 追兵 | 新 AI 图『楼梯间AI』,**起始状态就是追击**,所以在**断电那一刻**才 `AI_启用`;丢失 16 米后退回巡逻 |
| 速度 | **6.0 m/s**(= 玩家走路速度;前几章都是 4.08)—— 走路甩不掉,必须跑 |
| 楼层 | `楼梯间一层/二层/三层` 三个区域:进二层 / 三层各改一次目标("还有 2 层 / 1 层") |
| 结局 | 进 `楼梯间天台` → 冻世界 → **三个选项** |
| 真结局 | 选项 3 先判档案:`纸条数 + 病历数 >= 6` → 结局 3;不齐 → 字幕"你想不起来她是谁",落到结局 2(**不是死局**) |
| 灯 | 3 盏应急灯(900/1400/1400W)、门口**门楣自发光 + 60W 小红灯**(只给一个红点,不照亮天台)、天台**月光 SUN** |

**这一轮学到的两条**:

1. **"面板上看得见"≠"连着"**:`选项3 -> 档案判断` 那条线漏了,选择框上
   第三个选项明明在,按下去什么都不会发生 —— 连生成的 `match` 里都没有第 3 个
   `case`。`check_horror_demo.py` 现在会断 `options=3` **和** `ended=3.0` 两侧。
2. **红灯不要用大功率去"照亮"**:520W / 射程 9 米时,站在门口那几米内它把
   整片天台和雾照成洋红(实机截图整屏粉)。改成门楣自发光 + 60W / 射程 4 米。

## 美术:零件拼出来的人形(第 162 轮,M3 第一刀)

以前玩家和怪物都是**一个方块** —— 用户在好几轮里都提到"这是现在最不像二次元的地方"。
这一轮先用**零件**拼出能读的剪影(没有外部美术资产,也不用手工建模):

| 角色 | 零件 |
|---|---|
| 玩家(五关各一份) | 深蓝制服躯干 + 白衬领 + 头 + 黑发 + 刘海 + 双臂 + 双手 + 裙子 + 两只鞋 |
| 怪物(四关各一份) | 暗红长袍 + 惨白的脸 + 黑长发 + 刘海 + 垂到膝的长手 |

三条实现约束:

1. **零件是角色物体的子级** —— 导出侧把"根 + 全部子级"导成角色自己的 glb,
   世界 glb 会把整棵子树排除;挂别处会在出生点留一份静止的复制品;
2. **零件一律 `decor()`(无碰撞)** —— 碰撞体仍然只有那一个胶囊
   (给零件加碰撞 = 一堆小盒子堵路 + 挡相机);
3. **改尺寸改网格顶点,不动 `obj.scale`** —— scale 会跟着进 glb 节点,
   到 Godot 里就是"角色被压扁"。

三个"看起来像 bug"的坑(都写在 `make_horror_demo.py` 的注释里):

- 侧面像**灯柱** → 结构要**分段**(腿/袜 → 裙 → 上衣 → 领 → 头 → 发),不是"柱子 + 帽子";
- 怪物前面挡着**灰板** → 上衣必须比核心盒子**宽一圈**,否则核心从衣服里穿出来;
- 灯下像**浅灰**而不是深蓝 → 导出侧会把显示色解码成线性(`0.16 → 0.44`),
  想要深色就往下压到 0.04~0.09。

**还没做的**:没有骨骼动画(走路是整体平移)、没有贴图和表情。

## 角色动起来了:『角色_走路摆动』(第 163 轮)

零件拼的人形解决了"像一坨方块",但走起来还是**整体平移**。这一轮加了插件节点
**『角色_走路摆动』**,零资产、零骨骼:

| 它做什么 | 怎么做的 |
|---|---|
| 认零件 | 按名字里包含的字(`臂`)在角色子树里找 Node3D |
| 摆手臂 | 每物理帧 `rotation.x = base + sin(相位) × 摆幅 × 速度比`,左右**反相** |
| 步频 | 相位按**走过的距离**推进 —— 站着不动就停,走得快就摆得快 |
| 浮沉 | `Model.position.y += abs(sin) × 浮沉 × 速度比`(3 厘米,不蹦) |
| 腾空 | `is_on_floor()` 为假时摆幅压到三成(跳跃中手臂不抽风) |

预设 `create_character_preset` 已经默认连上它(参考速度 = 走路速度),
所以**新建的角色一键就有**;老 .blend 里的图不受影响。

⚠ 两个必须知道的点:

1. 改插件代码后**先跑 `scripts\install.ps1`** 再重建示例 —— Blender 里装的是
   副本,不重装的话新节点类根本不存在(`尚未定义节点类型 …`)。
2. 门禁断的是**运行时登记表**(`HORROR_WALK entries=1 arms=2`),不是 grep 生成
   代码:关键字被多引一层时,代码照样生成、照样编译,却一个零件都认不到。

## 节点图怎么分工

这是本轮改动最值得看的部分。**不要**再把 HUD / 存档 / 触发区塞进角色图:

| 图 | 挂在哪 | 只放什么 |
|---|---|---|
| **玩家逻辑(公共)** | 三关的角色物体 | 输入 / 移动 / 跳跃 / 鼠标视角 / 弹簧臂 / C·V 切机位 |
| **教室关卡 / 走廊关卡 / 楼梯间关卡 / 标题关卡** | 各自场景根(Node3D) | HUD / BGM / 暗角 / 运镜 / 触发区 / 存档 / 切关 / AI 启动 / 失败处理 |
| **怪物AI** | 由关卡图的『AI_启用』启动 | 巡逻 / 追击 / 去查看;对外输出 `is_chasing` / `is_investigating` |

三关的相机统一叫『侧视机位』『俯瞰机位』,而且是**同一个相机物体**
链接进三关 —— Blender 物体名全局唯一,各建一个会变成 `.001/.002`,
共用的角色图就找不到相机。

每张关卡图里用 Blender 原生 **分组框(NodeFrame)** 分成
「① 开场 / 氛围」「② 交互 / HUD」「③ 门口」「④ 失败 / 结局」等区块,
可以整块折叠(右键节点工具或侧栏『分组框』),不影响导出。

## 玩法闭环

1. **标题**:点『开始游戏』先删掉 `save1`,保证新开一局;
   也可以直接『退出游戏』。
2. **教室**:找 3 张纸条。**靠近纸条会出 `[E]` 提示,按 E 才拿走**
   (踩进去不再自动拾取);拿走时**纸条连同网格一起销毁**。
   HUD 实时显示 `纸条 N/3`;**按 J 打开笔记日志**看已读正文(Esc / J 关)。
   门口会检查 `纸条数 >= 3`:不够只显示"还差 N 张",**不会**把你放进
   走廊;够了按 E 推门才存档并切场景。
3. **走廊**:**手电按 F 开关,电量每秒 -1.5,耗尽自动灭**(HUD 显示电量)。
   怪物会巡逻、看见你追击、听见 K 键动静过来查看。
   **按住 LeftCtrl 蹲走**(3.0 m/s,不发出声音);**按住 LeftShift 跑**
   (10.8 m/s,**发出半径 6 米的脚步声**,怪物听得见)。
   离得越近心跳越快,被追击时还会额外抬紧张度。
   走过惊吓区会触发一次"镜头震 + 闪红 + 音效",并把 Master 压低;
   **2.5 秒后自动恢复总线音量**。
   **安全屋**:走进 `安全屋区域` 即存盘、写检查点。
   被怪物抓到(距离 < 1.9 米)会镜头倒地 → 冻住世界 → 给出
   **『回到安全屋』**/『回到标题』两个按钮;回安全屋时**纸条数保留、场景不重载**。
4. **楼梯间**:开局载入存档读回纸条数。门口 >= 3 才弹结局选择;
   选完写结局并落盘,然后**先解冻世界**再回标题 / 退出
   (`SceneTree.paused` 不会跨场景自动清零,不解冻会把标题页也冻住)。
   如果存档被改坏(纸条不足),会显示"还差 N 张"并给『回到标题』出口,
   不再是无路可走的死局。

## 实机游玩记录(2026-10-25)

完整跑了一遍 **标题 → 教室(拿 2 张被门禁挡住 / 拿满 3 张) → 走廊
(按 K 引怪 / 惊吓区 / 被抓 / 重试) → 楼梯间(结局选择) → 回标题 →
二周目**,并逐张截图检查。只有真正玩起来才暴露、已经修掉的问题:

| 实机现象 | 根因 | 修法 |
|---|---|---|
| 第三人称角色怼满屏幕、走廊像在贴脸看 | Blender 相机 50mm 被环境脚本写成 Godot `fov=22.9°`(长焦),覆盖了角色图的 60° | 相机改 21mm(侧视)/18mm(俯瞰);`reuse_camera` 同步焦距 |
| 教室/走廊/楼梯间整片灰白,雾像牛奶 | 环境颜色按"显示值"写进线性属性,导出又转一次 sRGB,雾色变成 0.51 中灰 | 新增 `_display_color()`:作者写显示值 → 存线性 → 导出还原;同时降雾密度、降月光 |
| 开场运镜 1–3 秒全是空背景 | ①从标题相机/未就位的侧视机位起飞 ②特写机位 74° 在 Blender 里是平视 | 先等弹簧臂 0.12s → 显式回侧视 → 再运镜;特写改 33° 低头看门口、28mm |
| 回标题后画面还停在上一关/上帝机 | 环境脚本"有相机在用就不抢",上一关相机残留 | 标题关卡图显式 `相机_切换` 到『标题机位』 |

## 写自动化探针踩过的坑(2026-10-28 · M1b)

这一轮排查「第 4 章侧门在自动试玩里打不开」,最后证明**门没坏**,是探针
自己的三个坑。记在这里 —— 它们是"用 DSH + 这套插件写试玩自动化"的通用坑,
不是恐怖示例特有。

### 1. 暂停之后 `await get_tree().physics_frame` **不返回**

游戏里『被抓 → 冻世界』走的是 `get_tree().paused = true`。这一刻起:

* **物理服务器不推进** —— `Area3D.get_overlapping_bodies()` 的集合和
  `body_entered` / `body_exited` 信号**一起冻住**。把玩家传送到门口也没用,
  集合里永远只有之前那些 body。
* 在协程里 `await get_tree().physics_frame` 这一句**永远等不到下一帧**,
  探针看起来像"卡死"(实测:整趟只跑到暂停前那一行,之后一个 print 都没有)。

要用 `await get_tree().create_timer(秒, true, false, true).timeout`
(第 2 个参数 `process_always = true`)才能在暂停下继续走。

**所以自动化里读门 / 触发区之前,先断言 `get_tree().paused == false`。**
如果当前真的被抓住了,先点『回到安全屋』(那条链会解冻),再继续下一步。

### 2. `--quit-after N` 是**帧数**,`create_timer` 是**墙钟**

headless 的帧率远高于实时(实测 400 帧的墙钟不到 2 秒)。
给它 400 帧的预算、里面又 `create_timer` 等 2 秒,进程会在 timer 到点之前
就被杀掉 —— 表现是"探针跑到一半没有任何输出"。
**等墙钟的探针把 `--quit-after` 放到几千帧。**

### 3. 传送之后要**等 ≥2 个物理帧**再读 overlaps / 按 E

`body` 的变换和 `Area3D` 的 overlap 集合是按物理步边界刷新的。实测
(把 `医务室玩家` 传到门口那块判定板上):

| 帧 | `get_overlapping_bodies()` | `交互目标` |
|---|---|---|
| 传送那一帧 | 0(连地面都还没进) | 空 |
| +1 帧 | 1(只有地面) | 空 |
| +2 帧 | 2(地面 + 玩家) | `去楼梯间` |

「传送 + 同一帧按 E」会被**静默吃掉**(目标还是空,门什么反应都没有);
同一个 E 晚两帧再按就正常。写探针时:传送 → 等 2 帧 →(可选)断言目标已
变成预期值 → 再按 E。
