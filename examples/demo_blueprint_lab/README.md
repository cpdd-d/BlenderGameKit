# 能源门 · 蓝图集成实验室

从 `demo_game` 的动画反馈、`demo_horror` 的门禁和 `demo_assets` 的资产复用提炼的独立小关卡。现有大示例继续保留；这里用最少职责图展示 Blender 创作、Godot 运行的完整链路。

打开 `BlueprintLab.blend`，在游戏逻辑编辑器选择下面的图；用 Godot 打开 `BlueprintLab_godot/project.godot`，按 **F5** 游玩。

| 图 | 职责 |
|---|---|
| 角色·只负责移动 | WASD、重力、相机朝向移动；绑定 Player |
| 组件·可复用能源门 | **同一张 ROLE 图绑定两扇门**，实例自己维护距离验证、激活状态、声音和动画完成信号 |
| 关卡·双门协作与通关 | 订阅两门 `opened` 信号，汇总进度、更新 HUD、验证终点，创建暂停菜单；挂关卡根 |
| 界面·实验室HUD | 顶部居中的标题、状态和操作提示；初始化只创建一次 |
| 游戏资产 | 同一信标模型三次复用，程序生成确认音 |

WASD 分别靠近青色、金色控制台，按 **E** 或点击对应按钮。键盘交互半径为 2.2 米；两个按钮分别标明 1.4 米、2.2 米的操作半径。两扇门都升起后穿过门，走到末端中央信标完成实验；只打开一扇不能通关；**R** 重开。键盘和界面调用同一个 `try_activate(radius: float) -> bool` 函数，距离与防重复规则只维护一份，调用方传入玩法参数。

**Esc** 或顶部“暂停”按钮打开菜单。暂停时角色、门的原生动画及碰撞位置停止，底层控制台按钮不能操作。默认焦点在“继续游戏”，**Enter** 恢复；**Tab** 或方向键在菜单按钮间循环，也可以点“重新开始”。恢复后动画接着播放，只有自然播完才向关卡发送完成信号；中途重开会清空旧进度。

## 同一蓝图，两个实例

选中 `EnergyGateA` 或 `EnergyGateB`，打开物体的游戏物理面板，两者的角色逻辑图都指向 `组件·可复用能源门`。在“角色引用”里分别绑定：

| 实例 | `@玩家` | `@控制台` | 自身状态 |
|---|---|---|---|
| EnergyGateA | Player | TerminalA | activation_count / completed |
| EnergyGateB | Player | TerminalB | activation_count / completed |

修改共享图的交互规则或流程，两扇门都会采用新规则；修改某门的引用，只改变这个实例。源文件只有一份行为图，导出器根据每个实例的引用生成对应脚本和模型。两门各有独立 AnimationPlayer，同一个 Blender Action 也能分别播放。关卡通过信号监听完成事件，不读取门内部的防重复变量，也不复制每门的交互流程。

关卡中的两个“带参调用门实例”节点使用同一接口图，目标分别指向 A、B 门，`radius` 接不同常量。函数返回 `true` 表示**本次请求接受**，UI 据此显示短暂反馈；距离不够或已经激活则返回 `false`。节点的“成功”只表示找到了目标方法并完成调用，与门是否接受请求分开。完成进度仍等待原生动画结束后的 `opened` 信号，接受请求不等于门已打开。修改调用方半径只改变该操作入口，不必复制门的行为图。

门动作是 Blender 原生 `GateOpen` Action，经 glTF 导出为 Godot AnimationPlayer。确认音由生成器合成，无联网或外部素材依赖。源文件使用 `//activation.wav` 相对音频路径；项目位置留空，按 `.blend` 文件名自动推导 `BlueprintLab_godot`，移动示例时整个目录一起复制。

## 重新生成和验证

```powershell
python scripts/check_blueprint_lab.py --blender "D:\blender-4.5.5-windows-x64\blender.exe" --godot "D:\godot\Godot_v4.7.2-stable_win64_console.exe"
```

检查器先生成源工程，在真实 Blender 中验证图诊断、共享图、独立引用、带参调用接口和暂停节点保存，然后复制导出物到 `_dist/blueprint_lab_probe/project`。真实 Godot 检查角色移动、远距拒绝、同样 1.7 米距离下不同半径实参的拒绝/接受、布尔返回值与 UI 反馈、重复调用返回拒绝、A 门开启时 B 门动画/声音/状态/碰撞不变、UI 与按键幂等、原生动画与碰撞放行、两门独立穿越、单门不能通关、双门任务汇总、HUD 和 R 重载归零，并验证动画中途暂停/恢复和重开不会派发旧完成事件。任何 `ERROR:` / `SCRIPT ERROR:` 或非零退出码都会判失败。通过时打印 `BLUEPRINT_LAB=OK`；日志和逐项结果位于 `_dist/blueprint_lab_probe`。

2026-11-16 的 Godot 实机基线：**GPU 与 headless 均 97/97 项通过**，包括 46 项关卡行为和三种分辨率各 17 项 UI 检查。保留此前 89 项，新增 8 项带参调用、返回值及实例隔离验收。GPU 模式的窗口与视口实测尺寸均匹配请求值；已审阅 960×540 的按钮半径标签、HUD 和交互反馈截图。逐项结果在 `result.json`；重新运行会先标记 `RUNNING`，失败写为 `FAILED`，不会沿用旧的成功记录。每次验证都会重建专用探针副本，避免旧脚本或导入缓存掩盖错误。

已有产物可加 `--skip-build`；有桌面 GPU 时加 `--render` 输出开场、只开一门和通关截图。加 `--ui-matrix` 另跑 960×540、1280×800、1920×800 三种尺寸的短 UI 流程：实际视口/窗口尺寸、控件边界、键盘焦点、暂停期间输入隔离、恢复和菜单重开。`--ui-only` 只跑此矩阵，避免重复跑完整关卡。矩阵使用真实键鼠事件，不直接调用按钮回调。`result.json` 的 `ui_sizes` 保存实测尺寸；与 `--render` 同用还会按尺寸输出 HUD 和暂停截图。普通验证使用 headless，不依赖屏幕截图判定行为。

Godot 的 headless 虚拟窗口固定为 64×64，检查器会明确设置待测逻辑视口并断言其实际尺寸，鼠标事件按逻辑视口坐标派发。结果同时记录实际视口、虚拟窗口和 `window_kind: dummy`，不把虚拟窗口当作目标分辨率。GPU 模式仍要求原生窗口与视口同时匹配请求尺寸。

```powershell
python scripts/check_blueprint_lab.py --skip-build --render --ui-matrix
```

这是同关多实例行为复用的架构验收示例。它没有引入自定义脚本承载游戏规则；后续可沿同一图、实例引用和信号接口扩展按钮、宝箱、机关等交互类型。
